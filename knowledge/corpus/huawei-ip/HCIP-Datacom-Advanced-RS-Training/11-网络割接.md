# 网络割接

## 学习目标

学完本课程后，您将能够：

- 描述割接基本概念与风险
- 按规范完成割接准备、实施与收尾流程
- 结合分支网络改造案例输出割接方案文档

## 1. 割接基本概念

随着企业业务发展，网络需不断改造与优化（如 IPv4 升级 IPv6、IS-IS Level 调整、VPN 架构整改）。凡影响现网业务运行的操作（如造成业务中断），企业都会按业务安全等级制定严格操作流程与风险规避措施，并将其定义为**割接项目**。

割接流程通常分为：

1. 准备阶段
2. 实施阶段
3. 收尾阶段

### 1.1 输出割接方案

根据调研结果、项目分析与技术人员风险评估编写割接方案。方案需明确准备、实施、收尾各阶段的详细步骤。

| 阶段 | 主要内容 |
| --- | --- |
| 前期准备 | 项目背景、现网概述、割接目标、风险评估 |
| 实施 | 割接准备、割接实施、业务测试、回退方案、应急预案 |
| 割接收尾 | 现场守局、资料移交、项目验收 |

### 1.2 实施方案

为高效、规范割接，每个实施步骤需提前规划，细化到具体命令行及所需时间。方案中应制定割接操作确认记录表，记录时间点、结果确认与异常信息。

示例割接执行步骤：

| 步骤 | 操作 | 操作时间 |
| --- | --- | --- |
| 旧设备下线 | 旧设备下电、线缆拆除 | 0:00–0:30 |
| 新设备上架 | 新设备上电、线缆连接 | 0:30–1:00 |
| 新设备配置 | 刷入提前配置好的脚本 | 1:00–1:20 |
| 网络状态检查 | 检查网络各项表项 | 1:20–2:00 |
| 业务测试 | 协调甲方人员测试业务、应用 | 2:00–2:30 |

### 1.3 回退方案

当割接失败（业务测试失败，或割接时间结束仍未完成）时，需按回退方案将网络恢复到割接前初始状态。回退步骤同样需精确到每一步操作。

示例回退步骤：

| 步骤 | 操作 | 操作时间 |
| --- | --- | --- |
| 新设备下架 | 新设备下电、线缆拆除 | 3:00–3:20 |
| 重上架旧设备 | 旧设备上电、线缆连接 | 3:20–3:40 |
| 业务测试 | 协调甲方人员测试业务、应用 | 3:50–4:00 |

### 1.4 方案验证和审定

大型、重要割接项目一般要求在实验室搭建环境提前验证（实验局测试），确认风险点与方案可行性。此外需与客户、实施方召开技术评审会，论证技术方案并当面解决问题。

### 1.5 割接准备

割接准备是顺利完成割接的基础，分为环境准备、人员准备与流程准备。

**软、硬件准备：**

| 类别 | 检查项 |
| --- | --- |
| 硬件 | 设备上电测试；单板运行观察；线缆连通性测试 |
| 软件 | 设备/对接版本配套检查；License 是否到位；整体/分段/回退脚本 |

**工具、备件准备：**

| 类别 | 内容 |
| --- | --- |
| 搬运工具 | 车辆、起降工具、上架工具 |
| 测试工具 | 网线测试仪、网络测试仪、光功率计 |
| 调试工具 | PC 终端、调测线缆、调试软件等 |
| 监控工具 | 业务监控、流量监控、网络分析工具 |
| 备件 | 重要单板甚至整机；新旧软件版本与脚本备份 |

**时间安排注意：**

- 必须与客户沟通并获得同意
- 制定总时间表，规定各时间段动作
- 执行阶段精细到分钟；重大操作预留缓冲
- 尽量避开业务高峰期（节假日、非正常上班时间等）

### 1.6 割接前快照

正式割接前对现网配置与动态数据再做一次快照，便于回退与割接后对比：

- 现网配置备份
- 现网动态数据采集（端口状态、流量、路由协议状态、路由数量、STP 状态、各端口 ARP/MAC 表项）
- 割接前业务测试，确认相关业务处于正常状态

### 1.7 割接执行与回退

- 现场人员按准备好的步骤严格执行，无特殊原因不临时更改
- 每一步记录实际时间点、动作与结果
- 若指定时间前未完成，按回退方案回退；回退范围可与客户协商部分或全部回退

### 1.8 割接测试、守局与验收

割接后测试维度：

- **网络运行状态**：再次采集动态数据并与割接前对比
- **业务测试**：ping、tracert 或第三方软件测连通性、延迟、抖动
- **客户应用测试**：检查网络承载的应用是否正常

守局：通过业务测试后进入观察期，工程师驻守局点观察运行状态。守局时长（如 24 小时、1 周、1 月）需与客户协商。

验收：守局无异常后进行转维护培训与资料移交。

## 2. 割接案例实践

### 2.1 课堂要求

重点通过实践掌握割接流程与方法，不仅完成设备配置。对给定场景需按流程讨论，并按《项目割接方案模板》输出文档，包含：

- 项目调研、分析：现网拓扑、业务分析，应采集哪些动静信息
- 风险评估：可能风险及规避措施
- 割接方案：细化到命令与时间节点
- 测试、检查项：割接后应检查与测试的内容

课堂环节示例：背景介绍 15min → 分组 5min → 讨论 30min → 总结汇报 20min。

### 2.2 项目改造背景

某公司多分支通过专线连总部，存在问题：

- 专线速率低，无法满足新业务带宽
- 分支出口单设备、单上行，存在单点故障
- 专线提速费用高
- 核心交换机单机部署，存在单点故障
- 终端增多，核心与出口性能不足

目标：改造分支网络，提升可靠性与到总部带宽。

### 2.3 原拓扑与目标拓扑

原拓扑问题：专线约 4Mbps；出口/核心单设备单上行；汇聚单上行。

目标拓扑要点：

- 设备冗余、链路冗余；出口增加 Internet，与总部建 IPsec VPN，承载延迟要求较低、带宽要求较高的业务
- 核心双机集群，与上下行跨框链路聚合
- 汇聚双上行与集群核心建链路聚合
- 网关放在核心 VLANIF，依赖集群与链路聚合，无需 VRRP
- 核心配静态路由将不同业务指向专线/IPsec 出口，并用浮动路由备份
- 配置 NQA 检测专线与 IPsec 可用性，静态路由 Track NQA 实现故障切换

业务分类：

- **A 类业务**：延迟要求高、带宽要求低 → 专线承载
- **B 类业务**：延迟要求低、带宽占用多 → IPsec VPN 承载

总部回向路由同样用静态 + NQA；本案例重点关注分支侧。

### 2.4 路由备份设计

核心上将 A/B 类业务路由分别指向不同出口，浮动路由互为备份。配置模板示例：

```cli
ip route-static A类型业务地址 mask A track nqa service_a icmp
ip route-static A类型业务地址 mask B preference 70
ip route-static B类型业务地址 mask B track nqa service_b icmp
ip route-static B类型业务地址 mask A preference 70
```

### 2.5 割接方案概览

1. 部署新出口路由器，接入 Internet，完成 IPsec VPN 与路由配置（含回程）
2. 部署两台新核心，完成集群、路由、NQA，与出口完成跨框聚合；暂不连汇聚
3. 断开原核心与上下行连接，将汇聚接到新集群核心
4. 修改原出口路由器指向内网的回程下一跳为新集群互联地址

请根据上述信息按模板输出《项目割接方案模板》。

### 2.6 关键检查点

1. 可在本地搭建实验局模拟客户网络，验证方案可行性
2. 需备份现网配置，并采集现网动态数据（端口状态、流量、路由协议状态、路由数量、STP、ARP/MAC 等）以便割接前后对比

## 本章总结

- 割接会变更网络并可能影响业务，需以客户需求为中心，实时把控风险
- 割接前认真调研与验证，步骤提前准备；割接后验证业务；严格按规范流程才能成功、高效完成割接
