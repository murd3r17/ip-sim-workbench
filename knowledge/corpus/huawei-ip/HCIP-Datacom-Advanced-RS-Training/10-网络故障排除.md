# 网络故障排除

## 1. 故障排除流程（续）

结构化流程：报告故障 → 确认故障 → 收集信息 → 判断分析 → **原因列表** → 故障评估 → 逐一排查 → 解决故障 → 收尾工作。

### 原因列表

列出所有可能原因，经信息过滤保留最可能项，排除当前最不可能项，缩小范围。

### 故障评估

复杂故障若短期难排除而业务急需恢复，可搭建临时替代环境；须评估安全风险，与用户充分沟通并获许可。

### 逐一排查

平衡解决问题迫切性与引入新故障风险；告知用户并获许可。涉及变更须有应急预案与回退准备。

### 解决故障与收尾

现象消失后持续观察，确认未引入新故障。收尾：变更备份、故障文档与总结报告、资料移交、向用户提改进建议，并通告受影响方、授权方及厂家/服务商等。

## 2. 核心思想与方法

### 以业务流量路径为核心

掌握受影响业务的往返路径，沿线逐步排查。需确认网络层路径与数据链路层转发路径。

### 分层故障处理法

自底向上：物理层 → 数据链路层 → 网络层 → 传输层 → …（低层正常高层才可能正常）。

### 对比配置法

对比正常与故障状态下的配置、版本、硬件差异（如 Hello 定时器不同）。

### 分块故障处理法

按配置结构归类缩小范围：管理、端口、路由协议、策略、接入、其他应用。例如路由表仅直连，可能出自协议/策略/端口三块。

### 分段故障处理法

按物理/逻辑分段（接入–汇聚–核心–出口）逐段排查。

### 替换法

怀疑线缆、模块、设备时用确认良好的备件替换验证。

对人员要求：精深协议理解、引导客户描述现象、熟悉所管网络、文档与经验总结、多种方法结合。

## 3. 常见网络故障排除

示例拓扑：R1–R2 OSPF，R2–R3 IS-IS，R1/R3 与 R2 IBGP（R2 为 RR）；接入交换机静态对接；MSTP 多实例；VRRP 网关等。

### LAN 故障

链路/设备故障常换硬件；环路用 STP/MSTP 处理；检查端口 Up、封装、错误计数、生成树角色与阻塞口。

### 路由故障

表现为路由不可达。排查 OSPF/IS-IS/BGP 邻居无法建立的常见原因：

- 接口/区域/网络类型/认证/Router-ID 冲突
- IS-IS Level、网络实体、电路类型
- BGP 对等体地址、AS 号、Update-source、IGP 可达、认证/GTSM

结合 `display ospf peer`、`display isis peer`、`display bgp peer`、路由表与策略过滤逐步定位。

### 业务故障

在连通性恢复后检查 ACL、NAT、QoS、DHCP、应用端口等。

## 4. 思考题与总结

1.（多选）收尾通告对象：受影响方、授权方、厂家/服务商等（非无关人员）  
2.（判断）大规模网络中对比法最有效？→ 通常并非最有效  

**总结：**

- 流程化九步；目的是恢复业务，故需掌握流量路径
- 方法：分层、对比、分块、分段、替换
- LAN 侧重硬件与 STP；网络层侧重路由邻居与通告
- 知识、方法与经验总结同样重要
