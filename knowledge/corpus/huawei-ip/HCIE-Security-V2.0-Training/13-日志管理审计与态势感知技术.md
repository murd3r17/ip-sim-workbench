# 日志管理审计与态势感知技术

## 日志的表现形式

- 日志收集需要通过多种方式全面收集网络中的各种设备、应用和操作系统的日志信息，确保用户能够收集并审计所有必须的日志信息。
- 操作系统日志不同于其他日志，无法通过网络协议发送给日志收集设备，这时候可以为用户提供一个通用日志收集器（Sensor）对用户日志进行收集。
- 常见的网络设备消息主要包括登录和注销、建立服务连接、配置更改、检测到攻击、检测到的侦查或探查行为等。
- 应用系统的日志主要包括权限管理日志、账户管理日志、登录认证管理日志、业务访问日志等。
- 数据库主要是事务日志，用于记录所有事务以及每个事务对数据库所做的修改。

### 日志收集的方式

| 方式 | 说明 |
|------|------|
| Syslog | 常被称为系统日志或系统记录，是一种用来在互联网络协议的网络中传递记录信息的标准。 |
| SNMP Trap | 被管理设备主动发送消息给 NMS 的一种机制。 |
| JDBC/ODBC | JDBC 是实现 Java 应用程序与各种不同数据库对话的一种机制。ODBC 与 JDBC 一样，也是一种重要的数据库访问技术。 |
| 文本 | 由于生成文本系统的成本较低，现有的许多计算机语言都包含了可以生成文本日志的框架。 |

### 日志分析要点

- Who：是用户还是访客。
- When：什么时间。
- Where：在什么地点，如位置信息，登录的设备信息，接入的接口信息，访问的服务等。
- How：通过什么方式，如通过有线接入，无线接入或者 VPN 接入。
- What：做了什么，如进行的操作行为，使用接入设备，访问的资源服务等。

- 很多网络设备都支持 Syslog，其中包括路由器、交换机、防火墙和其他网络设备。
- Syslog 常被用来作为日志等数据的传输协议，数据格式遵循规范主要有 RFC3164、RFC5424。

## 利用日志进行攻击溯源

### 事件

- 事件过程：某厂商日志分析发现 APT 攻击，但是日志记录的行为直接登陆内网，并无攻击过程，以及攻击手法，导致内网安全加固不知从何下手，并且不知道有什么后门需要清除，而且日志里攻击者 IP 为外国 IP，不确定真实 IP，还是代理 IP。无法定位真正攻击者的地理位置。
- 思路：反入侵得到攻击者机器权限，入侵现场还原，摸清入侵思路。并且须知入侵者的相关后门遗留，以便处理后门。抓取入侵者的真实 IP 获得地理位置。并按照攻击者的攻击路线加固相关漏洞安全。

### 日志分析（1）

某厂商日志：该 IP 属于 x 国，login 状态全部为 success。

> （原图：日志记录，dts 时间戳 2017-01-17T19:02:00，IP 为 221.150.x.x）

### 日志分析（2）

只能看到攻击者进入内网多个 IP。但无其他记录，如过程、手法。无法安全加固客户内网。无法分析出哪里出现问题，只能找出起始被入侵成功的 IP，需要得到攻击者的电脑权限，还原攻击过程，才可得知被攻击者的弱点并加固。

> （原图：多条日志记录，时间戳 2017-01-17 17:38-17:42，涉及 IP 10.1.32.46、10.1.32.74、216.36.23.36 等）

### 日志分析（3）

在 tns 日志中，oracle 相关存储得到入侵者相关的存储利用。如 downfile-smss.exe，地址为 115.231.60.76。此时，我们得到 2 个攻击者 IP，1 个样本。

> （原图：Oracle TNS 日志，包含时间戳、serial#、ipv6、gadip、login 状态（failed/success）、SYS 用户、tns 服务名等字段，以及 2017-01-12T02:58:08 的 BEGIN DBMS_OUTPUT.GET_LINES 调用记录，包含 "run_cmd /c echo Post.Open GET http://115.231.60.76" 等命令）

起初连接到入侵者 IP 的服务器，IP 归属地为韩国，并且服务器也为韩文，非中国渠道购买，起初以为攻击者为国外人员。

> （原图：服务器登录界面，IP 为 221.150.x.x）

- 整体思路临时改为：需要得到该服务器的权限，查看所有登陆成功日志，找出 IP 以及对应时间。
- 通过本地样本分析获取入侵者服务器密码。

### 加固

- 在该服务器上留有大量以地名命名的 txt 文本（如 beijing.txt）。文本内容为 IP，部分内容为账号、密码、IP。
- 至此通过该服务器的桌面相关软件以及相关攻击者文本记录，得知攻击者的入侵思路，以及部分后门留存位置特征等。以此回头来加固某政府内网安全以及切入点。

## E-log 日志管理系统

- 安全事件管理中心 HUAWEI eLog（以下简称 eLog）是华为推出的统一日志管理系统，是基于华为 B/S 的安全管理平台，实现日志管理、安全业务分析和日志审计等功能，具有高集成度、高可靠性等特点。
- eLog 采用 B/S 架构可以随时随地进行管理操作，业务扩展和系统维护操作简单。
- eLog 由采集器与分析器两部分组成，采集器主要提供日志收集、数据存储、数据处理功能；分析器由前端 UI 界面与后端日志服务系统组成，其中前端 UI 主要提供报表呈现和配置界面，而后端提供报表查询服务和业务告警。

### eLog 日志存储与转储模型

| 项目 | 在线日志 | 转储日志 |
|------|----------|----------|
| 日志格式 | 文件数据库 | 压缩后的文件数据库 |
| 占用空间 | 较大 | 较小（节省空间 75%） |
| 查询速度 | 免去解压缩过程，最快 | 自动解压后查询，快 |

### 集中式组网方案

- 集中式组网方案成本较低，适用于日志源数量低于 100 台，网络中日志量未超过集中式部署的 eLog 系统处理性能，且日志源分布集中的网络环境，选择该组网方式需要考虑以下因素：
  - 所管理日志源的组网情况
    - 集中式组网时，建议所管理的日志源部署在相同的局域网，如果日志源部署在广域网，集中式部署会导致大量的日志信息占用广域网的带宽，影响正常的业务。
  - 日志量
    - 集中式组网时，建议日志量不要超过一台日志采集器的处理能力。如果现网的日志量超过了一台日志采集器的处理能力，应该考虑使用分布式部署。

### 分布式组网方案

- 日志采集器和 eLog 分析器安装在不同的物理服务器上，多台日志采集器可以共用一台 eLog 分析器，一台 eLog 分析器最多可管理 15 台日志采集器。日志采集器可以部署在不同的子网，采集所在子网的日志源日志。
- 分布式组网方案适用于性能要求高或者日志源分布分散的网络环境。日志量超过集中式部署处理能力，或者日志源超过 100 台，或者日志源分散在多个不同城市等场景均建议采用分布式组网方案。选择该组网方式需要考虑以下因素：
  - 所管理日志源的组网情况
    - 日志源分布在多个区域，区域间需要通过广域网或者 VPN 连接。每个区域部署一台日志采集器，可以避免大量的日志信息占用带宽，节约租用带宽的成本。
  - 日志量
    - 当现网的日志量超过了一台日志采集器的处理能力，需要使用分布式部署。

### eLog 应用场景

#### 安全日志审计

- 面临问题
  - 企业网络系统的安全防范主要依靠防火墙等安全设备，但是这种防范对用户来说是黑盒的、被动的，用户无法看到防火墙拦截攻击的类型、攻击源以及一段时间内的攻击趋势。如果用户能够了解到这些信息，就可以采取主动防御动作。例如将频繁攻击的源 IP 加入黑名单，就可以在其引发事故前将风险降至最低。
  - 随着企业网络的扩大，网络流量组成变的越来越复杂，造成流量统计分析查看困难；另外，企业员工会利用公司网络资源进行网游、炒股、P2P 下载等私人活动，占用大量网络流量，无法有效监控员工上网行为和流量使用情况。
- 解决方案
  - eLog 高效地采集日志源的日志，向用户及时展示华为安全日志源的业务情况，帮助用户了解网络用户的行为，辅助用户迅速识别并消除安全威胁。
  - 通过对华为防火墙设备用户上网行为日志进行采集和分析，eLog 可以追踪企业内网用户的上网行为（如使用 P2P、email、HTTP、MSN、QQ 等业务），并辅助管理员分析内网用户上网行为以及应用时长和流量，进而对内网用户的上网行为进行管理。
  - 针对华为防火墙等设备提供丰富的报表功能，方便用户了解设备的实时和历史安全信息以及网络攻击状况。

#### NAT 溯源

- 面临问题
  - 网络地址转换（NAT，Network Address Translation）被广泛应用于各种类型 Internet 接入方式和各种类型的网络中。原因很简单，NAT 不仅完美地解决了 IP 地址不足的问题，而且还能够有效地避免来自网络外部的攻击，隐藏并保护网络内部的计算机。
  - NAT 在解决了 IP 地址资源的同时带来了一个问题，由于企业组织内部使用相同的 IP 地址，无法追究企业内部的人员在网上的违法行为。
    - 内部员工通过公司网络散布非法言论
    - 内部员工通过公司网络组织犯罪活动
    - 窃取公司商业机密或者技术机密
    - 离职员工通过网络散播不良言论，影响公司形象
    - 事件追责
- 解决方案
  - eLog 通过会话日志的高性能处理能提供业界领先的 NAT 溯源解决方案，支持移动和固网场景，支持和话单的结合完成对用户的溯源。
  - 在该应用场景下，eLog 对 NE40E/80E、Eudemon 防火墙等网络日志源和安全日志源的会话日志进行采集和分析，获取 NAT 信息（包括目的 IP 地址、目的端口、NAT 前源 IP 地址和协议等），结合身份关联数据源（如 AAA 服务器），从而追踪 NAT 用户的上网行为。

## 安全审计技术

### 安全审计概述

- 网络中的安全审计，其目的是重现不法者的操作过程，提供认定其不法行为的证据，也可以用来分析目前安全防御系统中的漏洞。从安全防御的角度上说：是对不法者的威慑。
- 审计系统的主要作用是在事后对安全事件进行审计，为了提供足够的证据，安全审计产品必须具备以下几个功能：
  - 记录使用者：记录使用者的身份和行为，如谁在做什么，什么时候做的。
  - 重现"工作过程"：重现使用者犯罪的过程。
  - 数据不可修改性：审计数据是事后取证的关键。

### 常见的安全审计类型

- 数据库审计
- 运维审计
- 上网行为审计

  - 合法用户滥用操作和误操作
  - 合法用户的异常操作
  - 不明用户的访问
  - 破坏 DB
  - 应用访问带来的破坏
  - 运维带来的数据和系统损坏

### 数据库审计部署模式

#### 单机部署

- 特点
  - 管理中心、审计引擎、授权中心三个组件部署于同一个 VM 上
- 优势
  - 系统组网简单，维护工作量小，节省服务器资源和存储空间
- 适用场景
  - 审计数据库数量小于 5 个，审计流量不大于 500M
  - 要求被审计目标系统与审计系统路由可达，引流插件转发的报文能到达审计系统

#### 分布式部署

- 特点
  - 管理中心、授权中心部署在一个 VM
  - 审计引擎部署于另一个 VM
- 优势
  - 独立部署审计引擎，扩容灵活，在审计流量增大的情况下，只需增加审计引擎
- 适用场景

### 运维安全问题分析

- 来自企业内部的非法威胁
  - 高权限操作风险不透明
  - 违规操作导致敏感信息泄露
  - 误操作导致服务异常甚至宕机
- 来自企业外部的非法威胁
  - 操作风险不可控
  - 黑客盗用帐号实施恶意攻击
  - 无法有效监管操作、必要取证/举证

| 问题 | 说明 |
|------|------|
| 独立的用户数据库 | 用户身份信息分散于各个系统，形成身份信息的孤岛 |
| 身份信息孤岛 | 维护人员同时对多个系统进行维护，工作复杂度会成倍增加 |
| 缺乏集中统一的资源授权管理平台 | 用户权限无法集中管理，越权事件时有发生 |
| 系统账号重叠 | 自然人身份和业务身份的混乱，帐号多人共用，难于确定帐号的实际使用者，难于对帐号的扩散范围进行控制，容易造成安全漏洞 |
| 自然人对多系统的访问频繁切换 | 切换系统登录时，都需要输入用户名和口令进行登录。给工作带来不便，影响了工作效率 |
| 独立的审计 | 无法对支撑系统进行综合分析，不能及时发现入侵行为进行安全预警和数据责任追踪，增加操作风险 |

### 信息安全相关标准、法案

| 标准/法案 | 要求 |
|-----------|------|
| 等级保护 | 国家颁布的安全等级保护技术要求中明确规定，第二级（指导保护级）以及以上级的信息系统中必须记录并保存的各种访问日志。 |
| ISO27001 标准 | 要求组织必须记录用户访问、意外和信息安全事件的日志，并保留一定期限，以便为安全事件的调查和取证。要求组织必须记录系统管理和维护人员的操作行为。明确要求必须保护组织的运行记录。 |
| SOX 法案 | 要求行政人员证明他们公司设计和执行了适当的控制，以保证所有财务报表都可靠而且符合公认会计准则（GAAP）。要求所有在 302 节中所控制的过程都有可信的财务报表。这法令要求 IT 经理对所有有关财务报表的产生过程负责。则要求信息系统经理必须确保所有负责的安全过程都在正确执行，符合安全策略和标准的要求。 |
| CC 标准 | 信息技术通用评估准则（Common Criteria for Information Technology Security Evaluation）中，安全审计是其安全功能要求中最重要的组成部分，同时也是信息系统安全体系中必备的一个措施，它是评判一个系统是否真正安全的重要尺码。 |

## 上网行为审计

### 安全接入之痛

- 企业职工共享网络，接入多台上网终端，威胁企业信息安全；
- 用户安全意识薄弱，极易称为攻击跳板；
- 网络攻击日益猖獗，用户上网难以保障。

现象解析：

- 手机、平板等终端的普及，增加了网络管理难度；
- 缺乏网络防护机制，对于常见和 APT 攻击较难防护。

### 带宽管理之痛

- 上网体验差，员工抱怨网络环境；
- 核心业务无法保障，IT 部门屡遭投诉；
- 分支机构与总部间数据交互慢，影响业务；
- 语音、视频会议系统断断续续；
- 邮件发送、资料下载受严重影响。

现象解析：

- P2P、流媒体等流量占用了大部分带宽；
- 带宽缺乏合理划分与分配措施；
- 单纯扩容带宽，治标不治本。

### 审计合规之痛

- 网络应用更新频繁，难以审计用户上网行为；
- 公安部 82 号令，要求所有互联网服务提供者和联网使用单位，必须能保留相关记录，至少留存 60 天；
- 公网网络需满足"无线非经"法规。

现象解析：

- 无法有效、准确识别用户上网行为；
- 缺乏日志记录，无法满足 82 号令上网日志留存要求；
- "无线非经"法规要求严格，考验产品综合实力。

### 简易运维之痛

- 分支、门店运维力量薄弱，上线周期长；
- 网络节点数量庞大，运维工作量巨大；
- 安全互联缺乏自动化机制，日常维护繁琐和重复性强。

现象解析：

- 分支和总部需具备简单化的运维手段；
- 总部缺乏统一监控和管理工具。

## 态势感知技术

### APT 攻击防御

#### APT 攻击案例——乌克兰电力系统攻击

- 通过鱼叉式钓鱼邮件或其他手段，首先向"跳板机"植入 BlackEnergy，随后通过 BlackEnergy 建立据点，以"跳板机"作为据点进行横向渗透，之后通过攻陷监控/装置区的关键主机。同时由于 BlackEnergy 已经形成具备规模的僵尸网络以及定向传播等因素，亦不排除攻击者已经在乌克兰电力系统中完成了前期环境预置。
- 攻击者在获得了 SCADA 系统的控制能力后，通过相关方法下达断电指令导致断电：其后，采用覆盖 MBR 和部分扇区的方式，导致系统重启后不能自举（自举只有两个功能：加电自检和磁盘引导。）；采用清除系统日志的方式提升事件后续分析难度；采用覆盖文档文件和其他重要格式文件的方式，导致实质性的数据损失。这一组合拳不仅使系统难以恢复，而且在失去 SCADA 的上层故障回馈和显示能力后，工作人员被"致盲"，从而不能有效推动恢复工作。
- 攻击者一方面在线上变电站进行攻击的同时，另一方面在线下还对电力客服中心进行电话 DDoS 攻击，两组"火力"共同配合发起攻击完成攻击者的目的。

#### APT 攻击过程

- 典型的 APT 攻击，包括多个攻击过程，如：资源侦查、外部渗透、命令与控制、内部扩散、数据外发等。一旦攻入企业内部，黑客能在企业内部持续横向渗透，收集敏感信息并回传，造成巨大的损失。

#### APT 攻击定义

- APT（Advanced Persistent Threat，高级持续性威胁）是黑客以窃取核心资料为目的，针对企业发动的网络攻击和侵袭行为。其目标是访问企业网络、获取数据，并长期地秘密监视目标计算机系统。

#### APT 攻击步骤

1. 发送钓鱼邮件给内部用户或通过 U 盘等存储介质传递
2. 内部用户被感染后连接远控服务器
3. 建立据点，长期潜伏和伺机扩散
4. 窃取或破坏数据

#### 传统威胁防御与 APT 威胁防御

- 传统的实时防御是以漏洞为中心的，基于漏洞的签名检测机制有着较高的准确性，可以用以进行设备自动化的阻截。
- 但当基于已知威胁的签名机制不能检测针对其的高级别威胁时，我们就需要转化思路。入侵和破坏是两回事，虽然也存在入侵开始到实际损害发生之间时间窗口很短的情况，但是我们也还是看到，大多数入侵如果想达到目的，需要较长的时间，特别定向攻击和 APT 攻击。那么如果安全团队可以在攻击者完成使命之前阻止其活动，就可以做到这点：我们有可能遭受入侵，但可能不会遭遇破坏。在入侵和破坏之间的时间窗上可以采取更好的安全手段检测并拦截，防止破坏的发生。
- 因此积极的检测和响应则是以威胁为中心，它不再强调单点的检测，也不再单纯的追求告警的精确性，它促使你从面上去着手，将若干的点关联起来，以数据为驱动来解决问题。在整个过程中（数据收集、检测、分析）都需要以威胁为中心，如果丢掉这个中心点，单纯的追求数据的大而全，则必然达不到效果。以威胁为中心，需要很多点构成一个威胁，不单纯追求单点检测的准确性。
- 点构成面，从时间维度、空间维度进行检测分析，以单点检测时间为线索，从时间维度上进行关联，从空间维度进行关联。
- 以威胁为中心，用数据来驱动安全，是检测 APT 类型威胁的有效手段。
- 由此可见，传统的安全产品没有过时，我们还是需要防火墙、需要 Anti-DDoS、IDS/IPS 以及 AV 这些不同的产品，形成一定的防御纵深，阻止随机性的攻击（通常追求机会，被选中往往是因为展现了易被利用的漏洞），并且延缓攻击节奏，扩大检测和响应的时间窗口。同时，传统的安全设备也是响应攻击的基础。

### 态势感知核心技术

#### 态势感知概述

- SA 通常根据一个特定的工作或功能的目标来定义。只有那些与手头的任务有关的情境片段是很重要的。当医生需要知道所有病人的症状来诊断疾病，但医生通常不需要知道病人的历史的每一个细节。同样，飞机的飞行员必须意识到其他飞机、天气和附近的地理环境变化，但飞行员不需要知道副驾驶的午餐吃什么。
- 安全态势感知是以大数据分析为基础，描述用户网络安全状况及变化趋势，辅助运维人员快速发现、定位、处置有效的已知和未知/高级威胁。

#### CIS 标准部署场景

- CIS 标准部署场景需要至少 11 台服务器，适用于网络中流量、日志量较大的场景，可以通过大数据节点的扩容不断提升系统的整体性能和分布式处理能力。CIS 标准场景包含六种类型的主机。
  - 可视化主机：CIS 的对外展示交互窗口。CIS 能够通过可视化平台呈现威胁检测的结果，包括威胁地图、威胁态势呈现等。管理员可通过可视化平台来安装、扩展 CIS 系统；也可以通过可视化平台对 CIS 进行配置、管理和监控。
  - 集群控制主机：CIS 底层大数据集群的管理和控制中枢。主要负责管理"存储检测"和"数据分发"两类主机，实时关注两类主机的运行状态，并统一进行资源调度。
  - 存储检测主机：CIS 大数据集群的数据节点。负责数据统一存储和分布式数据索引，另外还通过分布式数据处理和分析提供威胁检测功能。
  - 数据分发主机：CIS 大数据集群的数据节点。主要负责数据转发功能。
  - 流探针：CIS 了解网络的入口之一。流探针能够接收原始网络流量，并对其进行分析、汇总，提取必要的信息发送给大数据安全平台和沙箱进行后续更缜密的安全监测。
  - 采集器：CIS 了解网络的另一入口。采集器用于收集各种设备和第三方系统的 syslog、Netflow 等日志。采集器可将收集到的日志归一化处理，上报至大数据平台，作为威胁分析判断的来源数据之一。
- 根据业务场景的不同，又可以将 CIS 按照小型化场景、单机场景部署。

#### 数据采集与大数据处理

- 数据采集：通过采集关键网络路径的流量，包括 WEB 流量、MAIL 流量、DNS 流量等，通过采集关键设备和服务器端的日志信息，获取相关软件在终端的各种行为信息等。
- 大数据处理
  - 数据预处理负责对采集器上报的归一化日志和流探针上报的流量元数据进行格式化处理，补充相关的上下文信息（包括用户、地理位置和区域），并将格式化后的数据发布到分布式总线。
  - 分布式存储负责对格式化后的数据进行存储，针对不同类型的异构数据（归一化日志、流量元数据、PCAP 文件）进行分类存储，分布式存储的数据主要用于威胁检测和威胁可视化。考虑到可靠性和高并发性能的要求，分布式存储的数据保存在多个检测/存储节点，并且可以按需扩展存储节点。
  - 分布式索引负责对关键的格式化数据建立索引，为可视化调查分析提供基于关键字的快速检索服务。分布式索引采用了多实例自适应的索引技术和时间片抽取的分层索引结构，索引数据保存在多个检测/存储节点，提供了高可靠性和高并发索引能力，支持按需弹性扩展索引。

#### 威胁检测

- CIS 在收集的大量的原始的流量信息和日志/事件等数据的基础上，采用大数据的技术进行关联分析。CIS 提供了丰富的异常行为检测模型，通过离线检测、实时检测、关联分析、机器学习和综合评估实现贯穿 APT 攻击全阶段的检测，辅以上下文信息的验证，针对 APT 全攻击链中的每个步骤，渗透、驻点、提权、侦查、外发等各个阶段进行检测，建立文件异常、mail 异常、C&C 异常检测、流量异常、日志关联、web 异常检测、隐蔽通道等检测模型并关联检测出高级威胁。
