# DDoS防御与AntiDDoS系统部署及主机安全加固与数据安全

## 第一部分：DDoS攻击与AntiDDoS防御

### DNS解析过程与DNS Request Flood攻击原理

- DNS客户端查询通常采用递归方式，缓存服务器首先会判断本地是否有这个域名的解析缓存。
- 如果本地没有缓存，就会把域名发送到根服务器。根服务器收到www.huawei.com请求后，会判断.com是谁授权管理，并返回.com所在的顶级域名服务器IP地址。
- 缓存服务器继续向顶级域名服务器发送www.huawei.com解析请求，顶级域名服务器收到请求后，会返回下一级.huawei.com的递归服务器IP地址。
- 缓存服务器继续向递归服务器发送www.huawei.com解析请求，递归服务器收到请求后，返回www.huawei.com的解析地址。如果域名层级较多，则递归服务器也会存在多级。
- 缓存服务器得到www.huawei.com的解析IP地址后，将IP地址发送给客户端，同时在本地缓存。
- 后续一段时间内，当有客户端再次请求www.huawei.com这个域名解析时，缓存服务器直接回应解析的IP地址，不再重复询问。缓存服务器就相当于是授权服务器的一个代理，可以缓解授权服务器的压力。

- 为了方便表示，对于上一页提到的根服务器，顶级DNS服务器和递归DNS服务器，在这里统称为授权服务器。
- DNS Request Flood攻击原理其实很简单，就是黑客控制僵尸网络向DNS服务器发送大量的不存在域名的解析请求，最终导致服务器因大量DNS请求而超载，无法继续响应正常用户的DNS请求，从而达到攻击的目的。在DNS Request Flood攻击过程中，攻击的目标可能是DNS授权服务器，也可能是DNS缓存服务器。黑客伪造的客户端IP地址可能是虚假源IP地址，也可能是现网真实存在的IP地址。
  - 如果攻击的是DNS授权服务器，大量不存在的域名解析请求会导致服务器应接不暇，最终耗尽服务器性能；
  - 如果攻击的是缓存服务器，同时会导致缓存服务器不停的向授权服务器发送这些不存在域名的解析请求，一收一发更加重服务器的负担，直到最终导致服务器瘫痪。
- 所以针对DNS服务器发起的DDoS攻击需要从两方面防御，一是防御针对授权服务器发起的攻击，二是防御针对缓存服务器发起的攻击。

### TC源验证防御原理

- 正常情况下，向DNS缓存服务器发送DNS请求的都是上网的用户，所以防御过程中，需要判定这个DNS请求是否是由真实的、正常的浏览器客户端发出。
- TC源验证防御原理介绍：
  - 当客户端发送的DNS请求报文超过告警阈值后，Anti-DDoS系统启动源认证机制。
  - AntiDDoS系统拦截DNS请求，并进行回应，要求客户端以TCP方式重新发起DNS查询。
  - 如果这个源是虚假源，则不会正常响应这个DNS回应报文，更不会重新通过TCP方式重新进行DNS查询。如果是真实客户端，则会重新发送SYN报文，请求建立三次握手。
  - AntiDDoS系统收到客户端发送的SYN报文。源认证通过，客户端源IP加入白名单。
  - AntiDDoS系统发送错误序列号的响应报文，客户端重新请求建立三次握手，AntiDDoS系统将客户端第二次发送的三次握手请求直接放行，送给服务器。
  - 客户端与服务器之间建立三次握手成功，并通过TCP方式完成本次DNS查询。

### CNAME防御

- 正常情况下，向DNS授权服务器发送DNS请求的可能是上网的用户，也可能是缓存服务器，所以使用TCP源验证无法判断请求是否来自合法用户。还有些特殊场景，客户端不支持使用TCP协议发送DNS请求，因此无法使用TC源验证验证对方身份。
- 缓存服务器为合法的服务器，如果攻击者发送大量不存在的域名查询到缓存服务器，缓存服务器会因没有记录而向授权服务器发送请求，使用TCP源验证和被动防御都无法防御缓存服务器发送来的DNS请求，因此CNAME防御应运而生。

### DNS反射攻击防御

- 新型UDP反射放大攻击Memcached和IPMI被挖掘。尤其Memcached凭借其超5万倍的反射放大倍数将DDoS攻击流量峰值再一次推向1.7Tbps的历史新高，反射攻击的威力不容小觑。
- 下面我们就以利用DNS反射攻击威力，讲解反射攻击的基本工作原理。
- 黑客将自己的源IP地址伪造成被攻击目标的IP地址，然后向一系列网络中开放的DNS服务器发送大量的查询请求。通过伪造DNS请求报文的源IP地址，控制DNS回应报文的流向，这些DNS回应报文就会都被引导到被攻击目标，导致被攻击目标的网络拥塞，拒绝服务。

DNS反射攻击防御：AntiDDoS系统借鉴防火墙的会话表机制，利用DNS交互过程中，DNS Query报文首包建会话的机制，防御DNS反射放大攻击。

- 触发防御后，利用五元组为首个DNS Query报文创建会话，后续发送过来的DNS Reply需要匹配会话，如果命中会话，则允许通过，没有命中则丢弃。
- 攻击者仿冒Victim地址发送DNS请求，DNS服务器返回DNS Reply Flood，AntiDDoS设备通过会话匹配机制进行防御。

#### AntiDDoS使用场景

- IDC出口带宽流量较大，业务类型丰富，可靠性要求高，容易遭受Flood类攻击和新型应用层攻击的双重威胁。华为公司针对IDC网络特点，推出万兆级、全方位IDC防护解决方案。通过对DDoS、僵尸、木马、蠕虫等实施过滤，大大提高IDC的防御能力；针对IDC内部的Web服务器提供精细化防御，有效防御网页篡改、网页挂马等威胁。
- 互联网行业抵御来自外网的黑客攻击、病毒、DDoS、木马、恶意程序，又要确保业务应用的畅通，以及确保内部接入终端不会给整个网络带来危害。华为公司针对企业网推出全方位防护方案，可以同时针对上百种攻击提供精细化防御，有效防御各种类型的攻击。
- 网银、信用卡中心暴露在Internet中，容易受到抢占链路带宽的UDP Flood和ICMP Flood的混合型攻击及应用型HTTP Flood、HTTPS Flood攻击。一旦发生攻击，必定会影响客户正常业务，严重的可能会造成经济损失。华为针对金融业网络特点推出"检测设备与清洗设备联动"的清洗方案，以保护金融网络安全。方案中，清洗设备提供多种Flood类攻击和应用层DDoS防御，解决链路拥塞的同时，提供业务的精细化防护，确保网银、信用卡等业务的正常运行及安全，有效防御针对金融系统在线业务的DDoS攻击。

#### AntiDDoS解决方案组成

- 检测中心：检测中心负责对流量进行检测，发现攻击后上报管理中心，由管理中心下发引流策略至清洗中心进行引流清洗。
- 清洗中心：清洗中心主要根据管理中心下发的策略进行引流、清洗，并把清洗后的正常流量回注，同时将这些动作记录在日志中上报管理中心。
- 管理中心：即ATIC，负责检测中心和清洗中心的统一管理，是Anti-DDoS解决方案的管理中枢。提供设备管理、策略管理、性能管理、告警管理、报表管理等功能。

#### 静态引流与动态引流

- 静态引流，就是将所有去往防护对象的流量都引流到清洗设备进行清洗，不论流量是否存在异常。
- 动态引流，就是将去往防护对象的流量会先复制一份到检测设备进行检测，如果发现存在异常才会被引流到清洗设备进行清洗。如果没有异常流量，不会触发引流。

#### 动态引流流程（旁路部署模式）

- 该流程以旁路部署-动态引流的模式进行介绍：
  - 正常流量与攻击流量到达网络边界设备。
  - 网络边界设备通过端口镜像或分光器将流量复制到检测设备，检测设备检查流量是否超过定义的阈值。
  - 如果超过阈值，判定为异常流量，上报ATIC。
  - ATIC根据防御策略向清洗设备下发引流策略。
  - 清洗设备收到引流任务后，向对端设备发送UNR路由。
  - 所有流量通过BGP路由被引导至清洗设备，清洗设备对异常流量进行检测，并清洗。
  - 清洗完成后，正常流量被发送回原路径。
  - 原路径上的设备通过策略路由经路由器送往目的地。

#### 常见引流/回注模式

- 引流：是当ATIC检测到异常流量时，把待清洗的流量引导至清洗设备的过程。
- 回注：是当清洗设备将异常流量清洗后，发送回原路径的过程。
- 典型的引流和回注模式如下表：

| 引流 | 回注 |
| --- | --- |
| 静态路由引流 | 静态路由回注 |
| 策略路由引流 | 策略路由回注 |
| BGP引流 | UNR路由回注 |
| 组合方式 | 二层回注 |
|  | GRE回注 |
|  | MPLS LSP/VPN回注 |

### BGP动态引流+UNR路由回注配置实例

- 因为引流与回注发生在清洗设备上，为了方便展示，示意图中只画了清洗设备，检测设备未在图中展示。
- 该实例以BGP动态引流+UNR路由回注进行讲解。
  - 前提条件：动态引流的时候，ATIC会下发引流策略，在清洗设备上产生一条UNR路由用于引流，所以R1和清洗设备之间需要运行BGP协议进行路由的学习，并且在清洗设备上将UNR路由引入BGP协议，通过BGP协议传递UNR路由。并且为产生的UNR路由指定下一跳地址为P2接口的地址，后面用于清洗后的流量回注到R1。
    - 流量正常时，清洗设备不会进行引流，通过路由器R1能够将流量正常转发到服务器。
    - 如果发现异常流量，ATIC下发引流策略到清洗设备。
    - 清洗设备会自动产生一条UNR路由，该条路由会被引入BGP协议中。
    - R1通过BGP协议学到了去往10.1.7.102的路由，并放入路由表中。
    - R1中存在两条到达10.1.7.0的路由，根据最长掩码匹配，R1选择掩码最长，匹配最精确的路由把流量送往目的网段。
    - 会将访问服务器的流量发送给清洗设备，完成引流。
    - 清洗完成后，清洗设备查找路由表，根据路由表将正常流量回注回R1。
    - 通过在R1上配置策略路由，将在P2收到的回注流量，通过策略路由发送到目的设备，否则会形成环路。

### AntiDDoS系统配置举例

部署需求：
- 为防护某企业内部服务器设备免受DDoS攻击的威胁，在网络出口部署AntiDDoS系统；
- 检测设备负责检测异常流量，如果发现存在异常流量访问服务器，通知ATIC下发引流策略，清洗设备收到引流策略后引流并清洗异常流量。

- 指定接口功能前需要将接口加入安全区域，并配置安全策略放行流量。

#### 清洗设备UNR路由与防环路配置

- 清洗设备上生成的UNR路由会被引入到BGP中，并通过BGP发布到R2。这样，当R2收到目的地址为10.1.7.102/32的流量时，通过查路由表，根据最长掩码匹配原则，优先将流量从接口E2/0/0转发至清洗设备；清洗设备完成清洗后，查路由表，根据UNR路由将流量从接口GE1/0/1转发至R2。在清洗设备上配置团体属性，R2接收清洗设备发布的BGP路由后不再通告给其他对等体，以避免路由环路。
- 生成的这条UNR路由有两个作用：一方面，在R2上实现引流功能；另一方面，在清洗设备上实现回注功能。清洗设备无需再单独配置回注功能。
- 为了避免环路，在R2接口E2/0/1上需要配置策略路由，参考命令如下：
  - 定义流分类：

```cli
[R2] acl 3001
[R2-acl-adv-3001] rule permit ip
[R2-acl-adv-3001] quit
[R2] traffic classifier class1
[R2-classifier-class1] if-match acl 3001
[R2-classifier-class1] quit
```

  - 配置流行为并配置报文转发动作：

```cli
[R2] traffic behavior behavior1
[R2-behavior-behavior1] redirect ip-nexthop 10.1.6.23 interface Ethernet 1/0/1
[R2-behavior-behavior1] quit
```

  - 定义流量策略并在策略中为类指定行为：

```cli
[R2] traffic policy policy1
[R2-trafficpolicy-policy1] classifier class1 behavior behavior1
[R2-trafficpolicy-policy1] quit
```

  - 在接口上应用策略路由：

```cli
[R2] interface Ethernet 2/0/1
[R2-Ethernet2/0/1] traffic-policy policy1 inbound
[R2-Ethernet2/0/1] quit
```

#### 漏洞评估系统-CVSS

- CVSS，全称Common Vulnerability Scoring System，是一个"行业公开标准"，其被设计用来评测漏洞的严重程度，并帮助确定所需反应的紧急度和重要度。
- 基础度量指标（以CVE-2016-0099漏洞评分为例）：
  - 攻击向量（AV）
  - 攻击复杂度（AC）
  - 所需权限（PR）
  - 用户交互（UI）
  - 范围（S）
  - 机密性影响（C）
  - 完整性影响（I）
  - 可用性影响（A）

CVSS 3.0 Severity and Metrics:
- Base Score: 7.8 HIGH
- Vector: AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H (V3.0 legend)
- Impact Score: 5.9

| 分值 | 对应问题级别 |
| --- | --- |
| 9-10分 | 致命 |
| 7-8.9分 | 严重 |
| 4-6.9分 | 一般 |
| 0-3.9分 | 提示 |

参考链接：https://nvd.nist.gov/vuln-metric/cvss/v3-calculator?name=CVE-2016-0099&vector=AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H&version=3.0

#### 主机面临的威胁

| 为什么会被攻击 | 面临的威胁 |
| --- | --- |
| 计算机中有攻击者所需要的信息 | 依托系统、服务漏洞实现突破 |
| 可成为攻击者攻击其他系统的跳板 | 利用系统、服务漏洞实现提权 |
| 可用于挖矿和做肉鸡 | 植入恶意软件 |
| 便于隐藏攻击者攻击踪迹 | 植入远控等 |

- 一般攻击者的目标是利用漏洞获取系统拥有者（owner）或者根用户（root）的权限。
- 为了更好的检测企业安全性，模拟攻击者对系统进行评估，这个过程叫"渗透测试"。

### 渗透测试过程

#### 针对主机的渗透测试

- 渗透测试分为白盒测试和黑盒测试。
  - 白盒测试就是在知道目标网站源码和其他一些信息的情况下对其进行渗透，有点类似于代码分析。
  - 黑盒测试就是只告诉网站信息，其他均隐藏，再去渗透。
- 渗透测试一般流程：

```text
确定目标 -> 信息收集 -> 漏洞探测 -> 漏洞利用 -> 获得Webshell -> 内网渗透 -> 内网转发 -> 痕迹清除 -> 撰写测试报告 -> 结束
```

#### 信息收集

- 知己知彼，百战百胜。
- 根据网站URL可以查出一系列关于该网站的信息，通过URL我们可以查到该网站的IP、该网站操作系统、脚本语言、在该服务器上是否还有其他网站等等一系列的信息。
- 操作系统类型（Linux/Windows）
- 应用服务类型（Web/App）
- 服务运行语言（PHP/JAVA/ASP）

- Metasploit是一款开源的安全漏洞检测工具，可以帮助安全和IT专业人士识别安全性问题，验证漏洞的缓解措施，并管理专家驱动的安全性进行评估，提供真正的安全风险情报。这些功能包括智能开发，代码审计，Web应用程序扫描，社会工程。
- https://www.metasploit.com/

#### 漏洞利用

- 漏洞利用是指利用程序的某些漏洞，获取计算机的权限。Metasploit是最为知名的一个漏洞利用工具。

#### 漏洞利用（例：MS17-010）

- 2017年4月14日晚，黑客团体Shadow Brokers（影子经纪人）公布一大批网络攻击工具，其中包含"永恒之蓝"工具，"永恒之蓝"利用Windows系统的SMB漏洞可以获取系统最高权限。5月12日，不法分子通过改造"永恒之蓝"制作了wannacry勒索病毒，英国、俄罗斯、整个欧洲以及中国国内多个高校校内网、大型企业内网和政府机构专网中招被勒索。针对永恒之蓝，微软给出的编号为MS17-010。

- 常见端口转发有22、3389端口。
- 内网代理转发的过程主要使用到的协议有http、icmp、tcp等协议。

#### 帐户安全设置

- 锁定系统中多余的自建帐号
  - 锁定&解锁账号：
    - 使用命令passwd -l <用户名>锁定不必要的账号。
    - 使用命令passwd -u <用户名>解锁需要恢复的账号。
- 设置系统口令策略
  - 使用以下命令查看密码策略设置：

```cli
# cat /etc/login.defs | grep PASS
```

  - 配置密码策略，配置文件/etc/login.defs：

```text
PASS_MAX_DAYS 90    #新建用户的密码最长使用天数
PASS_MIN_DAYS 0     #新建用户的密码最短使用天数
PASS_WARN_AGE 7     #新建用户的密码到期提前提醒天数
PASS_MIN_LEN 9      #最小密码长度9
```

- 设置口令过期时间
  - 操作：修改/etc/login.defs文件，添加内容：PASS_MAX_DAYS 90
- 登录连续认证失败锁定帐号
  - 参考配置操作：
    - CentOS：在/etc/pam.d/system-auth中auth列中添加：auth required pam_tally.so onerr=fail deny=6 unlock_time=300
    - Deny：失败次数；Unlock_time：锁定帐户多少秒后解锁。

#### 系统安全设置

- 设置访问控制策略限制能够使用ssh管理本机的IP地址
  - 修改ssh配置文件/etc/ssh/sshd_config
  - 如需要限制只让192.168.1.0/24网段登录root用户，可在配置文件中添加：allowusers root@192.168.1.*
  - 保存后重启ssh服务：# service sshd restart
- 禁止root用户远程登陆
  - 检查/etc/ssh/sshd_config：
  - 查看是否有此条配置：PermitRootLogin yes
  - 可将此条配置修改为PermitRootLogin no
  - 保存后重启ssh服务：# service sshd restart
- 修改帐户TMOUT值，设置自动注销时间
  - 检查方法：# cat /etc/profile 查看有无TMOUT的设置
  - 添加配置：TMOUT=600，意思是无操作600秒后自动退出
- 启动IPTABLES并设置相关策略
  - 使用命令iptables-save来查看当前iptables策略。
  - 系统已经预置部分策略，如input仅允许ICMP端口、22端口、80端口。
  - 如果需要添加其他端口请添加相应IPTABLES实例。
- 修改SSH监听端口
  - 当前为22端口，可修改为其他端口，如2233、2345等
  - CentOS修改配置文件/etc/ssh/sshd_config；插入一行：port 2233
  - 重启sshd服务：# service sshd restart

#### Windows安全配置

根据业务需要，选择性的设置开启或者关闭Windows的策略配置，实现Windows的安全策略。

- 取消默认共享：
  - 编辑注册表键HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\services\LanmanServer\Parameters，新建项AutoShareServer，值为0，即可关闭盘符默认共享，新建项AutoShareWks，值为0，即可关闭ADMIN默认共享。
- 开启审核策略：
  - 在本地安全策略的审核策略中审核所有的成功失败操作，记录的信息可以在事件查看器的Windows日志中查看。
- 修改TTL值：
  - 编辑注册表键HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\services\Tcpip\Parameters，新建项defaultTTL，随便赋值，以防黑客通过ping获取TTL以鉴别操作系统类型。
- 关闭不必要的服务：
  - Windows默认会启动多个服务，可以在计算机管理的服务中禁用相关服务，如下可以禁用的服务：
    - COM+EventSystem
    - Computer Browser
    - DistributedLinkTracking Client
    - RoutingandRemoteAccess

- 停用Guest帐户：
  - 在计算机管理的本地用户和组中禁用Guest帐户，并为Guest帐户设置复杂密码，并拒绝远程访问。
- 重命名或禁用Administrator帐户：
  - 在计算机管理的本地用户和组中为Administrator帐户重命名，或直接禁用。
- 创建陷阱帐户：
  - 在计算机管理的本地用户和组中创建一个名为Administrator的本地帐户，并将它的权限设置成最低，加上一个超过10位的强密码。可通过将其隶属于Guest组已达到权限最低。
- 限制用户数量：
  - 在计算机管理的本地用户和组中删除所有的测试帐户、共享帐户和普通部门帐户，一般情况下，如果系统用户超过10个，一般总会存在一两个弱口令帐户。
- 开启帐户锁定策略：
  - 在本地安全策略的帐户锁定策略中设置帐户锁定阈值为3次，帐户锁定时间为30分钟，重置帐户锁定计数器为30分钟之后。
- 开启密码策略：
  - 在本地安全策略的密码策略中启用密码复杂性要求，设置密码长度最小值为7，密码最短使用期限为1，密码最长使用期限为42，强制密码历史为24，禁用以可还原的加密储存密码。
- 设置双重加密帐户保护：
  - 在运行对话框中输入syskey，启用SAM数据库加密工具，为Windows登录设置双重加密，注意此功能在Windows 10中已被剔除。

#### Windows用户组权限

- Administrators管理员组：Administrators中的用户对计算机/域有不受限制的完全访问权。
- Power User高级用户组：Power Users可以执行除了为Administrators组保留的任务外的其他任何操作系统任务。分配给Power Users组的默认权限允许Power Users组的成员修改整个计算机的设置。但Power Users不具有将自己添加到Administrators组的权限。
- Users普通用户组：用户可以运行经过验证的应用程序。Users组是最安全的组，因为分配给该组的默认权限不允许成员修改操作系统的设置或用户资料。
- Guests来宾组：按默认值，来宾跟普通Users的成员有同等访问权，但来宾帐户的限制更多。
- Everyone所有的用户：这个计算机上的所有用户都属于这个组。
- SYSTEM：SYSTEM不允许任何用户的加入，系统和系统级的服务正常运行所需要的权限都是靠它赋予的。

## 第三部分：数据安全

### 前言

- 我们已经进入大数据时代，每天都会产生大量各种形式与结构的数据，这些数据关乎我们的个人隐私、企业的运营、社会基础设施的正常工作。
- 当年在911事件后，很多企业因为数据被破坏而无法正常运营，造成巨大损失；而有些公司由于平时注意对业务数据的存储和备份，因此能在出现意外之后的很短时间内迅速通过异地备份，恢复意外发生之前的数据，使业务工作能继续推进。
- Facebook数据泄露事件一度成为互联网行业的焦点，几百亿美元市值瞬间蒸发，这个代价足以在地球上养活一支绝对庞大的安全团队，甚至可以直接收购几家规模比较大的安全公司了。

### 数据安全概述

- 概述：随着科技的发展，数据被泄露的风险越来越大。2011～2016年，出现多家电商平台大量用户数据外泄的事件。据调查，70%的数据泄露由内部威胁造成，由此带来巨大的经济损失。导致数据泄露的主要原因包括：黑客通过网络攻击、木马、病毒窃取，设备丢失或被盗，使用管理不当等。也就是说，数据从创建、存储、访问、传输、使用到销毁的全生命周期管理过程中都会遇到威胁。下面我们将逐步了解相关内容。
- 目标：清楚描述数据安全的要素。

#### 数据安全三要素

- Confidentiality（保密性）：数据的保密性就是指具有一定保密程度的数据只能让有权读到或更改的人进行读取和更改。
- Integrity（完整性）：数据的完整性是指在存储或传输的过程中，原始的数据不能被随意更改。这种更改有可能是无意的错误，如输入错误、软件缺陷；也有可能是心怀叵测的人为篡改和破坏。在设计数据库以及其他数据存储和传输应用时，都要考虑数据完整性的校验和保障。
- Availability（可获得性）：数据的可获得性是指对于该数据的合法拥有和使用者，在他们需要这些数据的任何时候，都应该确保他们能够及时得到所需要的数据。举例来说，我们常对重要的数据或服务器在不同地点作多处备份，一旦A处有故障或灾难发生，B处的备用服务器能够马上上线，保证信息服务不会中断。

### 数据治理流程

- 概述：数据从诞生到销毁有多个阶段。每个阶段都存在各种各样的数据安全风险。本节将对这些阶段的主要作用和面临的风险进行逐一介绍。
- 目标：清楚描述数据治理的全流程。

数据治理流程：

```text
数据采集 -> 数据存储 -> 后台数据分析 -> 共享和数据再分发 -> 前台业务处理 -> 访问和维护 -> 展示和应用 -> 数据销毁
```

#### 数据采集

- 数据采集：是指企业采集用户数据的阶段。从系统外部采集数据并输入到系统内部的一个接口。比如摄像头、麦克风，都是数据采集工具。采集的数据可以包括用户的各种信息。

#### 数据传输安全

- 流量保护：全站HTTPS是目前互联网的主流趋势，它解决的是用户到服务器之间链路被嗅探、流量镜像、数据被第三方掠走的问题。这些问题其实是比较严重的，比如电信运营商内部偶有舞弊现象，各种导流劫持插广告（当然也可以存数据，插木马），甚至连AWS也被劫持DNS请求，对于掌握链路资源的人来说无异于可以发动一次"核战争"。即使目标对象IDC入侵防御做的好，攻击者也可以不通过正面渗透，而是直接复制流量，甚至定向APT，最终只是看操纵流量后达到目的的收益是否具有性价比。
- 在用户到服务器之间还涉及两个业务安全方向的问题。
  - 第一个问题是账号安全，只要账号泄露（撞库&爆破）到达一定数量级，把这些账号的数据汇总一下，就必定可以产生批量数据泄露的效果。
  - 第二个问题是反爬，爬虫的问题存在于一切可通过页面、接口获取数据的场合，大概1小时爬个几百万条数据是一点问题都没有的，对于没有彻底脱敏的数据，爬虫的效果有时候等价于"黑掉"服务器。账号主动地或被动地泄露+爬虫技术，培育了不少黑产和数据获取的灰色地带。

#### 前台业务处理

- 前台业务处理：主要包括用户或业务在前台进行各种数据查询和API接口访问的阶段。

#### 鉴权模型

- 在很多企业的应用架构中，只有在业务逻辑最开始处理的部分设置登录态校验，后面的事务处理不再会出现用户鉴权，进而引发了一系列的越权漏洞。事实上越权漏洞并不是这种模型的全部危害，还包括各种K/V、RDS（关系型数据库）、消息队列等等，RPC没有鉴权导致可任意读取的安全问题。
- 在数据层只知道请求来自一个数据访问层中间件，来自一个RPC调用，但完全不知道来自哪个用户，还是哪个诸如客服系统或其他上游应用，无法判断究竟对当前的数据（对象）是否拥有完整的访问权限。绝大多数互联网公司都用开源软件或修改后的开源软件，这类开源软件的特点是基本不带安全特性，或者只具备很弱的安全特性，以至于完全不适用于海量IDC规模下的4A模型（认证、授权、管理、审计）。
- 对于业务流的鉴权模型，本质上是需要做到Data和App分离，建立Data默认不信任App的模型，而应用中的全程Ticket和逐级鉴权是这种思想下的具体实现方法。

#### 数据存储

- 数据存储：将数据存储在大型数据库中的阶段。这个阶段涉及到很多数据加密存储的算法，以及数据备份与恢复的问题。
