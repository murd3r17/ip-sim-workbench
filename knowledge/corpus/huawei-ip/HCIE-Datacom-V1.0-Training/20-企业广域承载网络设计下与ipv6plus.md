# 企业广域承载网络设计（下）与IPv6+

本篇承接企业广域承载网络的 QoS / 切片 / 可靠性 / 优化运维设计，并开启 IPv6+ 概述与演进。

---

## QoS 规划建议

网络正常时不同业务可走不同链路互不影响；链路故障切换后可能形成带宽竞争，关键业务需统一部署 QoS。若业务超过 8 种，应适当归类合并。示例：

| 优先级 | 业务 | 调度方式 | 权重 | 流量整形 | 丢弃方式 |
|--------|------|----------|------|----------|----------|
| CS6/CS7 | 协议报文 | PQ | NA | NA | 尾丢弃 |
| — | 生产业务 | PQ | NA | NA | 尾丢弃 |
| AF4 | VoIP、视频会议 | PQ | NA | 配置限速，避免饿死低优先级 | 尾丢弃 |
| AF3 | 视频监控 | WFQ | 按现网确定 | NA | WRED |
| AF2 | 办公业务 | WFQ | 按现网确定 | NA | WRED |
| AF1 | OA 业务 | LPQ | NA | NA | 尾丢弃 |
| BE | 其他业务 | LPQ | NA | NA | 尾丢弃 |

### QoS 部署位置

1. CE 无法分类标记时，可在 **PE 入口**标记。
2. PE 入口侧明确感兴趣流，并部署流量限速。
3. 所有承载网设备**出方向**部署拥塞避免与拥塞管理。

## 网络切片

### 介绍

网络切片可在网络中划分独享资源，承载高价值业务。切片层级与 SR 隧道不同，主要基于 1.5 层或 2 层资源预留，可与 SR 隧道同时使用。实现方式一般基于**信道化子接口**或 **FlexE**。

| 方式 | 特点 |
|------|------|
| 信道化子接口 | 队列资源隔离；多层次调度实现接口资源灵活精细管理；结合控制器可端到端资源预留 |
| FlexE | 队列和接口资源隔离；按 TDM 时隙严格隔离，满足资源独享 |

### 切片设计

现有设备切片主要基于带宽：按业务需求创建相应带宽切片，将 SR 隧道与切片绑定。

- **默认切片**：可部署 SR BE 或 SR Policy。
- **业务切片**：内部署 SR Policy；部署 BFD 检测隧道状态，实现切片内 Hot-standby 与 VPN FRR；控制器基于亲和属性算切片承载隧道，并在切片内调优。

### 使用场景

- 50GE 及以上接口推荐 FlexE；50GE 以下推荐信道化子接口。
- 跨越 **MSTP** 设备时只能用信道化子接口切片。
- 跨越 **OTN** 时可按需选用 FlexE 或信道化子接口。

### 典型规划示例

按应用类型放入不同切片，并结合传输线路选型：

- 内联业务切片（如 5G 带宽）：生产、办公、测试等
- 外联业务切片（如 5G 带宽）：金牌/银牌/铜牌业务
- 互联网业务切片（如 1G 带宽）：上网/APP 业务
- 新业务切片（如 1G 带宽）

传输使用 MSTP 时，切片技术只能使用信道化子接口。

## 可靠性设计

术语：RPO（Recovery Point Objective）、RTO（Recovery Time Objective）；GR（Graceful Restart）；NSR（Non-Stop Routing）。

### 控制器可靠性

- 容灾：心跳链路监控主备关联，复制链路同步数据；异常时告警，支持手动或仲裁自动处理。
- DRMgr 为华为自研，无需额外购买第三方 HA 软件。
- 主备倒换一般可在 10 分钟内完成，因此 GR 时间最小不能小于 20 分钟。

### 设备可靠性

- 主控板 1+1 主备（推荐 NSR，主备平滑倒换）
- 接口板多微引擎负载分担
- 电源最大备份
- 风扇等关键部件冗余备份

### 网络可靠性技术概览

| 技术 | 用途 |
|------|------|
| BFD / SBFD | 检查连通性 |
| IP FRR（LFA/RLFA/TI-LFA） | 中间网络链路与节点保护 |
| Anycast FRR | 特定节点（含中间与尾节点）保护 |
| Hot-Standby | 端到端隧道保护 |
| Mirror SID | 尾节点保护 |
| 防微环 | 防止全网收敛时间不一致导致的短暂环路 |

### 源端网络可靠性

源端含源 CE 及 CE—源 PE 链路。故障点：源 CE、CE—PE 链路、源 PE。

手段：BFD 快速感知 + IP FRR（主要 LFA/RLFA）计算备用链路，快速切到保护路径。

中间网络带宽不足或时延过大时，需部署 TWAMP 或 IFIT 感知质量。

### 宿端网络可靠性

宿端含宿 PE、宿 CE、PE—P 链路、PE—CE 链路。故障点：宿 PE、PE—P、宿 CE、PE—CE。

- 宿 PE / PE—P：BFD + Mirror SID 或 Anycast FRR 切到备用宿 PE
- 宿 CE / PE—CE：BFD + IP FRR（LFA/RLFA）

## 优化与运维设计

网络建成后需关注运行质量，预先做优化与运维设计。

### 网络性能监控

常用技术对比：

- **SNMP**：获取常用设备性能；频繁采集时压力较大。
- **Telemetry**：订阅—上报；频繁获取时对设备压力相对较小；适合秒级监控。
- **NQA**：模拟流量测质量，精度不足。
- **TWAMP**：统一检测模型与报文格式，部署简单；测链路质量（丢包、时延、抖动）。

华为云广域场景建议：

| 指标 | 技术 |
|------|------|
| 常用设备性能 | SNMP |
| 秒级网络性能（含 SR Policy） | Telemetry |
| 链路质量 | TWAMP |
| 链路/隧道带宽利用率、隧道丢包率 | Telemetry |
| 链路时延 | TWAMP |

### 网络流量调优

传统 MPLS TE 用 CSPF 分布式算路，难以协同管理全网带宽。控制器根据设备上报的性能数据（SNMP/FTP/Telemetry 等）与 TWAMP/IFIT 质量结果，调优并下发新路径。

**调什么**：

- **链路调优**：选中链路，参与算路的是链路上承载的所有 LSP
- **隧道调优**：选中隧道，参与算路的是对应 LSP

**怎么调**：

- **自动调优**：定时优化（如每 5 分钟或更多）；带宽越限触发；维护窗口触发。自动周期为 5 分钟整数倍。
- **手动调优**：用户随时按网络状况调整。

调优策略维度：

- **流量**：须设链路触发阈值，超限后局部或全局调优
- **时延**：比较配置时延与采集累加时延，超限隧道局部调优
- **时延+流量**：二者为“或”

手动调优常见场景：改链路约束改路径；业务配置完成后重优化；质量下降未达自动阈值、或带宽利用率不均时做局部/全局调优。

### 应用调优

在已部署 VPN 的网络上，按应用类别划分并用 **DSCP** 标识；DSCP 对应隧道 Color，将应用流量引入对应隧道。一般通过 **SR Policy Group + DSCP** 实现：CE 侧赋 DSCP，同 VPN 不同应用走不同 SR Policy。

### 用户管理与维护窗口

默认用户类型：

| 类型 | 权限概要 |
|------|----------|
| Administrators | 除用户管理、安全日志、在线用户外的大部分权限 |
| 安全管理员组 | 用户管理、安全日志、在线用户 |
| 操作员组 | 非安全功能类操作 |
| 监控员组 | 查看非安全功能，无操作权限 |

用户监控：安全管理员可查看在线用户、访问地址、时间、角色；可发即时消息或强制注销。会话数由“最大在线会话数”控制；监控不涉及用户个人信息。

**维护窗口**：为设备/链路割接设置维护策略；维护开始生成绕行路径，结束触发调优算路；维护期间流量不经过被维护对象。

   - A. SR-MPLS BE 隧道
   - B. SRv6 BE 隧道
   - C. SR-MPLS Policy 隧道
   - D. SRv6 Policy 隧道

参考答案：ABCD

## 企业广域章节总结

- 先设计基础网络：物理网络、IP/IPv6 地址、IGP。
- 其上搭建隧道：SR-MPLS BE / Policy、SRv6 BE / Policy；关注路径规划、引流与逃生。
- 隧道承载 VPN；VPN 规划基于业务类型与需求。
- 通过 QoS 与网络切片保障 SLA；通过控制器、设备、网络高可靠设计保障业务可靠。
- 建成后从性能监控与流量调优入手做调优；按用户等级划分维护范围，在合适时间维护。

# IPv6+ 概述与网络演进

## 前言与目标

IPv6 地址丰富、安全可靠、可灵活扩展，是网络演进必然趋势。IPv6+ 是对 IPv6 的进一步开发与应用，能为用户创造更大价值。

本课程介绍 IPv6+ 基本概念与发展趋势、关键技术应用，以及数据中心、广域网、园区网等场景的 IPv6 演进方案（阶段、技术与架构）。

学完后应能：描述 IPv6+ 相关概念与关键技术应用；基于 DC/广域/园区描述 IPv6 演进趋势。

## 数据通信网络是数字化基石

数据通信网络连接个人、企业与算力，包含多样化设备，是数字化世界的基石（数据中心、广域/运营商城域骨干、办公、家庭、生产、基站等）。

IP 是网络层最重要协议之一：设备对载荷做 IP 封装后转发；在路由表中查目的 IP，基于最短路径转发。

### MPLS 的出现

MPLS（Multiprotocol Label Switching）是 IP 骨干网技术：在无连接 IP 网上引入面向连接的标签交换，结合三层路由与二层交换。在 IP 报文中增加 MPLS 头，基于标签转发，效率更高，标签可携带指令；本质是隧道技术，支持流量工程、VPN、QoS 等。

### IP 网络三个时代

1. **Internet 时代**：以 IPv4 为代表的尽力而为转发。
2. **全 IP 时代**：核心是 MPLS，可做一定流量工程与端到端 VPN。
3. **万物互联智能时代**：核心是 **IPv6+**；连接模型灵活，SLA 从连通性扩展到时延、抖动、丢包等；以 **SRv6** 为核心的技术族引领进入 IPv6+ 时代。

### 从 MPLS 到 SRv6

SRv6 统一转发平面，具备简化协议、高扩展性、可编程等优势。相对 Classic MPLS / SR-MPLS，控制面与转发面均可简化（IPv6 + SRH）。

## IPv6+ 技术内涵

以 SRv6（分段路由与网络编程）、网络切片（FlexE）、确定性网络（DetNet）、随流检测（iFIT）、新型组播（BIERv6）、应用感知（APN6）等为代表。

三大类：

1. **基础连接**：单播 SRv6、组播 BIERv6；Native IPv6，去 MPLS 化。
2. **体验保障**：切片（资源预留、确定性）、随流检测（实时质量）。
3. **应用视角**：APN6（应用级网络服务）、SFC（业务链编程）。

缩写：FlexE（Flexible Ethernet）、DetNet（Deterministic Networking）、iFIT（in-situ Flow Information Telemetry）、BIERv6（Bit Index Explicit Replication IPv6 Encapsulation）、APN6（Application-aware IPv6 Networking）。

### 演进三阶段（能力视角）

- **阶段一**：SRv6 简化协议，解决 MPLS 分段配置、人工跨域打通效率低；SRv6 Policy 快速调优，为自治网络打基础。
- **阶段二**：引入网络切片与 FlexE，端到端隔离、路径可管可控、专享资源；随流检测实时感知质量并调整。
- **阶段三**：更细粒度基于应用的体验保障；应用信息可进 IPv6 扩展头，网络识别后提供差异化通道。

### 应用案例要点

- 运营商安全清洗：两张骨干网带宽与 VPN 能力不均，可在大带宽网部署 SRv6 引入流量，缩短开通周期。
- 企业上云专线：传统 MPLS 跨多 AS、多团队协调；SRv6 可在 CPE 与云 PE 间建端到端逻辑专线，一跳入云。
- iMaster NCE + SRv6：逐段测时延，按最小时延算路，提升公有云竞争力。

其他概念：WAMS（Wide Area Measurement System）；广域一张网（跨域协同服务，如金融二级行/网点经一级行汇聚到核心与总行 DC）；VR/AR。

## BIER / BIERv6

BIER：将目的节点集合以比特串封装在报文头发送；中间节点无需为每条组播流建树和保存流状态，仅按目的集合复制转发。边缘节点配置唯一 BFR-ID（如 1~256），用 Bit String 表示集合。

优点：适合大规模组播与 SDN（叶子加入只到头节点，控制器收集目的后下发）。BIERv6 继承优点并利用 IPv6 编程，便于在 SRv6 网络中组播转发。

BIFT（Bit Index Forwarding Table）：经 IGP（如 IS-IS）泛洪 BFR-ID 与前缀映射后建立邻居表。

BIERv6 优点摘要：协议简化（IPv6 承载 MVPN/公网组播，免 MPLS 标签管理）；部署运维简单（只部署头尾节点，中间不感知业务变化）；可靠性高（基于单播路由，无 SPT 切换等复杂事务，故障后随底层路由刷新 BIFT）。

## 企业 IPv6 演进总体策略

企业业务大致：互联网业务、DMZ 对外服务、自建业务系统；前两者依赖外部，长期 IPv4/IPv6 共存。

域划分：

- **数据中心**：对外公众服务（DMZ）与内部应用；演进涉及互联网出口、DMZ、内部服务网络。
- **广域网**：自建广域、运营商 MPLS L2/L3 VPN、Internet 等；重点考虑广域专网升级。
- **园区**：总部/分支办公园区、生产园区（终端生命周期长，长期双栈与互通）。

**整体迁移原则**：数据中心先行 → 广域网 → 园区按需。

| 阶段 | 要点 |
|------|------|
| 一 | DC 公共服务与测试区双栈；广域 Underlay IPv4、Overlay 双栈；园区试点双栈 |
| 二 | DC 内部应用逐步双栈；办公园区逐步双栈，生产园区双栈 |
| 三 | DC 内部应用全面 IPv6 单栈；广域 IPv6 Only |

### 数据中心改造要点

互联网接入区：NAT64 / IVI / 双栈；**推荐双栈**。NAT64 会话表受限，仅适合初期快速开通；IVI 地址结构受限，不推荐大规模。

内网资源池：双栈；初期可用 VXLAN Underlay IPv4 + Overlay 双栈；新建或改造可向 Underlay IPv6 + Overlay 双栈演进至 IPv6 Only。

架构：Underlay（推荐 Spine-Leaf）+ Overlay（VXLAN Fabric）。对外服务优先完成 DMZ 双栈升级。

互联网区演进方案：

1. 出口 NAT64（业务暂不改造时临时提供双栈服务）
2. 互联网接入区与 DMZ 双栈改造（利旧）
3. 新建 IPv6 互联网接入区与 DMZ（对现网 IPv4 零影响）

出口路由：单出口优选静态；多地多出口优选 BGP，用属性控选路与负载。资源池/服务器通常新建 IPv6，避免升级事故。

### 广域网 IPv6 演进

广域网对业务主要起承载管道作用；业界共识是很长时间内 IPv4 与 IPv6 共存。路径选择：

| 方案 | 要点 |
|------|------|
| 双栈 | 所有三层设备启用双栈且双栈路由可达；维护两套协议栈，复杂性增加 |
| 6VPE | 存量已部署 MPLS 时推荐；边缘使能交换 VPNv6，中间节点可仍 IPv4 单栈（MPLS）；P 节点无需改造，对维护冲击小 |
| SRv6 / IPv6+ | 新建网优选；IPv6 Only 一步到位；具备业务隔离；扩展性、应用结合与编程能力强 |

#### 新建网演进步骤

**Step1 准备**

- 向地址管理单位或运营商申请 IPv6 地址
- 现网评估：基础设施、安全、业务支撑、应用
- 集成验证并输出可行性报告
- 制定 IPv6+ 建网规范与演进方案，支持平滑到 IPv6 Only

**Step2 建设及业务割接**

- 建设：部署 SRv6、网络切片、随流检测、SDN 等
- 安全：安全设备支持 IPv6 防护，与网络设备联动
- 测试验收：满足 SLA、安全、运维要求
- 按业务逐步从传统广域迁到新建 IPv6 广域

**Step3 观察后拆老网**

- 设置观察期；运行无重大问题后再拆除老网

#### 存量网演进步骤

**Step1**：同新建网准备。

**Step2 边缘改造，使能基础 IPv6+**

- 优先升级云、互联网出口、园区出口 PE
- 新设备同时部署 SRv6 与传统 IP/MPLS：新旧之间 IP/MPLS，新设备之间 SRv6；部署控制器统一管控
- 同步升级相关安全设备；选择部分普通业务经 SRv6 验证基础能力

**Step3**

- 升级核心，全网支持 IPv6+
- 部署切片、随流检测、SDN、网安联动等高阶能力
- 业务迁移；观察后删除 IP/MPLS 冗余配置

#### Overlay 业务部署建议

- **二层**：SRv6 EVPN（点到点 / 点到多点）；相对 VSI/PW 更简洁、带宽利用与收敛更好
- **三层 IPv4**：可用 SRv6 L3VPN 或 SRv6 EVPN L3VPN，**建议 EVPN L3VPN**
- **三层 IPv6**：可用 SRv6 L3VPNv6 或 SRv6 EVPN L3VPNv6，**建议 EVPN L3VPNv6**

IGP 域内需发布 Loopback（管理/BGP 邻居）与 Locator（指导 SRv6 隧道转发）。跨 AS 可用 **BGP EPE（Egress Peer Engineering）** 为 Peer 分配 SRv6 SID。

#### EVPN L3VPNv6 over SRv6 BE 关键步骤

1. PE 配置 SRv6 与 IPv6 VPN 实例；中间节点需支持 IPv6。
2. PE2 发布 SRv6 Locator 路由给 PE1。
3. CE↔PE 交换路由（静态 / OSPFv3 / IS-IS for IPv6 / BGP4+）；PE2 将私网 IPv6 路由转为 IP Prefix Route 形式的 EVPN 路由。
4. PE2 经 BGP EVPN 邻居发布给 PE1，携带 RT 与 SRv6 VPN SID。
5. PE1 在下一跳可达且通过入口策略时做私网交叉、迭代 SRv6 路径、优选，写入 VPN 实例 IPv6 表并关联 VPN SID。
6. PE1 再向 CE1 发布 VPN 路由（方式同对侧）。

路由发布细化示例：

1. PE2 配置 Locator，生成 End SID。
2. 经 IGP 将 Locator 网段（如 `2002:1::/64`）发布给 PE1。
3. 在 Locator 范围内配置 VPN 实例 End.DT6 SID（如 `2002:1::D100`），写入 Local SID 表。
4. PE2 收 CE2 私网路由后转成 EVPN IP Prefix Route，经 BGP EVPN 发给 PE1，携带该 End.DT6 SID。
5. PE1 交叉到对应 VPN 实例 IPv6 表，再向 CE1 发布普通 IPv6 路由。

### 园区 IPv6 演进

园区主要涉及大中型办公、小型分支及工业生产园区；互访场景含内部办公、访问互联网、生产系统互访。

- **大中型传统园区**：原 IPv4 架构与配置保持，新增 IPv6 与支撑系统。
- **大中型虚拟化园区**：可采用 VXLAN Underlay IPv4 + Overlay 双栈。
- **小型办公园区**：内部双栈后，回传总部需经广域双栈通道：
  - 单 Internet：双栈 over IPsec6 / IPsec4 / GRE over IPsec6/4
  - 仅 MPLS VPN：专线升级双栈，出口用 BGP/IGP/静态对接
  - MPLS VPN + Internet：可用 SD-WAN；WAN 不升级时 IPv6 可先 IPv4 GRE 再经 SD-WAN

#### 传统园区第一阶段（与 SDN 并行）

思路：新建支持 SDN 与 IPv6 虚拟化的核心，接园区出口；存量网络逐楼（汇聚+接入）改造接新核心，由 SDN 控制器自动部署。

1. 在数据中心部署 SDN 控制器  
2. 园区核心机房新建核心，连接关系与存量核心一致，并建临时链路用于割接  
3. 在核心及互联设备上部署未来业务互通所需基础路由  
4. 逐楼 IPv6+SDN 改造：楼栋汇聚接入新核心，业务由 SDN 下发，并添加该楼路由  
5. 全部楼改造完成后整网完成演进  

注意：新楼 IPv6 与老楼 IPv4 互通需经数据中心 NAT64。优势：操作简单、节奏可控、对现网影响小。

#### 大中型传统园区内/外网对接

- 内网：三层升级双栈；IGP 常用 OSPFv3，区域与原 OSPFv2 一致。与广域可用静态缺省、IGP 或 BGP，策略宜延续 IPv4 方案。
- 外网：独立申请的 PI 地址时，单出口可用外部静态 + 内部 IGP 缺省；多出口可用外部 BGP + 内部 IGP 缺省，实现选路与负载分担。

GUA = Global Unicast Address；PI = 地区互联网注册管理机构分配给企业的 IPv6 地址。

#### 大中型虚拟化园区（集中式网关）

地址分配：

- **DHCPv6**：集中服务器；在 VXLAN 集中式 IPv6 网关 VBDIF 上使能 DHCPv6 Relay。安卓终端不支持 DHCPv6，须用 SLAAC。
- **SLAAC**：在集中式网关配置 RA（前缀、DNS 等）向终端推送。

接入认证：Edge 接入双栈用户时，需单次认证联动整栈策略，避免 IPv4/IPv6 各认证一次。应支持 802.1x / Portal / MAC；认证点、策略执行点位置与 IPv4 一致。可用 `capwap ipv6 enable` 使能 CAPWAP 隧道 IPv6。

### 配套系统改造

**应用系统**：关键在地址相关模块。

- 全面部署支持 IPv6 的 DNS，增加 AAAA；业务用域名而非裸 IP，并校验 AAAA 解析
- 排查直接使用 IP 之处，确保 IP 只作地址，不作用户 ID / 业务关键属性
- 排查 Socket：转向 IPv4&IPv6 兼容接口；校验地址合法性代码是否需改

**网管系统**：可不强制系统内部通信改 IPv6，但需：识别管理各类 IPv6 地址；DNS 解析监控；对 IPv6/双栈设备做性能、资源、故障采集与历史关联；可通过 IPv4 SNMP 访问设备 IPv6 MIB。

**服务器 OS 示例**：Fedora 13、RHEL 6、Ubuntu 12.04、Solaris 10、SLES 11 等默认装 IPv6；Windows 2003 需手工安装，2008 及以后默认安装。
