# SD-WAN可靠性安全与CloudWAN解决方案

## 1. SD-WAN 站点可靠性设计（续）

### RR 站点可靠性：设备冗余

一个 CPE 设备最多支持连接到两个 RR 站点（4 台 RR 设备）。三种部署方式可靠性逐步增强：

1. **单站点双设备**
2. **双站点单设备**
3. **双站点双设备**

### RR 站点可靠性：链路冗余

Edge 站点应双上行到 RR 站点。

- **单链路**：可靠性低；单台 RR 故障时，部分分支站点无法连接到 RR，造成业务中断。
- **多链路（RR 侧）**：RR 设备侧部署多链路，实现 CPE 与 RR 连接可靠性。
- **多链路（分支侧）**：分支站点侧部署多链路，实现 CPE 与 RR 连接可靠性。

### IWG 可靠性设计

分支站点指定连接主/备 IWG，分别建立 IWG Active 隧道，自动编排 BGP 路由策略，控制分支发布来自传统网络的 BGP 路由优先级。主 IWG 的优先级高于备 IWG。

## 2. SD-WAN 控制器可靠性设计

控制器是 SD-WAN 解决方案的核心部件，所有业务均由控制器编排，因此控制器可靠性将直接影响网络业务。控制器可靠性设计一般可分为：控制器部署可靠性设计、控制器组网可靠性设计。

### 控制器站内部署：分布式集群

控制器采用分布式集群架构部署，提供高可靠性和负载均衡能力。当集群中节点故障时，其他节点接管业务，对业务无影响。

- **北向负载分担**：外部请求分担到所有集群成员，而不是集中在一个节点处理，充分利用集群能力，提升可靠性。
- **南向负载分担**：基于各控制器节点负载情况，为网络设备动态分配控制器节点。

| 集群 | 功能描述 |
| --- | --- |
| 业务处理集群 | 提供业务处理能力，如 CPE 管理、Overlay 网络配置下发、流量策略配置 |
| 数据处理集群 | 主要提供 CPE 性能数据存储、数据聚合等功能 |
| Nginx 集群 | 高性能 HTTP 代理服务器，负责并发连接请求转发，主要用于北向流量 L4~L7 层负载分担 |
| LVS | Linux Virtual Server（负载均衡组件），主要用于南北向流量 L1~L4 层负载分担 |

### 控制器容灾部署（异地）

- 异地容灾系统由两套 iMaster NCE 组成，分别部署在两个异地站点上。
- 异地容灾支持两个集群间容灾备份；主集群与容灾备集群的节点数必须保持一致。
- 主备集群同时运行，只有主集群可对外提供正常服务，备集群不对外提供服务；主集群运行中的数据会实时同步到备集群，确保数据一致性。
- 控制器北向、南向采用统一域名方案，租户和设备通过统一域名访问主集群；主备倒换后，域名映射到新的主控制器集群。
- 异地容灾主备倒换采用手动方案，切换时间可控制在 10 分钟内。对于控制器集群内部部件级故障，依旧依靠集群、容错等可靠性保障。
- 异地容灾网络要求：时延 < 20 ms；带宽 ≥ 125 MB（原文口径）。

### 单控制器组网可靠性

为了保证 SD-WAN 管理通道可靠性，一般需要部署双网关双链路，保障 CPE/RR 能与控制器通信。

- **公网/专网混接组网**：控制器部署于 DC 内部；控制器可配置多个不同南向地址用于公网和专线；专线网络需将控制器所在网段发送至专网；EDGE 可通过公网和专线注册到控制器；公网出口设备需部署 1:1 静态 NAT（总部公网出口同样需要）。
- **单一类型网络接入**：类似要求，专线需发布控制器网段；公网需 1:1 静态 NAT，且使用相同公网地址。

### 主备控制器组网可靠性

主要通过控制路由条目优先级指导 CPE 与主备控制器通信。

- 主备控制器使用相同北向 IP，南向 IP 可不同；公网场景下需配置 NAT。
- 在纯专线网络中，需要将控制器南向/北向 IP 通过 EBGP 发布到专线网络，并使用路由策略使主控制器路由被优选。
- 在纯公网网络中，南向/北向 IP 需部署 1:1 静态 NAT，两台出口网关 NAT 配置需一致；将 NAT 地址相关路由通过 EBGP 发布到公网，并用路由策略使主数据中心相关路由被优选。

## 3. SD-WAN 安全设计

安全从整体上分为两个层面：

1. **系统安全**：满足 SD-WAN 解决方案本身的安全需求，保证系统能够安全可靠地运转。
2. **业务安全**：满足所承载业务的安全需求，根据企业用户实际需求灵活选择防护措施。

### 系统安全：组件间通信安全

各组件之间的通信连接分为管理通道、控制通道和数据通道：

- EDGE/RR 与 iMaster 之间：管理通道。
- EDGE 与 RR 之间：控制通道。
- EDGE 和 EDGE 之间：数据通道。

组件之间使用安全通信协议建立上述通道，保证通信数据安全。管理通道与控制通道的安全机制默认开启，无需配置；数据通道的安全机制需要基于情况设计。常见做法：SSH 保障管理通道；IPsec 保障控制通道与转发面；数据通道使用 GRE 或 GRE over IPsec。

### 系统安全：数据通道安全

数据通道中的连接是 EDGE 之间建立的 Overlay 隧道，通过 IPsec 协议保证传输过程中的机密性和完整性。

- 基于 Internet 网络建立数据通道时必须部署 IPsec。
- 基于 MPLS 或专网建立数据通道时可根据实际情况部署 IPsec。

### 系统安全：管理员认证和授权

系统对管理员进行认证时，支持本地认证和远程认证，通过严格身份认证确保合法管理员才能登录。

租户管理员登录 iMaster NCE-WAN / iMaster NCE-Campus 时，支持双因子认证（账号/密码 + 短信认证码）：

- **本地认证**：iMaster NCE 对租户管理员进行认证。
- **LDAP 服务器认证**：对接通用 LDAP 或 Windows AD；由 LDAP 服务器认证。

设备管理员通过命令行登录 EDGE 时：

- **本地认证**：租户管理员可在 iMaster NCE 上统一设置设备管理员密码下发给 EDGE，由 EDGE 认证。
- **TACACS 认证**：EDGE 通过 Underlay 对接 TACACS 服务器进行认证。

### 系统安全：EDGE 安全

EDGE 自身要具备安全的系统架构，并支持多种安全防护措施。控制平面、管理平面和转发平面应具备多种安全防御能力，包括但不限于：

- **物理安全**：关闭业务不使用的端口、串口和服务，防止从这些端口和服务遭到攻击。
- **数据安全**：对业务数据、用户名、密码等敏感信息加密保存；控制数据访问权限。
- **认证鉴权**：系统权限控制和账号权限管理；账号/密码保护、密码复杂度检查以及密码防暴力破解等。
- **防攻击**：防范 IP 泛洪、ICMP 泛洪、畸形报文、分片报文等攻击。
- **安全审计**：完备日志记录，配置操作与异常状态可追溯。

### 业务安全：访问互联网安全

通过 EDGE 内置安全能力提供业务安全保证，包括 ACL 过滤、防火墙、IPS 以及 URL 过滤。

- **集中上网场景**：所有分支上网流量绕行至总部后访问 Internet；在总部 EDGE 上启用防火墙，隔离内外部网络。
- **本地上网场景**：分支和总部上网流量从本地 EDGE 直接访问 Internet；在分支和总部 EDGE 上启用防火墙。

### 业务安全：VAS 高级安全

集中上网场景下，集中上网站点采用 WAN 侧出接口接入 Internet 时，可以旁挂部署物理防火墙（FW），提供基于 VAS（Value-Added Service，增值业务）的高级安全防护。部署后，集中上网流量绕行至总部 EDGE LAN 侧物理防火墙，处理后经 Underlay 访问 Internet。

### 业务安全：第三方云安全

支持对接第三方云安全网关（如 Zscaler、Forcepoint），将企业访问公有云、SaaS 的流量发送至第三方云安全网关，进行接入控制、威胁防御、数据保护等。为提高可靠性，第三方云安全网关通常提供两个接入点与 EDGE 建立隧道；EDGE 使用 GRE 隧道对接。

- **单网关场景**：一台 EDGE 与两个接入点建立主备两条 GRE 隧道。
- **双网关场景**：两台 EDGE 与两个接入点建立主备四条 GRE 隧道。

## SD-WAN 可靠性与安全小结

- **站点可靠性**：Hub / RR / IWG 站点可靠性设计。
- **控制器可靠性**：控制器部署可靠性、控制器网络可靠性。
- **安全设计**：系统安全设计、业务安全设计。

## 4. CloudWAN 解决方案概述

### 前言与目标

广域网（Wide Area Network，WAN）是连接不同地区的局域网或城域网的计算机网络，通过广域网可实现相当大范围内的信息与网络资源共享。企业广域 IP 承载网络用于实现企业内跨地域互联互通的广域骨干网络；政府、金融、教育、电力等行业广泛使用广域 IP 承载网络实现站点、云之间的连接，助力数字化。

### 企业广域网络简介

企业广域网络用于实现企业内跨地域的互联互通，连接企业总部与分支、企业与云，也实现云之间的互联互通。按使用对象分类：自建自用、自建他用。

企业广域网络 = 企业网络出口 + 企业广域 IP 承载网络（企业自建或运营商建设）。

Internet 接入相关：

- **互联网专线**：以太专线 / xPON 专线 / xDSL 专线；接入受地理位置限制；适用于基于 Internet 加密隧道的企业间通信。
- **拨号连接**：低带宽、低资费；接入不受地理位置限制；适用于个人用户。
- **BGP**：适用于数据中心互联网出口。

由于技术发展，历史上的广域网技术例如 T1/E1、PSTN、ATM、Frame Relay 等不在此展开。

### 典型逻辑架构

企业广域 IP 承载网络典型架构为接入层、汇聚层和核心层：

- **接入层（CE-PE）**：多地多数据中心接入、各地分支机构接入、各地外联业务接入。
- **汇聚层（PE-P）**：基于物理地域，将不同业务分类汇聚接入核心层。
- **核心层（P）**：一般采用 Full-mesh + 双平面架构；实现不同区域之间的流量转发，提供稳定、可靠、服务有保障的连接。

### 典型承载技术

| 方式 | 说明 |
| --- | --- |
| IP 承载 | 使用 IP 地址区分业务，所有业务混杂承载在一张 IP 网络上；适合中小企业，或无明确业务隔离/差异化 SLA/流量工程需求的场景 |
| MPLS 承载 | 将数据 MPLS 封装，基于标签转发；使用 VPN 区分业务，支持业务隔离和 SLA 保障；控制面常用 MP-BGP，数据面使用 MPLS；适合大型企业 |

### 迈向 IPv6+ 与 SRv6

企业广域 IP 承载网从 All IP / IPv4 / MPLS 向 IPv6+（协议创新 + AI）演进：尽力而为与人工运维 → 静态策略与半自动运维 → 万物互联、灵活连接、智能运维。

主流承载技术为 VPN 技术，控制面和转发面不断演进，广域承载网不断向 Segment Routing、向 IPv6 演进：MPLS → SR-MPLS → SRv6。控制面从 RSVP-TE / LDP / BGP-LU 等逐步简化为 IGP + SR Extension + BGP for Service；转发面从 MPLS Labels 演进到 IPv6 Header + SRH。

### 数字化转型两大变化与三大挑战

两大变化：

1. **百万企业上云**：本地处理 → 业务上云；私有云 → 混合云 / 多云。
2. **生产网络 IP 化**：多张 TDM 专网 → 一张 IP 综合承载（电力/交通等提出 IP 化转型趋势；时延、带宽、任意接入等要求提升）。

三大挑战：

1. 联接规模 ×100：如何让网络像云一样敏捷？（业务部署时长从数十天到 <1 小时）
2. 承载生产业务：IP 是否能提供确定性体验？（如电力继保单向时延 10 ms / 200 μs 量级要求；列车控制故障切换 50 ms 等）
3. 运维更简单、网络更可靠：7×24 在线等诉求。

### CloudWAN 3.0 能力方向

CloudWAN 3.0：引领广域网络进入智能云网时代（管控析平台 + 面向云时代智能全业务路由器）。

要点：

- **一跳入云，云网灵活联接**：SRv6 业务分钟级开通，业务敏捷上云。
- **一纤多用，确定性体验**：层次化切片；专利指纹切片技术，极简部署。
- **一键导航，云网一体调度**：SDN + 智能云图算法，云网资源利用率高。
- **一网通达，网络数字化**：逐跳检测技术，全网状态实时可视，分钟级排障。
- **一体安全**：乾坤安全云服务等，主动识别网络安全威胁。
- **IPv6+** 构建数字化基础设施底座。

产品形态示例：iMaster NCE（管 + 控 + 析）与 NetEngine 9000 / 8000、ME60、NetEngine40E 等路由器。

#### iMaster NCE-IP

- 网元管理：拓扑、告警、配置、存量。
- 业务管理：隧道管理、VPN 业务管理。
- 集中算路：多维约束的集中算路；逻辑拓扑（Cost、时延、带宽）；网络调优。
- 分析：性能、流量、质量展示分析；流量/故障/异常预测。

#### 关键技术说明

- **SRv6 一跳入云**：过去烟囱式专网相互独立、跨 AS 配置复杂；SRv6 只需在隧道两端部署即可实现业务一跳入云；CloudWAN 将多个协议精简为 SRv6 + IGP/BGP，结合 SDN 控制器实现分钟级自动化布放。
- **层次化切片**：使能生产网 IP 化，保障确定性 SLA；一张 IP 承载网上多切片实现生产与办公硬隔离，对关键业务带宽 100% 保障。
- **iFIT**：融合 RFC 8321 染色技术 + 随流检测，直接对业务报文测量，配合 Telemetry 秒级采集和 iMaster NCE 统一管控、计算和可视化，实现 SLA 实时可视、主动监控、故障快速定界定位。
- **智能云图算法**：结合云、网双因子；根据云不同负载做负载分担，基于 SRv6 和 SDN 智能调度业务访问到最合适的云，并按网因子调优流量。

#### iMaster NCE-IP 架构要点

整体架构包括公共业务、管理控制与分析、场景化 APP 以及南北向开放等模块；支持分布式虚拟化部署。跨厂家管理可由驱动包、NCE-Super 与 AOC（Agile Open Container）等配合；网络变更可由 AOC 原子 API + ISPA（Intelligent Service Process Automation）做意图编排。

### CloudWAN 典型应用场景

1. **某省电子政务外网**：云网一体，一网入多云；SDN + SRv6 实现跨域自动发放（周级 → 小时级），云网协同提升体验与系统上云率。
2. **某企业广域网流量智能调优**：总部—分支流量增长与专线预算不匹配、平均利用率偏低；夜间大带宽同步难按最短路径实现均衡；基于时间段、流量门限、突发等方式自动/手动触发调优，SRv6 策略自动配置替代人工逐跳策略路由。
3. **某电力公司网络分片**：基于时分复用的灵活以太等技术做物理网络分片，隔离不同业务并保证 SLA；控制器统一部署网络资源，承载电力业务（办公、视频监控、继电保护、调度电话、WAMS 等），支撑平滑升级到 100G/200G 以及演进到 SRv6 + EVPN。

## 5. 企业广域承载网技术原理（续篇开头）

### 前言与目标

广域 IP 承载网络是一种跨地域的数据通信网络，通常覆盖一个国家或地区，用于实现跨地域多个局域网或分支网络的互联互通。本课程以拥有“两地三中心”和各地分支机构的大型企业为例，介绍企业广域承载网典型架构、承载技术、VPN 业务、网络流量优化、SLA、可靠性、网络管理与分析等概念和技术原理及应用。

### 广域承载网络架构

对于同城数据中心的 P 设备之间，使用波分或裸光纤直接互联，链路带宽可达到 10G；对于异地数据中心，从成本考虑可以通过运营商 MSTP 链路互联。

分层架构：接入层（CE-PE）、汇聚层（PE-P）、核心层（P，Full-mesh + 双平面）。

技术应用：PE 之间构建业务隧道用于 VPN 业务迭代，例如 MPLS LDP、MPLS TE、SR-MPLS BE/TE、SRv6 BE/TE；CE 接入 PE 使用 VPN 隔离业务（L2VPN 二层互访、L3VPN 三层互访）；数据转发使用 MPLS 或 IPv6。

### 广域承载网络基础：MPLS / SR-MPLS / SRv6

#### MPLS 简介

MPLS 位于 TCP/IP 协议栈中数据链路层和网络层之间，可向所有网络层提供服务。通过在数据链路层和网络层之间增加额外 MPLS 头部，基于 MPLS 头部实现数据快速转发。

术语：

- **MPLS Domain**：一系列连续运行 MPLS 的网络设备构成 MPLS 域。
- **LSR**（Label Switching Router）：支持 MPLS 的路由器（也可指支持 MPLS 的交换机等）。位于边缘连接其他网络的称为 LER（Label Edge Router），区域内部称为 Core LSR。
- **LSP**（Label Switched Path）：IP 包在 MPLS 网络中经过的路径，单向；起始节点 Ingress，中间 Transit，末节点 Egress。

LSP 可通过静态配置和动态建立生成。动态建立常见协议：

- **LDP**：基于路由表从下游向上游分配标签，建立普通 LSP；通常是 IGP 最短路径，不考虑带宽等因素，也缺少对隧道保护、流量优化的考虑。配置维护相对简单，广泛应用于 BGP/MPLS IP VPN 场景，但无法进行隧道转发路径规划。
- **RSVP-TE**：通过端到端隧道资源申请和预留建立 CR-LSP（Constraint-based Routed Label Switched Path），基于带宽或路径约束建立。

#### MPLS TE

MPLS TE 是 MPLS 与流量工程的结合，支持对 MPLS VPN 业务进行路径规划、流量调优和故障保护。相比 MPLS LDP，增强了对 VPN 流量的控制和保护。

在 MPLS TE 中经常把多条 LSP 联合起来使用，并与一个虚拟隧道接口关联，这样的一组 LSP 隧道称为 MPLS TE 隧道。能够保证 SLA，但配置更复杂，也需要人工规划。

配置示例：

```cli
[R1] interface Tunnel1
[R1-Tunnel1] ip address ...
[R1-Tunnel1] tunnel-protocol mpls te
[R1-Tunnel1] destination R4
[R1-Tunnel1] mpls te bandwidth 50M
```

#### LDP 与 RSVP-TE 的问题

- LDP 本身并无算路能力，需依赖 IGP；控制面需要 IGP 及 LDP，设备间大量消息维持邻居与路径状态；若 LDP 与 IGP 未同步，可能出现数据转发问题。
- RSVP-TE 配置复杂，不支持负载分担；为实现 TE，设备间需发送大量 RSVP 报文维持邻居与路径状态；本质上是分布式架构，每台设备只知道自己的状态。

#### Segment Routing MPLS

段路由（Segment Routing，SR）基于源路由理念：在源节点选择一条路径并在报文中压入有序标签栈，其他节点按标签栈转发。特点：

- 通过对现有协议（例如 IGP）扩展，使网络更好平滑演进。
- 同时支持控制器集中控制与转发器分布控制。
- 采用源路由技术，提供网络和上层应用快速交互能力。

SR-MPLS 隧道两种实现：

- **SR-MPLS BE**：转发路径由 IGP 最短路径算法生成，LSP 只有一层标签（目的节点）；生产环境一般作为 SR-MPLS TE 的容灾方案（如控制器故障导致下发隧道失效时，可依靠 IGP 生成转发隧道）。
- **SR-MPLS TE**：基于 TE 约束属性利用 SR 创建隧道，一般有多层标签以实现路径控制，支持主备多路径；一般与控制器结合，由控制器全局计算路径后在头节点下发标签栈。

基于 MPLS 和 IPv6 两种转发技术，SR Policy 可分为 SR-MPLS Policy 和 SRv6 Policy。

#### SRv6

SRv6（Segment Routing IPv6）基于源路由理念在 IPv6 网络上转发数据包。与 SR-MPLS 都遵循 Segment Routing 架构，主要区别在于数据平面指令：SRv6 指令为 IPv6 地址，SR-MPLS 指令为 MPLS 标签。

SRv6 在 IPv6 报文中插入路由扩展头 SRH（Segment Routing Header），其中包含显式 IPv6 地址栈；转发过程中不断更新目的地址并偏移地址栈完成逐跳转发。

小结：企业广域承载技术选择可简单分为 MPLS 网络（MPLS LDP、MPLS TE、SR-MPLS）和 IPv6 网络（SRv6）。

### VPN 业务（概要）

- **L2VPN**：包括 VPWS（点到点）和 VPLS（点到多点）；传统 L2VPN 没有控制平面不传递 MAC，使用 BGP 作为信令建立 VC。
- **VPDN**：在公共网络上构建虚拟专用网络，广泛使用 L2TP；严格来说 L2TP 也属二层 VPN，但因拨号方式等差异分类为 VPDN。
- **L3VPN / VPRN**：包括基于 RFC2547 的 BGP/MPLS IP VPN、以 IPsec 或 GRE 作为隧道的 IPsec VPN 和 GRE VPN 等。

传统广域 L2VPN 基于 MPLS：AC（CE-PE 接入电路）、VC（PE 间逻辑连接）、Tunnel（透明传送业务数据，如 MPLS LDP/TE）。VPLS/VPWS 广泛用于运营商为企业提供 MPLS L2 专线。

传统广域 L3VPN 一般特指 BGP/MPLS L3VPN：控制平面用 MP-BGP 发布 VPN 路由，数据平面用 MPLS LSP 转发。

EVPN 最初是基于 BGP 扩展的 L2VPN 技术，协议扩展后也能支持 L3VPN，可作为广域 VPN 控制平面，与 EVPN VPLS、EVPN VPWS、EVPN L3VPN 等结合；并可与 MPLS LDP、MPLS TE、SR-MPLS、SRv6 等隧道结合。华为设备上 EVPN 的 L2/L3 业务使用一个地址族示例：

```cli
[Router] bgp 100
[Router-bgp] l2vpn-family evpn
```

当企业广域承载网同时部署多种隧道技术时，VPN 选择迭代隧道需要遵循隧道策略。

### 隧道管理（要点）

- GRE 可应用于 L2VPN/L3VPN；当 P 仅提供纯 IP、不具备 MPLS，而 PE 具备 MPLS 时，可用 GRE 替代 LSP。
- SR-MPLS Policy / SRv6 Policy 分别为对应隧道形态。
- 隧道管理配置有配置隧道策略和配置隧道策略选择器两种方式；隧道策略选择器主要适用跨域 VPN 场景。
- CR-LSP 类型隧道包含 RSVP-TE 与 SR-MPLS TE，系统会根据隧道 Up 时间确认优先级等细节，参见产品文档。
- SR Policy 引流方式有 Binding SID、Color、DSCP 等。

### 网络流量优化（开头）

基于固定带宽选路可能导致最短路径拥塞而其他链路空闲；基于固定顺序建立隧道可能导致后续隧道因带宽不足失败。全局计算可最优调整隧道路径。

网络流量优化即针对网络拥塞情况进行全局分析，按合理优化策略（保障关键业务 SLA）得到计算结果并应用到网络。三个阶段：

1. **网络信息采集**：拓扑、带宽、链路时延、网络流量等。
2. **网络流量调优计算**：如路径 COST 最优、时延最小、链路带宽利用率最大化等。
3. **调优结果下发**：NETCONF、PCEP、BGP SR Policy 等。

不同方案采集协议可能不同：例如华为 MPLS 网络使用 PCEP 采集 TE 隧道信息，SRv6 网络使用 BGP SR Policy 采集 TE 隧道信息。

路径偏好示例：带宽均衡路径（满足约束且 COST 相同中剩余带宽更多者）；最优可用度路径（满足约束中可用度最优者）。

调优结果下发方式：

1. **NETCONF/YANG**：将计算结果作为配置下发；YANG 模型标准化，厂家兼容性好。
2. **PCEP**：下发消息创建或更新 LSP；标准未定义统一隧道模型时，厂家私有实现可能无法互通。
3. **BGP SR Policy**：使用 BGP 扩展下发隧道；RFC 统一定义隧道模型和数据报文结构，厂家互通更容易实现。
