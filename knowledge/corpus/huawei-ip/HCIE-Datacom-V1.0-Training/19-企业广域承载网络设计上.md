# 企业广域承载网络设计（上）

本篇承接 SRv6 章节中基于 iMaster NCE-IP 的部署收尾，并转入企业广域承载网络设计。

---

## 计算 SRv6 Policy 并部署

在满足约束的情况下，控制器可提供的算路结果包括：

- **最小开销**：满足约束的所有路径中 cost 最小。
- **最小时延**：满足约束的所有路径中时延最小。
- **带宽均衡**：满足约束且 cost 相同的路径中，剩余带宽更多者。

创建 SRv6 Policy 时需指定每条隧道对应的 **Color**。

可选约束条件：

- **带宽约束**：业务带宽不超过途经链路剩余带宽。
- **PIR 约束**：峰值带宽不超过途经链路的 BC0 带宽。
- **Delay limit**：路径时延不超过配置值。
- **Hop limit**：经过链路数目不超过配置值。
- **亲和属性约束**：规划业务允许/不允许走哪类链路。

---

## BGP IPv6 SR Policy 部署

BGP IPv6 SR Policy 主要用于下发 SRv6 Policy 信息。iMaster NCE-IP 至少需要与**隧道源节点**建立 BGP IPv6 SR Policy 邻居。

| 方案 | 说明 | 推荐 |
|------|------|------|
| 方案一 | 控制器与所有 PE 建立邻居 | — |
| 方案二 | 控制器与 RR 建立邻居，其余设备与 RR 建立邻居 | **推荐**（减少邻居数） |

### 建立邻居

```cli
[P1] bgp 65001
[P1-bgp] peer 2000::102 as-number 65001
[P1-bgp] peer 2000::102 connect-interface LoopBack0
[P1-bgp] ipv6-family sr-policy
[P1-bgp-af-sr-policy] peer 2000::102 enable
```

```cli
[~P1] display bgp sr-policy ipv6 peer

BGP local router ID : 1.0.0.5
Local AS number : 65001
Total number of peers : 7
Peers in established state : 5

Peer        V      AS  MsgRcvd MsgSent OutQ Up/Down    State    PrefRcv
2000::102   4   65001    11286   11195     0 0160h44m Established 2
```

BGP IPv6 SR Policy 邻居可使用 IPv4 或 IPv6；本课程主要使用 IPv6。

---

## 通过 SRv6 Policy Group 创建隧道

**SRv6 Policy Group**：快速建立共享相同 SLA 要求的一组隧道。

适用：在创建业务前批量创建多条 SRv6 Policy。隧道类型可选：

- **Any To Any**：网元间全联接。
- **Hub-Spoke**：网元分 Hub / Spoke，Spoke 间通信经 Hub。

在华为云广域网络解决方案中，Policy Group 用于隧道规划：先算好路径，有业务需求时按需下发。

---

## 通过 SRv6 Policy 承载 VPN 业务

企业网常见 VPN 类型：

- **L2VPN**：客户 IP 在同一网段。
- **L3VPN**：客户 IP 在不同网段。
- **EVPN**：融合 L2VPN 与 L3VPN。

**隧道策略（Tunnel Policy）** 决定选择何种隧道，有两种方式：

1. **隧道类型优先级**：按隧道类型优先级及参与负载分担的隧道条数迭代（首选）。
2. **隧道绑定**：目的地址与某条隧道绑定，VPN 到该目的的流量只走该隧道。

VPN 业务从隧道策略中选择 Up 状态的隧道类型，再在同类型隧道中按 Color / DSCP / Policy Group 等选择转发路径。

# 企业广域承载网络

## 前言与目标

企业广域承载网络（企业广域骨干网络）用于实现企业分支之间、分支与云之间、云和云之间的互联互通。

过去广域网只需转发流量；随着业务对网络依赖增强，对 SLA 保障提出要求。新技术在满足业务的同时，也使运维与设计复杂化。本课程基于**华为云广域网络解决方案**梳理相关技术与设计思路。

- 描述企业广域承载网络面临的挑战

- 描述基础设计、隧道与 VPN、SLA 与可靠性、优化与运维设计思路

## 1. 企业广域承载网络现状与挑战

### 广域承载网介绍

按层次可分为 IP 承载网与传输承载网。多数企业无法自建传输（铺光纤需资质），一般租用运营商传输线路，在其上自建 IP 承载网——即企业广域承载网（企业骨干网 / 核心网）。

承载业务包括：数据中心之间同步、分支与总部之间语音等。本课程所说广域承载网主要指**广域 IP 承载网**。

### 架构

总体可分为接入层、汇聚层与核心层：

- **接入层**：接入不同分支站点。
- **汇聚层**：按业务类型或地理位置分类汇聚，接入核心骨干。
- **核心层**：顶层互联，提供业务高速互访。

### 建设诉求

- **多网融合**：一张物理网承载生产、办公等；用 BGP 策略按业务属性分流到不同路径。
- **多业务灵活承载**：多业务上云与多网融合后，资源利用率低、流量不均；用 Segment Routing 灵活规划路径。
- **高可靠**：网络可靠性（架构、稳定性）与业务可靠性（带宽、时延、丢包等）。
- **简便运维**：拓扑/事件/配置/业务发放/链路质量统一管理；流量入隧道、带宽、路径、节点流量动态控制；应用流可视、可分析、可预测。

### 面临挑战

- **多业务隔离**：物理隔离变为同网承载后，部分企业 VPN 即可，部分需硬管道隔离。
- **网络资源与流量路径规划**：传统 MPLS-TE 配置复杂、算路有缺陷，难有效解决多业务承载。
- **快速收敛与 SLA**：传统 LFA/RLFA FRR 场景受限，高可靠需求下可能无法提供保护。
- **调优与可视化运维**：NQA 精度不足；传统网管难以基于业务做端到端可视化监控。

### 华为应对思路（云广域网络）

| 挑战 | 应对 |
|------|------|
| 多业务隔离困难 | 部署网络切片，不同切片承载不同业务 |
| 流量路径规划部署困难 | 基于 SR + 控制器全局规划并自动部署 |
| 缺乏快速收敛 / SLA 保障 | TI-LFA 算备份路径，配合 FRR、Hot-standby |
| 调优困难、缺可视化 | TWAMP / IFIT 精确感知质量并调优 |

术语：TI-LFA = Topology-Independent Loop-free Alternate；BNG = Broadband Network Gateway；TTM = Time To Market。

## 2. 华为云广域网络解决方案概述

iMaster NCE-IP 基于云化平台实现服务化与组件化，包括网络管理、网络控制、网络分析三大逻辑模块及面向场景的多种应用，可按需模块化部署。华为具备全场景 SRv6 产品能力（接入/城域/骨干）。

### 主要功能

- 转发路径自动规划、自动部署
- 网络性能实时监控，流量智能调优
- 网络切片，流量隔离转发
- 可视化运维，快速定位故障

### 关键技术要点

**BGP-LS** 收集拓扑的优势：

- 降低对上层控制器计算能力的要求，且不再要求控制器具备 IGP 能力
- BGP 汇总各进程/各 AS 拓扑，直接上送完整拓扑，利于算路
- 拓扑上送协议归一化

**BGP SR-Policy**：将转发路径信息通过 BGP 路由下发给头端，流量被引导进入特定 SR-Policy；段列表由优化目标与约束（时延、亲和性、SRLG 等）综合计算得到。SR Policy 是当前主流 SR 实现方式。

**TWAMP**：标准协议，可部署在 IP / MPLS / L3VPN 等；可获得性、可部署性强，无需时钟同步。

**IFIT**：直接对业务报文测量，得到真实丢包率、时延等；部署方便、统计精度高。

**信道化子接口 / FlexE**：

- 信道化子接口：不同类型业务归属不同 Dot1q VLAN 子接口，各自独立 HQoS，实现隔离。
- FlexE：基于以太网的多速率子接口在多 PHY 上承载，支持捆绑、通道化、子速率。

相关缩写：SQ（Subscriber Queue）、GQ（Group Queue）、VI（Virtual Interface）、DP（Data Plane）、TM（Traffic Manager）、PIC（Physical Interface Card）。

### 运维能力概览

- 网络 TOPN，快速发现瓶颈
- 性能拓扑，质量劣化清晰可见
- 区域流量/质量地图，识别热点
- 流量秒级峰值（如 15 分钟内每 5 秒最大值），真实反映带宽瓶颈与突发

### 使用场景示例：金融云广域

分布式云数据中心建设推动云骨干弹性扩容；引入 SDN、SRv6 实现智能管理与流量调优：业务快速发放、集中算路、智能选路；网络可视、实时感知；向多地多中心演进；控制器南向/北向能力开放。

## 3. 企业广域承载基础网络设计

基础设计主要包括：**物理网络设计、IP 地址规划、路由设计**。

### 3.1 物理网络设计

#### 核心层

- 核心节点选在业务流向集中且业务量大的位置。
- 同城核心之间通过波分互联，异地通过跨省/城域运营商专线；核心数量不宜过多。

#### 汇聚层

建设初期可基于现有业务规划，常见三种汇聚模式：

| 模型 | 说明 |
|------|------|
| DC/业务中心汇聚（DC-PE） | 汇聚数据中心、业务中心等服务总公司的单元 |
| 同城城域汇聚（MAN-PE） | 汇聚同城机构、附属机构等城域业务 |
| 区域分支汇聚（BR-PE） | 汇聚分公司及省级城域机构业务 |

#### 接入层

考虑带宽、专线类型与价格、可靠性与负载分担，例如：

- “口”字形组网构成主备双平面
- 主备平面通过业务规划或路由策略做广域流量负载分担

#### 专线选择

多数企业购买运营商传输专线（主要为 MSTP 与 OTN）：

- 分支接入：可用 MSTP，也可用 MPLS VPN 专线
- 接入—汇聚：可用 MSTP
- 汇聚—核心（不同机房）：可用 MSTP/OTN
- 核心之间：可用 MSTP/OTN；有裸光纤时也可用 DWDM

### 3.2 IP 地址规划

一般包括：IPv4 地址规划、IPv6 地址规划、SRv6 Locator 规划。

#### IPv4 设计原则

| 原则 | 说明 |
|------|------|
| 唯一性 | 骨干中不能两台主机同地址；即使 VPN 重叠也尽量避免 |
| 连续性 | 利于分层聚合、缩减路由表 |
| 扩展性 | 每层留余量 |
| 实意性 | 见地址可大致判断所属设备 |

环回地址：统一专有地址空间；采用 /32；按物理位置分配并预留；多平面则按平面依次分配。用于设备间通信、与控制器通信、建立邻居等。

规划建议：

- 内部互联：/30
- 接入地址：按原规划按需（如 /29）
- 分配顺序：互联从低到高，Loopback 从高到低
- 同层：编号小取奇地址，大取偶地址
- 跨层：靠近核心取奇，远离核心取偶

#### IPv6 设计原则

统一性、唯一性、层次化、安全性、连续性、可扩展性。

结构化规划建议层次化分配，减少碎片、增强聚合；子网字段可按 4 bit 粒度划分提高可读性。示例字段：固定前缀、网络类型、可分配地址块、主机地址等。进一步可拆：属性标识、网络类型、地址类型、地域、可分配块、接口地址（后 64 位）。

聚合性强的字段放高位；过度分层会耦合业务、降低利用率，需结合现网确定字段数。

#### SRv6 Locator

- Locator 是节点标识，用于路由转发到该节点，具备可路由、可聚合属性。
- 配置后生成 Locator 网段路由，经 IGP 在 SR 域扩散；本节点发布的 SID 均可通过该路由到达。
- Function（Opcode）可 IGP 动态分配或 `opcode` 静态配置；`static static-length` 决定静态 Opcode 数量。
- Args 可选，由 `args args-length` 决定。
- 建议全网 Locator 相同掩码；按核心→汇聚→接入从小到大分配。
- Locator 一般不建议超过 88 位；SID 尽量静态，保证设备重上线后不变，便于管理。

End.DT4 / End.DT6 分别标识 IPv4 / IPv6 VPN 实例；End.OP 主要用于 Ping/Tracert 等 OAM。

### 3.3 路由设计

#### IGP

广域网中 IGP 实现全网三层拓扑收集与泛洪，并配合 TWAMP/IFIT 收集链路时延等状态。骨干可用 OSPF 或 IS-IS，对比要点：

| 项 | IS-IS | OSPF |
|----|-------|------|
| 网络规模 | 较大（单 Level 极限规格约 4K） | 较小（单区域极限约 2K） |
| IPv6 | TLV 结构，无需另起协议栈 | 需单独 OSPFv3；双栈时 v2/v3 邻居分别配置，消耗更大 |
| SRv6 | 有标准/草案，生态更成熟 | 标准化落后于 IS-IS，并非所有厂家支持 |
| SR-MPLS | 支持，功能完善 | 支持，功能基本完善 |

参数建议：

- IGP 进程号：建议与 BGP AS 号一致
- IS-IS NET：建议 `aa.bbbb.cccc.dddd.00`，可用 Loopback0 映射（如 `21.231.232.1` → `21.0231.0232.0001.00`）
- OSPF Router ID：与 Loopback0 一致
- 接口类型：P2P，加速收敛
- 路由发布：IGP 只发布互联与管理地址

**IGP Metric 原则**：

- 接入层 Metric 优于汇聚层
- 汇聚层优于核心层
- DC 间链路优于分支到 DC 的广域链路
- DC 间跨平面优先在核心节点跨平面
- 独立 RR 到核心 P 的 metric 设最大（RR 只反射不转发）

#### BGP

- IBGP：统一用 Loopback0 建 peer；PE 与所有 RR 建 MP-IBGP 交换 VPN 私网路由
- EBGP：PE 用接口 IP 与 CE 建邻；域间 VPN 一般 Option A
- BGP-LS：控制器与所有 RR 建邻，收集逻辑拓扑
- 可部署独立 RR
- PE-CE 除 EBGP 外，也可用 OSPF/IS-IS/RIP/静态

**AS 规划**：企业常用私有 AS（64512~65534）。建议承载网统一一个 AS 作高速转发核心；不同地域 DC、分支部署独立 AS，与承载网建 EBGP。

**双平面 MED 示例**：同平面下一跳 MED=100，异平面 MED=200，使对端优选同平面；再向 CE 通告时通过 MED 微调优选指定 PE。

**防环防次优**：DC/分支内部一般不跑 BGP，IGP 引入 EBGP 路由时打 tag；反向把本地 IGP 引入 BGP 时按 tag 过滤，避免环路/次优。

## 4. 企业广域承载网络隧道与 VPN 设计（上）

将 VPN 流量承载于隧道之上，可在隔离的同时保障业务质量。

### 隧道技术概述

隧道即用一种协议封装另一种协议。企业网常用 BGP/MPLS IP VPN 通过 MPLS LDP 或 MPLS TE 隧道承载 VPN。

MPLS 本质是指导转发的隧道技术，具备完整创建、管理、维护机制——偏运营管理驱动，而非应用驱动。

### Segment Routing 解决思路

- **简化协议**：扩展后的 IGP/BGP 具备标签分发能力，无需 LDP；软件升级即可，保护投资。
- **源路由**：头端将转发策略实例化为标签/SID 列表，控制路径。
- **业务定义网络**：应用提出时延/带宽/丢包等需求，控制器收集拓扑与质量信息后算显式路径。

### SR-MPLS 分类

| 类型 | 要点 |
|------|------|
| SR-MPLS BE | IGP 分发标签，无需 LDP；SPF 算最短标签路径；无流量黑洞、无需维持 LDP 邻居 |
| SR-MPLS Policy | 扩展 BGP/IGP 将带标签 LSDB 送给控制器全局算路，无需 RSVP-TE 申请/维持路径；Node SID + Adjacency SID 实现负载分担与严格路径 |

基于 SR-MPLS BE 承载 VPN 时，转发类似 LDP BGP/MPLS IP VPN（公网标签 + 私网标签）。基于 Policy 时，头端 Push Segment List，沿途按最外层标签转发并 Pop。

### SRv6 简介

SRv6 不再基于 MPLS：在 IPv6 中插入 SRH，压入显式 IPv6 地址栈，中间节点不断更新目的地址完成逐跳转发。

- **SRv6 BE**：类似 LDP，基于 IGP/BGP 最优路径；通常一个 Segment 即可标识路径与业务；依赖 Cost 规划。
- **SRv6 Policy**：数据带外层 IPv6（含 SRH）与内层真实目的；每跳按 SRH 替换外层 DA。

本章隧道设计重点在 **SR-MPLS Policy / SRv6 Policy**（BE 随 IGP 设计基本完成）。

### 设计关注点摘要

- **端到端部署**：路径控制力强、可视化好；隧道数量多（大规模可达 5~10K）、扩展时需大量新增隧道。
- **时延探测**：IFIT 需全网 1588v2，场景受限；TWAMP 用 NTP 即可。
- **带宽规划**：下发隧道本身不限实际流量，入口需限速并配合 QoS 或网络切片。
- **引流**：基于 Color 只能按 Endpoint 选隧道，同目的不同业务可能进同一隧道；基于 DSCP 可按 Endpoint+DSCP 区分业务进不同隧道。
- **候选路径**：一个 Policy 可有多个 CP，由 `<protocol, origin, discriminator>` 唯一确定；preference 高者激活；控制器生产 Policy 时常只能做主备，主隧道内未必能负载分担。
- **逃生**：推荐同时部署 SRv6 BE 与 Policy；优先 Policy，全部失效后走 BE。

### VPN 划分与类型选择

多数企业：主要业务（生产/办公）一个 VPN，非主要业务一个，外联一个，互联网一个。

| 场景 | 建议 |
|------|------|
| SR-MPLS 承载 IPv4 L3VPN | 可用 BGP VPNv4 或 BGP EVPN |
| SRv6 承载 IPv4 L3VPN | 考虑与 IPv6/L2 统一，**推荐 BGP EVPN** |
| SR-MPLS 承载 IPv6 L3VPN | MP-VPNv6 或 BGP EVPN |
| SRv6 承载 IPv6 | **推荐 BGP EVPN** |

VPNv4/v6 与 EVPN L3VPN 能力基本一致；故障切换均可配合 VPN FRR、IP FRR、TE-HSB、TI-LFA、Mirror-SID 等。

## 5. 企业广域承载网络 SLA 与可靠性设计（开篇）

通过可靠性与 SLA 技术保障被承载业务质量。

### SLA 技术介绍

控制器可基于带宽算路并下发 SR Policy，但路径信息不含流量限速；实际流量可能超过规划带宽。需部署 SLA 技术限制所用带宽，主要包括 **QoS** 与 **网络切片**。

### QoS 规划原则

1. **合理性**：按业务重要性分配资源
2. **一致性**：分类、标记、调度、限速等整网一致
3. **可扩展性**：考虑后续业务扩展
4. **可维护性**：便于日常调整
