# SRv6高可靠性

## 报文转发流程回顾（SRv6 Policy）

头端 PE1 接收到 CE1 发送的单播 IPv6 报文后，查找 IPv6 路由表，该路由的出接口是 SRv6 Policy。PE1 为报文插入 SRH 信息，封装 SRv6 Policy 的 SID List，然后封装 IPv6 报文头信息。完成后，PE1 将报文向 P1 转发。

- 中间 P1 节点根据 SRH 信息逐跳转发。
- 报文到达尾节点 PE2 之后，PE2 使用报文的 IPv6 目的地址 `FC03::3` 查找 My Local SID 表，命中 End SID，因此 PE2 将报文 SL 减 1，IPv6 DA 更新为 END SID Net2。
- PE2 使用 END SID Net2 查找 My Local SID 表，命中 End SID，PE2 解封装报文，去掉 SRH 信息和外层 IPv6 报文头，然后将报文转发给 CE2。

## 广域承载网高可靠性需求

**50 ms 故障恢复**已经成为广域承载网的基础要求。

- **语音业务**：实时性强。故障恢复时间控制在毫秒级时，用户无感知或仅有轻微感觉，对业务影响不大；达到秒级则会话中断。
- **IPTV 业务**：故障恢复控制在毫秒级时，可能出现瞬时马赛克；丢包导致的 I 帧损伤是造成花屏的关键原因。

> 标准参照：YD/T 1071-2000《IP Telephone Gateway technical specification》。

### 多层可靠性方案概览

广域承载网需要从设备、网络、业务各层构建高可靠性，实现端到端 99.999% 高可用、全业务 50 ms 快速保护倒换。

| 层级 | 要点 |
|------|------|
| 物理层 | 高可靠硬件架构：主控、交换、转发、电源、风扇等关键部件冗余；高可靠组网：冗余路径、环形 / Spine-Leaf / 双平面等，并预留足够保护带宽 |
| 隧道层（SRv6 隧道 / IGP） | TI-LFA、Midpoint 保护（TE FRR）、Candidate Path（HSB） |
| 业务层（EVPN / L3VPN） | VPN FRR |

### 多层网络高可靠性技术概览

| 检测对象 | 检测技术 | 保护技术 |
|----------|----------|----------|
| Physical Link | BFD for Intf | TI-LFA |

| LSP / Locator | BFD for Locator | Midpoint 保护 |

## SRv6 隧道状态检测与隧道保护

### SRv6 隧道检测技术

SRv6 隧道一般可通过 **SBFD、Ping、Tracert** 等方式检测连通性。

- **SBFD**：可用于端到端检测隧道连通性；但不能定位具体故障位置，因此一般与 HSB 或 VPN FRR 配合使用。反射端的 IPv6 地址需和 SRv6 Policy 的目的地址相同。
- **SRv6 SID Ping**：主要用于检查网络连接及主机是否可达。Ping 检测有逐段检测与非逐段检测两种。
- **SRv6 SID Tracert**：在检查可达性的同时，还可分析故障发生位置。

SRv6 转发基于标准 IPv6 数据平面，可直接使用 ICMPv6 Ping & Tracert 实现普通 IPv6 地址连通性检测，无需改动硬件或软件。当目的地址是 SRv6 SID 时，也可通过 SRv6 OAM 扩展完成。当前 SRv6 OAM 扩展主要包括：

1. 在 SRH 中引入 **O-bit**（OAM 比特位）。
2. 引入 **End.OP SID**。

### SBFD 工作原理

SBFD（Seamless Bidirectional Forwarding Detection）是 BFD 的简化机制：简化状态机、缩短协商时间，提高网络灵活性。

- SBFD 分为**发起端**和**反射端**。链路检测前，双方通过互相发送 SBFD Control Packet 通告 Discriminator 等信息。
- 检测时，发起端主动发送 SBFD 报文，反射端根据本端情况环回；发起端根据反射报文决定本端状态。
- 反射端环回报文携带 **Admin Down** 或 **Up** 状态。
- 发起端收到 Up → 本地置 Up；收到 Admin Down 或定时器超时收不到返回 → 置 Down。

**发起端状态机**：只有 Up / Down；发出报文也只有 Up / Down；只能接收 Up 或 Admin Down。报文初始状态为 Down。目的端口号 7784，源端口号 4784；目的 IP 为用户配置的 127 网段任意地址，源 IP 为本端 LSR ID。

**反射端**：无 SBFD 状态机、无检测机制，不主动发送 SBFD Echo，仅构造环回报文。所构造报文目的端口 4784、源端口 7784；源 IP 为本端 LSR ID，目的 IP 为发起端的源 IP。

### SRv6 Ping / Tracert 介绍

**方案一：SRH 中的 O-bit**

O-bit 处于 SRv6 报文头中，每一个 SRv6 Endpoint 节点都需处理并响应 ICMPv6 Ping & Tracert，因此可实现**逐段（Segment-by-Segment）**检测。通过 `ping ipv6-sid` 和 `tracert ipv6-sid` 可检测单个或多个 SID。

**方案二：End.OP SID**

End.OP SID 指示将数据包上送到控制平面进行 OAM 处理。检测 SRv6 Policy 时，头节点将 End.OP SID 编入 Segment List。只有生成了 End.OP SID 的 Endpoint 才能处理请求，因此可实现**端到端（End-to-End）**检测。进一步分为：

- 在 `ping ipv6-sid` / `tracert ipv6-sid` 中增加 End.OP 类型 SID，实现对 SID 栈的检测。
- 在 `ping srv6-te policy` / `tracert srv6-te policy` 中指定 `end-op` 参数，实现对 SRv6 Policy 的检测。

### SRv6 Ping 工作原理

SRv6 Ping 可分为逐段 Ping 与非逐段 Ping。

**逐段检测：**

1. PE1 向 PE2 发起 Ping，携带 P1 的 SRv6 SID（End SID / End.X SID）和 PE2 的 End SID，构造并发送 ICMPv6 请求。
2. P1 收到后向 PE1 发送 ICMPv6 应答，并向 PE2 转发请求。
3. PE2 收到后向 PE1 发送 ICMPv6 应答。

**非逐段检测：**

1. PE1 向 PE2 发起 Ping，携带 PE2 的 End SID，构造并发送 ICMPv6 请求。
2. P1 收到后向 PE2 转发请求。
3. PE2 收到后向 PE1 发送 ICMPv6 应答；发送端 PE1 可查看 Ping 详细信息。

### SRv6 Tracert 工作原理

SRv6 Tracert 可分为 Overlay Tracert 与非 Overlay Tracert。

**Overlay 检测：**

1. PE1 向 PE2 发起 Tracert，携带 P1 的 SRv6 SID 和 PE2 的 End SID，构造 UDP 报文并封装 SRH。IPv6 首部 Hop Limit 初值为 64，每经一跳减 1；为 0 时丢弃并向 PE1 发 ICMPv6 超时。
2. P1 收到后 Hop Limit 变为 63，向 PE1 发 ICMPv6 端口不可达，并向 PE2 转发 UDP。
3. PE2 收到后 Hop Limit 变为 62，向 PE1 发 ICMPv6 端口不可达。

**非 Overlay 检测：**

1. PE1 向 PE2 发起 Tracert，携带相关 SID，构造 UDP 并封装 SRH；Hop Limit 初值设为 1。
2. P1 收到后 Hop Limit 变为 0，向 PE1 发 ICMPv6 超时。
3. PE1 将 Hop Limit 加 1（设为 2）继续发送。
4. P1 收到后 Hop Limit 为 1，向 PE2 转发。
5. PE2 收到后 Hop Limit 为 0，确认 SID 类型为 End SID，并校验上层协议头是否为 UDP 或 ICMPv6。

## 隧道保护技术概述

SRv6 隧道保护可分为两大类：

| 类型 | 特点 | 代表技术 |
|------|------|----------|
| 本地保护 | 切换快；只保护链路/节点 | TI-LFA FRR、Midpoint TI-LFA FRR、防微环、ECMP |
| 端到端保护 | 依赖检测机制快速切换；保护端到端路径 | Hot-Standby（HSB）、逃生路径 |

## TI-LFA FRR

### 原理

TI-LFA（Topology-Independent Loop-free Alternate）FRR 能为 SRv6 隧道提供链路及节点保护。某处链路或节点故障时，流量快速切换到备份路径继续转发。

示例：PE1 到 PE2 最短路径（主用）为 PE1→P1→P4→PE2。P1 计算到 PE2 的 TI-LFA 备份路径：

1. 排除主下一跳（Link P1→P4）计算收敛后最短路径：P1→P2→P3→P4→PE2。
2. 计算 P 空间和 Q 空间：P 空间为（P1，P2），Q 空间为（P3，P4，PE2）。
3. 把任意路径表示为多段：源节点 ↔ P ↔ Q ↔ 目的节点。源到 P、Q 到目的为无环路径；P 到 Q 用严格显式路径（END.X SID）表达，使整个 TI-LFA 路径无环。为简化修复路径，选取 P 空间中离源最远的 P2、Q 空间中距目的最远的 P3 及 PQ 间链路。
4. P1 感知 P1→PE2 接口 Down 后，使用备份表项转发，封装新 SRH（示例 Segment List 为 `<FC03::C4，FC06::6>`），修改 IPv6 目的地址为 `FC03::C4`，从备份出接口转发。

### P 空间与 Q 空间

- **P 空间**：以源节点为根到其他节点的 SPF 树，删掉被保护路径及其下挂分支和节点后，剩下可达节点（不含根）集合。
- **扩展 P 空间**：以源节点各个邻居为根（不含被保护链路节点）计算 SPF，删掉故障点下挂分支和节点后的可达节点集合。
- **Q 空间**：以目的节点为根，其他节点到根的 r-SPF 树，删掉被保护路径及其下挂后的可达节点集合。

### TI-LFA 优势

- 满足 100% 拓扑覆盖，不必担心网络 cost 规划对保护路径计算的影响。
- 部署简洁，基于 IGP 计算备份路径，无需为可靠性引入额外协议。
- 优先使用 Post-convergence 路径（IGP 收敛后路径）作为备份，减少切换次数，更利于带宽规划。

### TI-LFA 计算原则

优先级：`SRLG Disjoint > 节点保护 > 链路保护 > cost 最小`。

1. 计算同时满足 SRLG Disjoint + 节点保护的备份路径；多条时选 cost 最小。
2. 否则计算 SRLG Disjoint + 链路保护的备份路径；多条时选 cost 最小。
3. 否则计算满足节点保护的最小 cost 备份路径。
4. 否则计算满足链路保护的最小 cost 备份路径。

### TI-LFA FRR 的局限

在 SRv6 Policy 中常需约束报文经过指定节点或链路。当某些必须经过的节点/链路故障后，TI-LFA FRR 可能无法起到保护作用。

示例：主路径经 P1→P2→P3；P1 经 TI-LFA 算出去往 P3 备份为 P1→P2→P4→P3。若 **P2 故障**，备份路径仍依赖 P2，数据无法转发。

## Midpoint 保护

### 概述

为解决 SRv6 Policy 严格节点约束导致 TI-LFA 失效的问题，由中间节点（Midpoint）的上游节点代替其完成转发处理，该上游节点称为**代理转发（Proxy Forwarding）**节点。

代理转发节点感知到报文下一跳接口故障，且下一跳是报文目的地址、且 SL > 0 时：代替中间节点执行 End 行为，将 SL 减 1，将下层要处理的 SID 更新到外层 IPv6 报文头，再按下层 SID 指令转发，绕过故障节点。

### Midpoint 保护原理

1. 正常时，P1 计算到各节点的 IGP 最短路径和 TI-LFA 备份路径。
2. P1 配置 Middle point TI-LFA 后，若 P2 故障：P1 感知出接口故障，报文目的地址为直连邻居 P2 且 SRH 的 SL>0，触发 Middle point TI-LFA。
3. P1 代理转发：SL 减一，将 Next SID（如 `FC06::6`）拷贝到 IPv6 目的地址，再按目的地址转发，流量可经 P1→P3→P4 到达 PE2。
4. 若代理转发后发现到目的地址下一跳仍是 P2，则紧接着再做一次基础 TI-LFA，切到正确备份路径。
5. PE1 完成 IGP 收敛后删除到 P2 的 FIB；若 iMaster NCE-IP 仍下发含故障节点的 Segment List，节点也会做 Proxy Forwarding（SL 减一，以 Next SID 为 IPv6 DA）并沿途转发。

## 微环与防微环

### 微环介绍

TI-LFA 与 Midpoint 保护能在 IGP 收敛完成前短暂维持转发；收敛完成后不再按 FRR（隧道方式）转发，而按 IGP 路由正常转发。

现网各设备收敛速度可能不同，可能产生短暂环路，直至沿途路由器都收敛完成才消失，称为**微环**。

### 本地正切微环

紧邻故障点的节点收敛后引发的环路。

1. P1→P4 链路故障时，流量先按 TI-LFA 备份路径转发。
2. P1 收敛后下一跳收敛到 P2，按新路径发给 P2。
3. P2 及其他节点尚未收敛，P2 到 PE2 的下一跳仍是 P1 → P1 与 P2 形成环路，直到 P2 收敛完成。

### 本地正切防微环方案

节点收敛后**延迟一段时间再下发转发路径**：

1. P1 感知 P4 接口故障，进入 TI-LFA，按备份路径转发。
2. P1 启动定时器，超时前保持原转发表项，继续走 TI-LFA。
3. 定时器超时，网络其他节点均已收敛，P1 收敛并按新路径正常转发。

因 TI-LFA 一定是无环路径，只需维持一段时间继续走 TI-LFA，待其他节点收敛后再退出。

### 远端正切微环

故障在远端时，沿转发路径若离故障更近的节点先于更远节点收敛，也可能成环：

1. P3→P4 故障；假设 P3 做本地正切防微环延时收敛，流量走 TI-LFA；但其他节点正常 IGP 收敛。
2. P2 先收敛，到 PE2 新路径为 P2→P1→P5→PE2，流量到达 P2 后回发到 P1。
3. P1 尚未收敛，仍沿旧路径 P1→P2→P3→…，形成环路。

### 远端正切防微环方案

节点只能针对本地直连链路/节点故障预计算无环备份，无法对任意潜在故障预计算。需在节点收敛后计算无环路径。

P2 收敛后计算无环 TI-LFA（如 P2→P1→P5→PE2）。防环路径可以是严格显式路径，也可以是松散路径。

### 回切微环

分布式收敛无序同样影响故障回切：

1. P1→P4 故障期间，PE1→PE2 路径为 PE1→P1→P2→P3→P4→PE2。
2. 故障恢复后，若 P2 先收敛，到 PE2 路径变为 P2→P1→P4→PE2，流量发到 P1。
3. P1 因业务量大或 CPU 高等尚未收敛，仍用旧路径回发到 P2 → 成环。

### 回切防微环方案

与远端正切防微环类似：P2 收敛后在报文中封装新 SRH，按严格显式路径约束转发；P1 收敛后按收敛后路径转发到 PE2。也可使用松散路径。

## SRv6 Policy 端到端保护

### HSB（Hot-Standby）

部署 SRv6 Policy 时配置两个优先级不同的 candidate-path，可实现端到端隧道保护：preference 高为主路径，低为备份路径，并为两条路径启动 SBFD 检测。主路径 SBFD 检测到故障时切换到备路径。

若网络中部分设备不支持 SRv6 导致无法使用本地保护，也可使用 HSB 提供高可靠性。

示例示意：

```text
SRv6 policy PE1toPE3 endpoint PE3 color 100
  candidate-path preference 200 // Primary
    segment-list <PE1.End, PE3.End>
  candidate-path preference 100 // Backup
    segment-list <PE2.End, P2.End, PE4.End, PE3.End>
```

### ECMP

在一个 candidate-path 中配置两个 Segment-list，可实现负载均衡；其中一条失效时，流量仍可在另一条上转发。

### 逃生路径

当 PE1 通过 SBFD 感知主路径和备份路径都失效时，可将流量承载到 **SRv6 BE** 隧道上。

```cli
bgp 100
#
ipv6-family vpn-instance vpn1
 segment-routing ipv6 traffic-engineer best-effort
```

## SRv6 尾节点保护与接入保护

### 尾节点保护概述

对同一源端，SRv6 Policy 基于 `<Color，Endpoint>` 确定隧道。Endpoint（尾节点）故障时，隧道无法将数据送到目标网段。

局部保护和端到端保护只能保护源端 PE 与中间 P，**不能保护尾节点**。尾节点故障时，主要通过 **VPN FRR** 修复；也可用 Anycast FRR 与镜像保护（较复杂，现网较少使用）。

### VPN FRR

源端 PE 基于学习到的两条不同下一跳 PE 的私网路由，预先计算主备路由并下发 FIB；结合 BFD 快速探测远端 PE 故障，在感知远端故障且 VPN 路由收敛前，先将 VPN 流量切到备份路径。

```text
BGP 路由示意：
Prefix   NHP
Net2     PE2          （主）
Net2     PE3          （Backup）
```

### Anycast FRR

在 CE 双归的 PE 上部署相同 Locator 和 VPN SID，实现尾节点保护。除尾节点保护外，也可用于局部保护。

局限：

- 需静态指定 VPN SID，保证两台 PE 的 VPN SID 一致。
- 受限于 IGP 优选，无法做 VPN 层面选路（如希望 PE3/PE4 负载分担或优选 PE3，但 IGP 到共享 Locator 优选 PE4）。
- PE-CE 侧接口故障时，报文仍可能先到故障 PE 再绕行，产生绕行且难以恢复。

### SRv6 接入保护（Mixed FRR）

CE 双归 PE 时，若尾节点 PE 到 CE 链路故障可能导致丢包，可用 **Mixed FRR**：

PE2 从 CE2 收到一份私网路由，同时从 PE3 收到一份私网路由，形成 FRR。PE2→CE2 链路故障时，PE2 将相关流量导入备份路径 PE3。主路径下一跳是接入接口，备路径是 SRv6 隧道，形成混合 FRR。

```text
PE2 BGP 路由示意：
Prefix   NHP     Out-Int
Net2     CE2     PE2->CE2 接口   （主）
Net2     PE3     SRv6 Tunnel     （Backup）
故障后转发：PE2 → PE3 → CE2
```

## SRv6 基础配置：L3VPNv4 over SRv6 BE（上）

### 组网需求

1. PE1 和 PE2 各有一个 CE 属于 VPN 实例 `vpna`。
2. 在骨干网部署 L3VPN 迭代 SRv6 BE，使 CE1 与 CE2 的 Loopback1 可互通。

> （原图：CE1—PE1—P—PE2—CE2；AS 65000 / 100 / 65001；骨干 IPv6 链路 `2001:DB88:12::/96`、`2001:DB88:23::/96`；Loopback0 分别为 `2001:DB8:1::1`、`2001:DB8:2::2`、`2001:DB8:3::3`；CE Loopback1：`10.1.4.4/32`、`10.1.5.5/32`。）

实验基于 NE20E-S2F（软件版本：NE20E V800R012C10SPC300），不同设备思路相似，请参考对应产品手册。

### 配置思路

1. 完成设备接口 IPv6 地址及 IS-IS 配置（略）。
2. 在 PE1 与 PE2 之间建立 MP-BGP 对等体关系。
3. 骨干网上使能 Segment Routing，建立 SRv6 BE 路径。
4. PE 上配置使能 IPv4 地址族 VPN 实例。
5. PE 之间配置 MP-IBGP 交换路由信息。
6. 结果验证。

### 建立 SRv6 BE（PE1 示例，PE2 略，P 不需要）

```cli
[~PE1] segment-routing ipv6
[*PE1-segment-routing-ipv6] encapsulation source-address 2001:DB8:1::1
[*PE1-segment-routing-ipv6] locator as100 ipv6-prefix 2001:DB8:100:: 64 static
[*PE1-segment-routing-ipv6-locator] quit
[*PE1-segment-routing-ipv6] quit
[*PE1] bgp 100
[*PE1-bgp] ipv4-family vpnv4
[*PE1-bgp-af-vpnv4] peer 2001:DB8:3::3 prefix-sid
[*PE1-bgp-af-vpnv4] quit
[~PE1-bgp] quit
[~PE1] isis 1
[~PE1-isis-1] segment-routing ipv6 locator as100
[*PE1-isis-1] commit
[~PE1-isis-1] quit
```

### 配置说明：SRv6 基本功能

1. `segment-routing ipv6`：使能 IPv6 转发平面 Segment Routing，进入 SRv6 视图。
2. `encapsulation source-address ipv6-address [ ip-ttl ttl-value ]`：配置 SRv6 VPN 封装源地址。入隧道时使用该地址作为 IPv6 报文头源地址；必须是设备上已存在的接口地址。
3. `locator locator-name [ ipv6-prefix ipv6-address prefix-length [ static static-length | args args-length ] * ]`：配置 SRv6 Locator。
   - Locator 字段对应 `ipv6-prefix`，长度由 `prefix-length` 决定；Locator 本身是 IPv6 网段，其下地址均可作为 SID。配置后系统生成 Locator 网段路由，用于定位本节点。
   - Function（Opcode）可由 IGP 动态分配，也可 `opcode` 静态配置；`static static-length` 指定静态段长度。IGP 动态分配在静态段范围外申请，避免冲突。
4. （可选）`opcode func-opcode end-dt4 vpn-instance vpn-instance-name`：配置静态 End.DT4 Opcode。也可后续用 `segment-routing ipv6 locator` 使能 BGP 动态分配而跳过本步。
5. `quit` 退出 Locator / SRv6 视图。

### 使能 IS-IS SRv6

1. `isis [ process-id ]` 进入 IS-IS 视图。
2. `ipv6 enable topology ipv6`：在 IPv6 拓扑上使能 IS-IS IPv6 能力。
3. `segment-routing ipv6 locator locator-name [ auto-sid-disable ]`：使能 IS-IS SRv6。
   - 不带 `auto-sid-disable`：使能 SID 动态分配（须在 locator 范围内）。
   - 带 `auto-sid-disable`：关闭动态分配，完全静态分配。
   - 存在静态 Opcode 时优先用静态 SID；否则动态分配。
   - IS-IS 可为每个 Locator 分配 End SID（含 PSP / 非 PSP）；接口使能 IS-IS IPv6 后分配 End.X SID。进程可引用多个 Locator，但只有一个 Locator 能发布 End / End.X SID。
4. `quit` 退出 IS-IS 视图。

### 配置 VPN 私网路由携带 SID 属性

执行 `peer ipv6-address prefix-sid`，使能与指定 IPv6 对等体之间交换 IPv4 Prefix SID 信息。
