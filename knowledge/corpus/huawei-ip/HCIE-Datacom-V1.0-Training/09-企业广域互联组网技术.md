# 企业广域互联组网技术

## 1. 广域互联网络基本架构

### 运营商专线

企业基于网络可靠性与网络安全性考虑，在构建企业广域网时会向运营商租用传输专线或 MPLS 专线：

- 向运营商租用传输专线价格昂贵，但是数据被承载在传输专用线路上，业务质量和业务安全都有保障。传输专线常见形态：裸纤 / SDH / MSTP / WDM。
- 向运营商租用 MPLS 专线线路在价格上比传输专线便宜，能够保障业务安全，但是业务可靠性没有传输专线好。MPLS 专线常见形态：MPLS L2VPN / MPLS L3VPN。
- 少部分企业（比如交通、电力）拥有部署光纤的能力，可以自建骨干网。

### Internet 与 VPN

随着 Internet 的发展，部分企业业务可以使用 Internet 承载。由于 Internet 有安全风险，因此需要使用 VPN 技术提供安全可靠的连接。

- 以 PPTP、L2TP 以及 PPPoE 为代表的 VPDN 技术提供终端用户或者分支拨号连接到运营商或者总部网络的能力。
- 以 IPsec VPN 为基础的网络更多地成为企业分支之间以及分支与总部互连的选择。
- 为了解决 IPsec 在大规模组网配置复杂的问题，DSVPN、A2A VPN 等技术也发展起来并被广泛使用。

常见技术：PPTP / L2TP / SSL VPN / IPsec VPN / DSVPN / A2A VPN。

### 常见应用场景

企业广域互联需要基于企业需求部署。例如在金融行业为了可靠性和安全性，大多会租用传输专线或 MPLS 专线；在别的企业，考虑到网络成本一般会租用 MPLS 专线做主线路，Internet + VPN 做备用线路。

| 场景 | 说明 |
| --- | --- |
| 金融行业广域互联 | 总行—一级分行—二级分行—支行，常用 SDH/MSTP/MPLS；全国核心骨干高速干线 |
| 某酒企广域互联 | 企业总部到分支：MPLS（主用）+ Internet（备用，如 GRE Over IPsec） |

### 三种组网方案

企业广域互联方式较多，基于企业不同的需求，一般会使用一种或多种互联方式：

1. 传输专线（裸纤 / SDH / WDM / MSTP）
2. MPLS 专线（MPLS VPN）
3. Internet VPN

## 2. 广域互联组网技术应用

### 专线与 VPN 的对比

专线业务出现非常早，能够很好地满足企业之间互联的需求，对可靠性和安全性也有较好保障，但价格一直比较昂贵。随着网络的发展，VPN 技术开始占有更多的市场；对于网络有高安全高可靠性诉求的部分行业（如金融），依然倾向使用专线技术。专线与 VPN 的取舍应基于公司业务，多方面比较。

| 对比项 | 专线技术 | VPN 技术 |
| --- | --- | --- |
| 安全性 | 比较高，安全依赖于 ISP | 非常高，数据加密传输，安全控制由用户掌握 |
| 可靠性 | 很高，主要依赖 ISP 的网络可靠性 | 比较高，依赖 Internet 线路的可靠性 |
| 可扩展性 | 依赖 ISP，扩展存在中间环节，扩展性一般 | 基于 TCP/IP，接入方式灵活，网络可达就可以扩展 |
| 投资成本 | 费用很高，需按月支付专线租用费用，且网络建设初期需投入设备费用 | 设备一次性费用投入，无需支出每月的运营费用 |
| 对移动用户的支持 | 只能连接专线到达的网络，不支持离开局域网的内部移动用户接入 | 内部移动用户可使用 Internet 安全接入，消除地域差异 |
| 传输带宽 | 由于价格昂贵，一般租用的带宽都比较小 | Internet 价格低廉，租用带宽一般比较大 |

### 运营商专线介绍

- 运营商拥有大量线路资源，对于不同的行业与场景推出不同专线业务。
- 运营商高品质的传输专线业务主要是 SDH、MSTP、裸纤等，价格昂贵，但是性能优异。
- 运营商还有一类专线业务是 MPLS VPN：能提供稍逊于传输专线的性能，但价格更便宜。

示例：金融行业租用运营商 MSTP/SDH 专线保障高可靠；某省图书馆可采用运营商 MPLS VPN，或企业自建 GRE Over IPsec。

### 企业自建专线与 VPN

- 企业可以通过运营商网络自行建立 VPN，比如：SSL VPN、DSVPN、IPsec VPN 等。
- 部分大型企业有自行铺设光纤的能力，能够自建专线，但拥有该能力的公司较少。
- 企业自建 VPN 由于价格低廉、扩展方便、企业可控性强，被越来越多地使用。

示例：某省图书馆 VPN 网络（GRE Over IPsec）；能源行业可自建 MPLS VPN 骨干。

### 专线技术概述

专线技术诞生很早，由于网络的发展很多专线技术已经不再使用（如帧中继、ATM 等）。现在使用比较多的专线技术基本分以下几种：

- **裸纤**：也叫裸光纤，运营商提供光纤，中间不经过别的设备，光纤价格昂贵。
- **SDH / MSTP / WDM**：传输类专线，使用传输设备在光纤上构建硬管道，能够保障良好的性能，价格比裸纤便宜。
- **MPLS VPN**：MPLS 专线，使用以太网做接入，基本不构建硬管道，在性能上比传输类专线弱，但是价格是专线中最便宜的。

### 裸纤专线

裸纤也叫裸光纤，运营商提供一条纯光纤线路，网络容量取决于光纤两端的企业设备。裸纤按照距离收费，距离越远越贵；光纤有最大长度，一般认为光纤一跳最大距离是 300 km，超过 300 km 的站点之间需要架设中继设备。

> （原图：企业分部—运营商光缆网络—企业总部，两端为企业传输设备）

应用场景示例：同城的主校区和分校区之间可以租用运营商裸纤互联，简化网络管理和接入认证管理。

### SDH / MSTP / WDM

- **SDH**（Synchronous Digital Hierarchy，同步数字体系）：一种 TDM（时分复用）系统，是传统的电路调度方式。
- **MSTP**（Multi-Service Transport Platform，多业务传送平台）：同时实现 TDM、ATM、以太网等业务的接入、处理和传送。
- **WDM**（Wavelength Division Multiplexing，波分复用）：利用多个激光器在单条光纤上同时发送多束不同波长的激光，WDM 设备的传输带宽很高，现网基本能达到 8T 的带宽。

应用场景：金融分支站点互联时，为了保障网络的高可靠和高安全，一般会选用 MSTP 或 SDH 专线（总行—分行—支行）。

### MPLS VPN 专线

MPLS VPN 技术被广泛地用于企业互联，根据企业需求可以部署 MPLS L2VPN 或者 MPLS L3VPN。MPLS VPN 作为价格和性能折中的方案，是一种很受欢迎的专线业务。

- 对于能够自建广域网的企业（如铁路、电力等），MPLS VPN 是一种易管理、低成本的 VPN 技术；对于无法自建广域网的企业，向运营商租用 MPLS VPN 价格可能较贵。
- 对于一些有高可靠、高安全需求的企业，可以使用 MPLS VPN 作为主链路，使用 GRE Over IPsec 作为备用链路。

跨域 MPLS L3VPN 方案有 3 类：Option A、Option B、Option C。

- Option A 适合小型跨域 MPLS L3VPN 网络。
- Option B 适合中大型跨域 MPLS L3VPN 网络。
- Option C 适合大型或特大型跨域 MPLS L3VPN 网络。

### VPN 技术分类

按业务用途划分：

- **Access VPN（远程访问虚拟专网）**：向出差流动员工、远程办公人员和远程小办公室提供通过公用网络与企业 Intranet/Extranet 建立私有网络连接的能力。结构有两种：用户发起（Client-initiated）与接入服务器发起（NAS-initiated）。
- **Intranet VPN（企业内部虚拟专网）**：通过公用网络进行企业内部各个分布点互联，是传统专线网或其他企业网的扩展或替代形式。
- **Extranet VPN（扩展的企业内部虚拟专网）**：利用 VPN 将企业网延伸至供应商、合作伙伴与客户处，使不同企业间通过公网构筑 VPN。

根据在 OSI 模型中实现隧道的层次：

- **第二层隧道协议**：将整个 PPP 帧封装在内部隧道中。现有的第二层隧道协议有：PPTP（Point-to-Point Tunneling Protocol）、L2F（Layer 2 Forwarding）、L2TP（Layer 2 Tunneling Protocol）。
- **第三层隧道协议**：隧道内只携带第三层报文。主要有 GRE（Generic Routing Encapsulation）、IPsec（IP Security）。IPsec 不是一个单独的协议，包括 AH（Authentication Header）和 ESP（Encapsulating Security Payload）。

### VPDN 与隧道技术

VPDN 的具体实现是采用隧道技术，即将企业网的数据封装在隧道中进行传输。隧道技术的基本过程是在源局域网与公网的接口处将数据作为载荷封装在一种可以在公网上传输的数据格式中，在目的局域网与公网的接口处将数据解封装，取出载荷。被封装的数据包在互联网上传递时所经过的逻辑路径被称为“隧道”。

VPDN 有以下 3 种常用的隧道技术：

- 点到点隧道协议 PPTP
- 二层转发 L2F
- 二层隧道协议 L2TP

#### PPTP 简介

PPTP 协议是一个 VPN 协议，已有 20 多年的历史。该协议依赖于加密、认证和点对点协议（PPP）进行协商。实质上，它只需要用户名、密码和服务器地址就可创建连接。PPTP 速度很快，但速度是以弱加密性为代价的；在所有 VPN 协议中，PPTP 加密级别最低，且必须基于 IP 网络。

#### L2TP 简介

IETF 的开放标准 L2TP 协议结合了 PPTP 等协议的优点，特别适合组建远程接入方式的 VPN，已经成为事实上的工业标准。但请注意，L2TP 只是一种隧道协议，既不提供加密也不保证隐私，因此一般与 IPsec 配合使用。L2TP 被作为常用的企业互联技术之一，使用 L2TP 需要配合 AAA 服务器；当需要构建 L2VPN 时，L2TP 是非常好的选择。

典型角色：L2TP Client、LNS、L2TP Tunnel。

#### Access VPN 现网应用

Access VPN 现网中多用于内网用户远程接入，使用最多的是 L2TP over IPsec。PPTP 由于需要 Windows 系统支持，且外网接入需要将内网的 Windows 服务器通过 NAT 映射出去，部署不便，使用很少。

分支站点之间也可以使用 L2TP 链接，但 L2TP 没有办法传递组播数据，无法在总公司和分公司之间传递路由，所以现网 L2TP 更多用于远程用户接入。

#### Intranet VPN 主要技术

- GRE
- GRE Over IPsec
- DSVPN
- DSVPN + IPsec 保护

#### GRE 原理要点

GRE 是 Tunnel（隧道）技术的一种，属于第三层隧道协议。GRE 隧道是一个虚拟的点到点连接，为封装的数据报文提供一条传输通路。GRE 隧道的两端是 Tunnel 接口，分别对数据报文进行封装及解封装。负责发送封装后报文的物理接口叫做隧道源接口，对端接收此报文的物理接口叫做隧道目的接口。

封装过程概要：

1. RTA 连接企业分部的接口收到 IP 数据报文后，首先交由 IP 协议处理。
2. IP 协议检查报文头中目的地址来确定如何转发；若需经 GRE 隧道到达，则发给相应 Tunnel 接口。
3. Tunnel 接口为其封装 GRE 报文头，再交由 IP 协议处理。
4. IP 协议再为 GRE 报文封装新的 IP 报文头（源地址为隧道源接口 IP，目的地址为隧道目的接口 IP），然后按路由从表相应物理接口发出。

解封装过程与封装过程相反：RTB 收到目的为本机且协议号为 47（GRE）的 IP 报文后，剥掉 IP 头交给 GRE；GRE 校验后剥掉 GRE 头再交 IP，最终转发到企业总部。

#### GRE Over IPsec

- GRE 可以封装组播数据并在 GRE 隧道中传输；而 IPsec 目前只能对单播数据进行加密保护。因此对于路由协议、语音、视频等组播数据需要在 IPsec 隧道中传输的情况，可先 GRE 封装，再对封装后的报文进行 IPsec 加密。
- GRE Over IPsec 结合两种技术优点：既可支持多种上层协议和组播报文，又可支持报文加密、身份认证和数据完整性校验。
- 当网关之间采用 GRE over IPsec 连接时，先进行 GRE 封装，再进行 IPsec 封装。
- 封装模式：隧道模式、传输模式。

#### IPsec 简介（与 GRE 结合）

IPsec（IP Security）协议族是 IETF 制定的一系列安全协议，为端到端 IP 报文交互提供基于密码学的、可互操作的、高质量的安全保护机制。通过对数据加密、认证，IPsec 使得数据能够在 Internet 上安全传输。IPsec VPN 可以和多种 VPN 技术结合使用。

现网中分支站点互联多使用 GRE Over IPsec：IPsec 保障数据安全传输，GRE 保障企业内网之间能够互联。

#### DSVPN 解决的问题

DSVPN 主要解决 GRE Over IPsec 的缺陷：

- 所有流量必须穿越 Hub。
- 新增站点后需要修改 Hub 配置。
- Spoke 站点使用动态地址时，部署点到点 GRE 会有问题。

#### Intranet VPN 现网应用

Intranet VPN 现网中主要用于企业分支与总部、分支与分支之间互联。现网中使用比较多的是 GRE Over IPsec。对于有较多分支的企业，可以使用 Efficient VPN 简化分支配置；部署 IPsec 链路冗余备份后可以保障 GRE 的可靠性。

DSVPN 在现网使用较少，主要原因：很多企业希望分支之间流量能经过总部，便于管理；企业运维人员对 DSVPN 了解一般，运维较不便。

#### Extranet VPN

Extranet VPN 主要用于在客户或者供应商之间构建安全的访问服务，同时对于出差员工也可以使用 Extranet VPN 接入公司网络。主要用到的技术是 SSL VPN 与 L2TP。

#### SSL VPN

SSL VPN 是以 SSL 协议为安全基础的 VPN 远程接入技术，移动办公人员（远程用户）使用 SSL VPN 可以安全、方便地接入企业内网，访问企业内网资源。

在 SSL VPN 出现之前，IPsec、L2TP 等技术虽可支持远程接入，但存在缺陷：

- 远程用户终端上需要安装指定的客户端软件，部署、维护比较麻烦。
- IPsec / L2TP VPN 的配置繁琐。
- 网络管理人员无法对远程用户访问企业内网资源的权限做精细化控制。

应用场景：外部用户接入内网，使用 SSL VPN 比较方便，无需安装客户端，直接使用网页即可访问公司内网；业务选择较多，比如网页代理、文件分享、端口转发、网络扩展。对于不支持 SSL VPN 的路由器，可使用 L2TP 建立外网对内网的连接。

## 3. 广域互联高可靠性技术应用

### 链路探测技术

网络链路质量的波动会影响业务质量，而如何快速地感知链路质量波动是改善链路质量的第一步。探测链路质量的协议和技术基本可以分为两大类：

**链路连通性检测技术：**

- BFD（Bidirectional Forwarding Detection，双向转发检测）
- EFM（Ethernet in the First Mile，最后一公里以太网）
- CFM（Connectivity Fault Management，连接错误管理）

**链路质量检测技术：**

- NQA（Network Quality Analysis，网络质量分析）
- IP FPM（IP Flow Performance Measurement，IP 流性能测量）

现网中主要使用 BFD 探测链路连通性，使用 NQA、IP FPM 探测链路质量。

同一数据路径上只建立一个 BFD 会话；如果不同应用在同一数据路径上需要使用不同的 BFD 协议参数，则应通过共享解决：选择能覆盖所有应用要求的参数来配置唯一的 BFD 会话，BFD 会话状态变更将上报给所有绑定的应用。

NQA 监测网络上运行的多种协议的性能，使用户能够实时采集各种网络运行指标，例如：HTTP 总时延、TCP 连接时延、DNS 解析时延、文件传输速率、FTP 连接时延、DNS 解析错误率等。

#### IP FPM 角色

- **TLP（Target Logical Port，目标逻辑端口）**：分布在网络边缘的观测点，对应网络中边缘节点的接口，负责执行统计动作（丢包统计、时延统计），产生统计数据（收发报文计数、收发流量统计、时间戳信息等）。对于一条具体的目标流，上游统计点称为 In-Point-TLP，下游统计点称为 Out-Point-TLP。
- **DCP（Data Collecting Point，数据收集点）**：对应网络中的边缘节点，负责管理和控制 TLP、收集 TLP 产生的统计数据、上报统计数据给 MCP。
- **MCP（Measurement Control Point，测量控制点）**：对应网络中的中间节点，负责收集 DCP 上送的统计数据、完成统计数据的汇总和计算、向用户终端或网管系统上报统计结果。

#### 应用场景

- NQA 与 BFD 通常会与浮动路由联动。当 NQA 或 BFD 检测到链路出现故障，则高优先级路由会失效，备用路由会被启用。
- IP FPM 通过对数据包进行染色标注，帮助入口与出口设备测量特定流量的丢包或抖动；由于可以端到端地测量网络质量，可在出口多链路场景下测试不同链路的真实网络质量。

### 网络与业务可靠性

#### 网络可靠性

当网络出现问题时，问题点可能无法第一时间发现或者修复，因此需要冗余技术。常用的冗余技术主要有堆叠、链路聚合、VRRP 等。其中出口或者网关设备使用最多的网络冗余技术是 VRRP。

主机与外部网络互联需要通过网关，当单网关出现问题时会面临较长时间的业务中断。增加出口网关是提高系统可靠性的常见方法，此时如何在多个出口之间进行选路就成为需要解决的问题。

VRRP（Virtual Router Redundancy Protocol，虚拟路由冗余协议）把多台路由设备联合组成一台虚拟的路由设备。当网关设备发生故障时，VRRP 机制能够选举新的网关设备承担数据流量，从而保障网络的高可靠性（Master / Backup 切换引导流量切换）。

#### 业务可靠性：SAC 与 SPR

云计算时代，网络的可靠性不再满足用户的需求，用户希望能够基于应用了解现网的情况，并根据应用的现状调整网络。传统网络面临挑战：

- 传统网络无法很好地识别应用。
- 传统网络无法基于应用调整。

为应对以上挑战，产生了两种技术：

- **SAC**（Smart Application Control，智能应用控制）：能够灵活地识别应用。
- **SPR**（Smart Policy Routing，智能策略路由）：能够基于网络状况或者应用状况切换转发路径。

一条流量的报文进入设备之后，设备首先根据报文中携带的五元组信息，判断该报文是否已经识别过应用。如果识别过，则不需要重复识别，直接送入三层转发；如果没有识别过，则送入 SAC 进行应用识别。SAC 识别结束后，报文根据识别结果进行业务处理，再送入三层转发。SAC 识别流程为：先根据 FPI 中的 ACL 规则识别应用；失败则根据 FPI 中的 DNS 关联表识别；再失败则根据 FPI 中的协议端口表识别；若三者都未识别出应用，再送入 SA 继续识别。

SPR 可以主动探测链路质量并匹配业务的需求，从而选择一条最优链路转发业务数据，可有效避免网络黑洞、网络震荡等问题。

应用场景：基于 SAC 识别应用，并通过 SPR 选路就可以保障关键业务在网络上的可靠性。SAC 通过 SA 特征库与 FPI 特征库识别应用并分组流量；SPR 基于探测报文确定链路质量从而决定转发路径。

## 4. 广域互联优化技术应用

### QoS 技术应用

为了支持具有不同服务需求的语音、视频以及数据等业务，要求网络能够区分出不同的通信，进而提供相应的服务。例如 VoIP 等实时业务对报文传输延迟提出了较高要求；相对而言，E-Mail 和 FTP 业务对时间延迟并不敏感。传统 IP 网络的尽力服务不可能识别和区分出网络中的各种通信类别，而具备通信类别的区分能力正是为不同通信提供不同服务的前提。

QoS 旨在针对各种应用的不同需求，为其提供不同的服务质量。例如：

- 可以限制骨干网上 FTP 使用的带宽，也可以给数据库访问以较高优先级。
- 对于 ISP，其用户可能传送语音、视频或其他实时业务，QoS 使 ISP 能区分这些不同的报文，并提供不同服务。
- 可以为时间敏感的多媒体业务提供带宽和低时延保证，而其他业务在使用网络时，也不会影响这些时间敏感的业务。

在企业广域互联场景下，QoS 一般被部署在出口链路上，通过部署 QoS 技术能保障高价值业务的带宽与时延（如视频流、语音流优先于数据流）。

### HQoS 概述

传统的 QoS 基于接口进行流量调度，单个接口只能区分业务优先级，只要属于同一优先级的流量，就使用同一个端口队列，彼此之间竞争同一个队列资源。因此，传统的 QoS 无法对接口上多个用户的多个流量进行区分服务。

HQoS 基于多级队列实现层次化调度，不仅区分了业务，也区分了用户，实现了精细化的 QoS 服务。

家宽/多租户场景下，不同家庭可能租用不同的网络带宽和不同的网络服务（如上网 HSI、IPTV、VoIP），QoS 无法精细化管理这些家庭；HQoS 可解决此类局限。

相关业务术语：

- VoIP：IP 语音电话业务
- IPTV：互联网电视业务
- HSI：个人上网业务

### FEC / A-FEC 技术应用

差错控制技术一般可以分为前向纠错与后向纠错两种：

- **ARQ**（Automatic Repeat-reQuest，自动重传请求）：按需重传机制。发送方通过“发送-确认”机制感知接收方是否收到数据报文；如果没有收到确认则会重传。这种纠错方式需要重复发送报文所以会引入额外时延，也称为后向纠错。
- **FEC**：将冗余纠错包与数据包一起发往接收方，接收方如果发现差错，直接通过冗余纠错包还原丢失的数据包。该纠错行为发生在接收方，也称为前向纠错。FEC 冗余纠错包的纠错能力有一定限制，例如 4 个报文中丢了 3 个，依靠剩下的 1 个报文无法还原其余三个。

#### A-FEC 简介

在 FEC 中，原始数据与冗余纠错包的数量比例是固定的。当碰到突发丢包时有可能因丢包过多导致冗余包无法还原原始数据，因此面对有突发丢包的网络时 FEC 不适用；同时 FEC 由于添加了冗余包使得带宽利用率有所下降。

A-FEC（Adaptive-FEC）技术可以基于现有网络质量灵活地增加冗余包：

- 当网络质量较好时，A-FEC 可以少量添加或者不添加冗余包，提高带宽利用率。
- 当网络质量较差时，A-FEC 会增加冗余包的数量，避免因突发丢包导致的数据无法还原。

应用场景：使用 FEC 或 A-FEC 可以保障关键的视频应用，减少视频卡顿与花屏。使用 A-FEC 算法根据应用和链路质量在发送端灵活增加冗余包，抵御网络连续丢包，可保障关键视频应用在 20% 丢包的情况下无卡顿、无花屏。

### GRE 产生背景与隧道技术

随着企业的发展，越来越多的企业需要在分支—总部之间进行内网通信。传统方式需要租用专线（如 MPLS、传输专线等），价格昂贵。由于 Internet 发展，通过 Internet 建立分支—总部内网通信的可行性越来越高，GRE（Generic Routing Encapsulation，通用路由封装协议）在此背景下被提出。通过 GRE 隧道，分支和总部之间可以基于 Internet 建立企业网络。

GRE 本质上是一种隧道技术。隧道技术类似于一座桥，可以在底层网络（如 Internet）之上构建转发通道，用户可自行构建隧道网络，不需要底层网络管理者（如 ISP）介入。常见隧道技术有：MPLS、GRE、L2TP、VXLAN 等。基本过程：封装外层头部 → 设备根据外层头部在底层网络转发（底层对内层数据不感知）→ 解封装外层头部。

#### GRE 头字段

| 字段 | 解释 |
| --- | --- |
| C | 校验和验证位。置 1 表示 GRE 头插入了 Checksum 字段；置 0 表示不含校验和字段 |
| K | 关键字位。置 1 表示插入 Key 字段；置 0 表示不含关键字字段 |
| Recursion | 表示 GRE 报文被封装的层数；完成一次封装后加 1；若封装层数大于 3 则丢弃。用于防止无限次封装 |
| Flags | 预留字段，当前必须置为 0 |
| Version | 版本字段，必须置为 0 |
| Protocol Type | 标识乘客协议类型。常见 IPv4 为 0800；Ethernet over GRE 为 0x6558 |
| Checksum | 对 GRE 头及其负载的校验和 |
| Key | 关键字字段，隧道接收端用于对收到的报文进行验证 |

#### GRE 基本工作原理与 Keepalive

GRE 隧道是三层隧道，主要承载 IPv4/IPv6 报文。GRE 通过封装外层 IP 头部，使得数据可在公网上传递，达到企业分支—总部内网互通的目的。

Keepalive 检测功能实现过程：

1. 源端使能 Keepalive 后创建定时器，周期发送 Keepalive 探测报文，同时通过计数器进行不可达计数；每发送一个探测报文，不可达计数加 1。
2. 对端每收到一个探测报文，就给源端发送一个回应报文。
3. 若源端计数器值未达到预先设置的重试次数（Retry Times）就收到回应，表明对端可达；若达到重试次数仍未收到回送报文，则认为对端不可达，源端关闭隧道连接。但源端口仍会继续发送 Keepalive；若对端 Up，则源端口也会 Up，建立隧道链接。

#### GRE 安全威胁与校验/关键字

GRE 隧道主要作用是传递数据，数据并不加密，有被篡改的风险；通过伪造 IP 地址也可能使非法设备与合法设备建立 GRE 隧道。

- 隧道两端可按需配置校验和：若本端配置而对端未配置，本端不对接收报文做校验和检查，但对发送报文计算校验和；相反则只检查接收、不计算发送。
- 关键字用于标志隧道中的流量，属于同一流量的报文使用相同关键字；解封装时基于关键字识别。两端都不设置，或两端设置相同关键字，才能通过验证，否则丢弃。

#### GRE 构建分支—总部内网与 GRE Over IPsec

GRE 隧道能承载 IPv4/IPv6 单播、组播、广播报文，分支—总部之间可以通过 GRE 隧道建立动态路由协议邻居（如 OSPF Area），使内网互联更方便。

GRE 技术简单，但数据以明文方式传递，容易被窃取。现网一般与 IPsec 结合：GRE 构建内网互联，IPsec 加密 GRE 隧道报文（先 GRE 内层，再 IPsec 外层）。

#### 通过 GRE 接入 MPLS VPN

在 MPLS VPN 中，为了让 CE 接入 VPN 往往需要 CE 与 MPLS 骨干网的 PE 之间有直接物理链路。实际组网中并非所有 CE 和 PE 都能直连（例如已连接到 Internet 或基于 IP 技术的骨干网，地理位置相距甚远），无法直接访问 MPLS VPN 内部站点。

为了让 CE 能接入 MPLS VPN 且保证数据传输安全性，可在 CE 和 PE 间利用公共网络或某私有网络相连，并在 CE 与 PE 之间创建 GRE 隧道，在 PE 上将 VPN 与 GRE 隧道接口进行关联。

### L2TP 概述

L2TP（Layer 2 Tunneling Protocol）结合了 L2F 和 PPTP 的优点，是 IETF 有关二层隧道协议的工业标准。L2TP 是虚拟私有拨号网 VPDN（Virtual Private Dial-up Network）隧道协议的一种，扩展了 PPP 的应用，是远程办公场景中为出差员工远程访问企业内网资源提供接入服务的重要 VPN 技术。

#### 关键角色

- **NAS**（Network Access Server）：主要由 ISP 维护，连接拨号网络，是距离 PPP 终端地理位置最近的接入点。ISP 在 NAS 上部署 LAC，可为远程拨号用户提供 L2TP 服务，和企业总部建立隧道连接。
- **LAC**（L2TP Access Concentrator）：交换网络上具有 PPP 和 L2TP 协议处理能力的设备。LAC 根据 PPP 报文中所携带的用户名或域名信息，和 LNS 建立 L2TP 隧道连接，将 PPP 协商延展到 LNS。
  - NAS-Initiated：ISP 在 NAS 上部署 LAC；或企业分支以太网络中网关作为 PPPoE 服务器同时部署为 LAC。
  - L2TP Client-Initiated：分支网关配置可主动向 LNS 发起 L2TP 隧道连接请求的 L2TP Client，不需要远端系统拨号触发，L2TP Client 为 LAC。
  - Client-Initiated：出差人员在 PC 或移动终端上使用 L2TP 拨号软件，则终端为 LAC。
- LAC 可以发起建立多条 L2TP 隧道使数据流之间相互隔离。

#### 控制消息与数据消息

- **控制消息**：用于 L2TP 隧道和会话连接的建立、维护和拆除；使用消息丢失重传和定时检测隧道连通性等机制保证控制消息传输可靠性，支持流量控制和拥塞控制。控制消息承载在 L2TP 控制通道上，封装在 L2TP 报头内再经 IP 网络传输。
- **数据消息**：用于封装 PPP 数据帧并在隧道上传输；数据消息不可靠，不重传丢失报文，不支持流量控制和拥塞控制。

#### 连接建立与典型场景

1. **建立 L2TP 隧道连接**：LAC 收到远程用户 PPP 协商请求时向 LNS 发起隧道请求；通过控制消息协商隧道 ID、隧道认证等，成功后由隧道 ID 标识。
2. **建立 L2TP 会话连接**：若隧道已存在则协商会话 ID 等；会话携带 LAC 的 LCP 协商信息和用户认证信息，LNS 认证通过后通知 LAC 会话建立成功，由会话 ID 标识。
3. **传输 PPP 报文**：会话建立成功后，PPP 终端将数据发至 LAC，LAC 按隧道和会话 ID 做 L2TP 封装发到 LNS，LNS 解封装后按路由转发。

典型场景：

- 出差员工在 PC 上使用 L2TP 拨号软件，总部网关部署为 LNS，建立虚拟点到点连接。
- 分支网关部署为 L2TP Client，总部为 LNS，只对分支网关认证，分支用户 IP 报文经虚拟拨号接口送至 LNS。
- 分支用户使用 PPPoE 客户端，分支网关作为 PPPoE 服务器和 LAC，将呼叫请求到达总部 LNS。

### IPsec 简介与协议框架

企业分支之间经常有互联需求。部分企业从成本和需求出发选择 Internet 线路互联，但存在安全风险。IPsec 通过将数据报文加密传输，保障企业互联安全性。

IPsec 为端到端 IP 报文交互提供基于密码学的、可互操作的、高质量的安全保护机制。

#### 对称加密与非对称加密

- **对称加密**：加密密钥能从解密密钥推算出来；发件人和收件人共同拥有同一个密钥，既用于加密也用于解密。适合加密大量数据；安全性取决于密钥是否泄露；通信双方须先安全交换密钥。
- **非对称算法（公钥加密）**：使用公钥和私钥，二者在数学上相关。公钥可公开传递，私钥保密。只有私钥才能解密用公钥加密的数据；用私钥加密的数据只能用公钥解密。

#### 数据认证

数据认证主要目的是确认数据是否被篡改，主要基于 Hash 算法：数据通过 Hash 算法计算出唯一 Hash 值并携带转发；对端对数据重新 Hash，将收到的 Hash 值与计算出的 Hash 值比对，一致说明没有被篡改。

#### IPsec 加密基本思路

IPsec 同时使用对称加密与非对称加密，保证安全也兼顾性能：将对称加密所用的密钥使用非对称算法加密并传递；数据通过交互后的对称密钥加密。

#### IPsec SA 与 IKE

两端设备使用 IPsec 通信时需要保证一致的加密算法、验证算法等，因此需要协商机制。建立 IPsec SA 一般有两种方式：

- **手工方式**：管理成本很高，加密验证方式需手工配置，手工刷新 SA，且 SA 信息永久存在安全性较低，适用于小型网络。
- **IKE 方式**：管理成本较低，加密验证方式通过 DH 算法生成，SA 信息有生成周期且动态刷新，适用于小型、中大型网络。

IPsec SA 由一个三元组唯一标识：安全参数索引 SPI（Security Parameter Index）、目的 IP 地址和使用的安全协议号（AH 或 ESP）。IKE SA 的主要作用是构建一条安全通道，用于交互 IPsec SA。

IKE 支持的认证算法：MD5、SHA1、SHA2-256、SHA2-384、SHA2-512、SM3。  
IKE 支持的加密算法：DES、3DES、AES-128、AES-192、AES-256、SM1 和 SM4。

ISAKMP 由 RFC2408 定义，定义了协商、建立、修改和删除 SA 的过程和包格式；ISAKMP 只提供通用框架，并未定义具体的 SA 格式。ISAKMP 报文可利用 UDP 或 TCP，端口都是 500，一般情况下常用 UDP。

#### IPsec 算法与 HMAC

- ICV（Integrity Check Value）用于接收方进行完整性校验；可选认证算法有 MD5、SHA1、SHA2、SM3。
- 常用对称加密算法：DES、3DES、AES、国密 SM1/SM4。其中 DES 和 3DES 安全性低，存在安全风险，不推荐使用。
- 常用验证算法：MD5、SHA1、SHA2、国密 SM3。其中 MD5、SHA1 安全性低，不推荐使用。
- IPsec 的加密功能无法验证解密后的信息是否是原始发送的信息或完整。采用 HMAC（Keyed-Hash Message Authentication Code）比较数字签名进行数据包完整性和真实性验证。通常加密和验证配合使用：发送方对加密后的报文通过验证算法和对称密钥生成数字签名，与 IP 报文同时发给对端；接收方用相同算法和密钥得到签名并比较，验证不通过则丢弃，通过后再解密。
