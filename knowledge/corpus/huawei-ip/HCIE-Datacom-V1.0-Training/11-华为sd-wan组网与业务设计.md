# 华为SD-WAN组网与业务设计

## 1. SD-WAN 应用体验与安全概述

### 应用体验优化方案

从企业各种应用对网络的需求来看，传统 WAN 有以下问题：

- 不同价值的应用承载在相同链路上。
- 链路质量下降时应用不能动态选路。
- 链路质量劣化时缺少有效改善手段。

SD-WAN 解决方案针对以上问题，提出企业应用体验优化方案，包含：应用识别、智能选路、广域优化、QoS 等。基本流程：接收 → 应用识别 → 智能选路 → 广域优化 → QoS → 转发。

#### 应用识别与选路

华为 SD-WAN 通过 SA（Service Awareness）识别应用，并通过 SPR（Smart Policy Routing，智能策略路由）实现智能选路。SAC 通过 SA 与 FPI 识别应用并分组流量；SPR 基于探测报文确定链路质量从而决定转发路径。

#### QoS 与广域优化

华为 SD-WAN 通过 HQoS 实现带宽控制与调度，通过 FEC（Forward Error Correction）/ A-FEC（Adaptive Forward Error Correction）实现流量的广域优化。

- HQoS 基于多级队列实现层次化调度，不仅区分业务，也区分用户，实现精细化 QoS 服务。
- FEC/A-FEC 根据网络丢包情况调整相关参数生成冗余包，并由对端设备对数据报文进行校验和重组。

### SD-WAN 安全概述

SD-WAN 出现后，传统企业 WAN 的封闭式架构向开放式架构转变，扩大了攻击面，带来非法接入、数据泄露、网络攻击等新挑战。华为 SD-WAN 解决方案的安全从整体上分为两个层面：

1. **系统安全**：组件间安全与组件自身安全。
2. **业务安全**：防火墙、IPS、URL 过滤等。

#### 系统安全加固

组件间安全主要包括管理通道安全、控制通道安全和数据通道安全；组件自身安全主要包括 iMaster NCE 系统自身安全与 CPE 自身安全。例如：通过鉴权认证等保障 iMaster NCE 安全；使用 SSH 保障管理通道安全；使用 IPsec 保障控制通道安全与转发面安全；数据通道常用 GRE 或 GRE Over IPsec。

#### 业务安全（按流量）

1. **站点间互访业务**：主要通过 IPsec 加密实现。
2. **站点访问 Internet 业务**：可通过 EDGE 内置防火墙、IPS 与 URL 过滤实现。
3. **站点访问云应用业务**：站点对接第三方云安全网关，将企业访问 SaaS 云应用的流量发送至第三方云安全网关。

### 可视化运维概述

能力方向包括：快速获取异常流量、快速定位故障设备或站点、优化 WAN 投资及配置策略；告警实时监控、拓扑状态可视、45+ 自定义视图、自定义 Dashboard；基于站点、链路的拓扑展示；站点/链路/应用/设备/用户健康度视图；全网实时告警（分钟级）；企业实时获取站点、链路状态及性能信息（站点带宽利用率、TopN 应用流量、TopN 吞吐量站点、链路吞吐量趋势等）。

## 2. 华为 SD-WAN 使用场景

### 企业自建 SD-WAN

| 产品形态 | 功能 |
| --- | --- |
| SD-WAN 控制器 | 作为最核心部分，实现 CPE 设备统一管理、业务自动下发和 Overlay 网络统一控制 |
| RR | 分布式控制组件，基于 VPN 拓扑策略，负责 CPE 之间的 VPN 路由分发 |
| EDGE | 企业分支、总部、DC 等站点的出口设备 |
| GW | 负责连接 SD-WAN 网络和非 SD-WAN 网络的中间网关设备 |

SD-WAN（Software Defined WAN）：通过在 WAN 网络中部署 SD-WAN 控制器，集中管理 EDGE 设备，零配置开局，缩短业务开通时间，帮助企业应对云化带来的挑战，做到业务随需而变。像金融、零售连锁、加油站这类具有大量分支的大型企业，可以在企业总部部署 SD-WAN 控制器，组建企业 SD-WAN 网络，自助管理企业的 SD-WAN 业务。

### MSP 转售 SD-WAN

MSP（Management Service Provider）提供统一的 SD-WAN 控制器为多个企业提供 SD-WAN 服务；MSP 自建 PoP 骨干网，提供 PoP 点接入，企业可以就近接入 PoP 点，实现高品质企业互联。PoP 点支持多租户，可以同时为多个企业实现 PoP 接入。企业作为租户可管控本企业范围内所有站点的 SD-WAN 业务，但无法看到其他租户业务。

### 运营商转售 SD-WAN

运营商提供统一的 SD-WAN 控制器为多个企业提供服务。企业可作为租户租用服务并管控本企业站点，或托管给运营商。通过 SD-WAN GW 实现 SD-WAN 网络与传统运营商骨干网灵活对接，快速兼容。

### 本节小结

- SD-WAN 主要解决了多分支互联管理困难、建设和维护昂贵的问题，同时也能保障关键业务质量。
- 华为 SD-WAN 提供：零配置开局（1 小时内完成业务开通）、转控分离灵活组网、应用优化业务可控可视、完整安全防御体系、可视化运维快速定位故障。
- 使用场景主要有：企业自建、MSP 转售与运营商转售。

## 3. 华为 SD-WAN 组网设计

组网设计主要包括：站点设计、隧道设计与 VPN 设计。设计思路：

1. **站点设计**：WAN 侧网络设计、LAN 侧网络设计、双 CPE 互联设计、网络超规相关考虑。
2. **隧道设计**：RR 组网设计、数据隧道设计、NAT 穿越设计、拓扑相关考虑。
3. **VPN 设计**：拓扑设计、VPN 路由设计。

### 3.1 站点设计

SD-WAN 站点指部署了 SD-WAN 网络互连的站点，并统一被 iMaster NCE-WAN / iMaster NCE-Campus 控制器管理和监控。站点设计一般可分为：WAN 侧网络设计、LAN 侧网络设计、双 CPE 互联设计。

#### 部署原则

- 小型站点可部署单 CPE；可靠性要求较高的站点建议双 CPE，以提供设备级冗余。
- 通常建议 CPE 的 WAN 侧部署多条链路：相互备份提供链路级可靠性；同时便于后续基于业务选择主备路径，为业务提供差异化链路选择。
- 每台 CPE 最多可以部署 10 条 WAN 链路。实际部署时，综合可靠性与运维方便性，建议单 CPE 不超过 3 条 WAN 链路，双 CPE 时站点最多不超过 6 条 WAN 链路。

#### WAN 侧典型组网

- **单 CPE 多 WAN 链路**：中小站点或可靠性要求不高的分支可只部署单个 CPE，并部署多条 WAN 链路，将不同价值应用分布到不同链路。常见：一条 MPLS + 一条 Internet；MPLS 承载关键价值应用，非关键类应用使用 Internet。
- **双 CPE 多 WAN 链路**：大型或高可靠站点部署双 CPE，至少两条或以上 WAN 链路（如分别 MPLS 和 Internet）。双 CPE 之间需部署互联链路，避免单设备故障后无法转发数据。

#### WAN 侧 Underlay 路由

EDGE 的 WAN 接口支持部署传统静态路由、OSPF 或者 EBGP。具体采用哪一种，由 WAN 侧 Underlay 网络对接设备的路由部署方式决定，两边保持一致即可。现网使用时，静态路由没有协议交互，无法感知非直连链路的 WAN 网络故障，可能会造成业务中断。

#### LAN 侧网络设计

- **对接 L2 网络**：规模较小、内部结构简单时，CPE 通常通过二层方式连接站点内部网络。
- **对接 L3 网络**：可能提供直连、双归、口字型组网；按 LAN 设备要求配置相关路由协议。

单 CPE：

- SOHO 等小站点可通过 LAN 侧接口直接连接终端。
- LAN 侧接口不足时可在 CPE 下部署接入交换机，以单臂路由方式连接。

双 CPE：

- 通常在 CPE 上部署 VRRP，避免双 CPE 结构对 LAN 侧影响。
- LAN 侧 SW 可以多台堆叠；CPE 之间支持直接互连，也支持通过 LAN 侧网络互连。
- 直接互连时支持 Eth-Trunk；同时需要主备设备间建立互联链路，用于在设备间转发业务报文。
- 较大企业站点存在三层核心时，出口路由器需与三层设备对接，可通过直连、双归等方式，支持 BGP、OSPF、静态路由交换。

#### 双 CPE 互联（Interlink）

双 CPE 双链路组网下，若某条上行链路故障，需要 CPE 互联链路（Interlink）传递数据。Interlink 除用于站点双 CPE 间路由交互外，还用于同步关键信息，包括：链路信息、隧道连接信息、隧道连接的 SLA 信息、IPsec SA、应用识别结果信息等。这些信息使得站点内双 CPE 资源可被统一看待，以实现跨设备选路等业务场景。

推荐 Interlink 与业务链路分开：当 LAN 侧链路调整时互连链路不受影响，且业务流向清晰。

### 3.2 隧道设计

SD-WAN 解决方案中一共有三种隧道：管理隧道、控制隧道与数据隧道。控制通道主要在 RR 与 EDGE 之间建立，数据隧道主要在 EDGE 之间建立，最终承载业务的是数据隧道。隧道设计一般可分为：数据隧道设计、RR 设计、NAT 穿越设计、网络超规设计。

#### 关键概念

- 传输网络与路由域（TN/RD）主要用于枚举构建 Overlay 隧道。
- Site ID 主要作用是作为路由条目的下一跳。
- CPE Router ID 主要用于建立不同站点间的 BGP 邻居。
- TNP 主要用于隧道建立；TNP ID 可认为是接口编号；Public IP 与 Private IP 作为控制和数据通道的源/目的 IP。部分 CPE 置于 NAT 后，需知道 NAT 之后的 Public IP（一般通过 STUN 感知）。

数据通道建立时会进行隧道枚举，保证建立所有可用数据通道。先决条件：

- CPE 之间已经学习到对端站点的业务路由。
- CPE 之间已经学习到对端站点的 TNP 信息。

通道作用：

- 管理通道：建立控制通道以及下发基本配置。
- 控制通道：建立数据通道；DTLS（Datagram Transport Layer Security）主要用于保障数据安全传输相关能力（原文提及保障 TCP 数据安全，以控制面安全通信为背景理解）。
- 数据通道：传递用户数据。

TNP 信息一共会交互两次：控制通道建立阶段交互 RR 与 EDGE 建通道信息；数据通道建立阶段交互 EDGE 与 EDGE 建通道信息。

#### 隧道组网模型与可靠性

| 模型 | 说明 |
| --- | --- |
| 不同 RD | 站点双链路 Underlay 隔离，规划不同 RD，站点间建立两条隧道 |
| 同 RD 不同 TN | 站点双链路 Underlay 互通，规划相同 RD，站点间建立 Full-mesh 网络 |
| 同 RD 逻辑划分不同 RD | Underlay 互通但规划不相同 RD，站点间建立两条隧道 |

可靠性权衡：

- 不同 TN 规划到同一 RD：组网可靠性更高，但对设备虚拟连接资源消耗较大。
- 不同 TN 规划到不同 RD：减少连接数、扩大组网规模，但组网可靠性相对较低。

#### RR 部署建议

- 为避免站点网络调整影响 RR 稳定性，建议 RR 独立部署。
- RR 作为区域大脑，需部署高性能设备（参见版本规格清单）。
- RR 必须具有公网地址，或者在 RR 前面部署 NAT 设备；只支持 1:1 静态 NAT。
- 一个 Edge 站点最多连接两个 RR 站点；租户内部署的 RR 站点支持双 CPE。CPE 数量较多时可部署多个 RR，每个 RR 分别为一部分 Edge 服务。
- EDGE 连接到两个 RR 站点时，与每个 RR 站点内每个 CPE 均建立 BGP 连接。
- 若存在 Standby 链路：Active 正常时 Standby 不建立控制通道；所有 Active 到 RR 的链路 DOWN 时，Standby 参与控制通道建立。不推荐 RR 站点部署 Standby 链路。
- EDGE 较多超出 RR 控制规格时，建议分区域，每区域单独部署 RR，区域间 RR 建 BGP 邻居做路由交换。
- 需考虑各站点 LAN 侧路由总和，避免超过 RR 有效路由规格。
- 一个 CPE 最多支持连接到两个 RR 站点（4 台 RR 设备）。
- 规模较小网络（例如小于 50 站点）可采用 RR 与 Hub 站点共部署。
- RR 需要强大的 BGP 连接能力、EVPN Connection 数、路由反射能力与效率；实际部署需选择规格清单推荐款型（如 AR6300/AR6280 等）。

典型场景：

- **企业自建**：中小企业可用 RR 与站点共部署（Hub 作 RR）；大型高可靠客户推荐 RR 独立部署。
- **MSP**：RR 共享模式（多租户共享一台 RR）适合中小企业；RR 独享模式适合大企业。也可在租户内采用共部署、独立部署、多区域部署等方式。

#### NAT 穿越场景

- **EDGE 与控制器**：EDGE 主动向控制器发起注册，要求控制器南向地址 IP 可达。控制器若在 NAT 后，需在 NAT 上部署 NAT Server 并映射端口，例如：10020（南向注册）、10031（南向 HTTP）、18008/80（北向 Web）、18018（终端上传文件）、18021（文件服务器）。由于可部署 NAT Server，可认为没有 NAT 穿越问题。
- **EDGE 与 RR**：RR 部署时要求必须有公网 IP 或 1:1 静态 NAT，因此 EDGE 与 RR 通信可认为没有 NAT 穿越问题。
- **EDGE 与 EDGE**：站点间数据通道传输互访流量；当 EDGE 位于 NAT 后（尤其两端都在 NAT 后），需要使用 NAT 穿越技术（STUN）。STUN 定义见 RFC3489/RFC5389（前文已述）。

#### 组网规格计算（示例口径）

规划时需考虑 BGP 邻居数量、隧道数量、带宽等。示例：

- Hub/RR 的 BGP 邻居数 = 双网关站点数 × 2 + 单网关站点数（如 200×2+100=500）。
- Hub 隧道数 = Hub 双网关各自隧道之和；双 Hub 站点共享隧道规格（例如每 Hub 规格 1000，则双 Hub 共享这 1000）。示例 Hub 隧道数 = 300×4=1200。
- Hub 站点网络带宽 ≈ 分支站点数量 × 站点所需带宽（如 300×10 Mbps=3 Gbps）。
- 控制器可管理大量站点，一般在组网规格计算中无需太过关注。不同设备 BGP 邻居规格与隧道规格不同，以产品文档为准。

超规时可采用：

- **分区域组网**：租户下划分多个区域，总部/DC 内部署多个 Hub，每区域关联 1~2 个 Hub；分支按区域加入；RR 可独立部署；跨区域经 Hub LAN 侧绕行。
- **分租户组网**：MSP 创建多个租户，总部/DC 内部署多个 Hub，每租户关联 1~2 个 Hub；按地理区域对分支分组入不同租户；跨区域经 Hub LAN 侧绕行。

### 3.3 VPN 设计

通过 VPN 隔离功能实现单租户多部门间业务隔离，即每个部门网络分别是一个独立业务 VPN。VPN 设计一般可分为：VPN 设计、拓扑设计、VPN 路由设计。

#### SD-WAN VPN 介绍

每个 VPN 是一个独立的 IP 三层私有网络。多个不同 VPN 端到端从连接站点的 Tunnel 到站点的 CPE 设备，都实现逻辑隔离，互相无法直接访问。

- 每个 VPN 可以拥有独立拓扑，支持 Full-mesh、Hub-Spoke、Partial-mesh、分层组网。
- 每个 VPN 可以独立进行业务策略配置，如选路策略、QoS 策略等。

#### VPN 规划建议

- 根据业务隔离诉求规划部门数量（如研发部、财经部、市场部等）。
- 规划不同部门所需 LAN 侧物理接口、VLAN：可独立物理接口，也可共用物理接口通过 VLAN 隔离。
- 规划初始相关策略：选路策略、访问 Internet 策略、QoS 策略、与传统网络互访策略以及 URL/IPS/FW 策略等。

#### 拓扑类型

- **Hub-Spoke**：总部和数据中心作为 Hub，分支作为 Spoke；分支互访也经 Hub 中转。适用于以分支到 Hub 为主要互访业务的企业（如连锁门店主要访问总部/DC，门店间几乎无协同互访）。
- **Full-mesh**：分支间存在业务互访则直接交互，不经中间节点。适用于站点规模不多的小企业，或分支间需协同（VoIP、视频会议等）的大企业；组网简单、互访效率高，扩展性一般，适用于约 10~100 个分支。
- **Partial-mesh**：可看作特殊 Full-mesh；Underlay 可直连则直连，否则经共同连接的逃生/中转站点（Redirect）互访。可用于 Underlay 无法直连，或 Full-mesh 下为可靠性部署 Redirect 备份路径。
- **分层组网**：单层模型叠加；WAN 划分多区域，经集中骨干区域互联，实现海量站点跨区域互访。适合站点规模庞大或跨国分散企业，结构清晰、可扩展性好。

#### VPN 路由设计

本端 CPE 的 VPN 路由通过 LAN 侧路由协议收集后，通过 WAN 的 BGP EVPN 协议发送至对端 CPE。

- **LAN 侧路由**：支持静态、OSPF 或 BGP，与 LAN 侧对接设备保持一致。
- **WAN 侧 Overlay 路由**：一般部署 BGP EVPN，和 RR 建立 BGP 邻居，实现 Overlay 域路由传播（系统自动编排）。
- LAN 侧与 WAN 侧路由可通过路由策略控制过滤。

### 组网设计小结

- **站点设计**：主要包括 WAN/LAN 网络设计与双 CPE 设计。
- **隧道设计**：主要包括数据隧道设计、RR 设计、NAT 设计与网络超规设计。
- **VPN 设计**：主要包括 VPN 设计、拓扑设计与 VPN 路由设计。

## 4. 华为 SD-WAN 业务设计

业务设计主要包括应用业务设计与网络业务设计。

### 4.1 应用业务设计

企业应用种类繁多（生产类、协同类、娱乐类等），对带宽和链路质量要求各不相同。应用业务设计一般可分为：智能选路设计、QoS 设计、丢包优化设计。

#### 应用识别流程（SAC）

五元组命中已识别应用则直转发；否则进入 SAC：FPI ACL → FPI DNS 关联表 → FPI 协议端口表 → SA。

#### 智能选路：链路质量选路

不同应用对链路质量要求不同，例如语音和视频对时延、丢包率容忍较低（时延一般要求 150 ms 以内，丢包率低于 1%）。可将语音和视频主选链路配置为质量较好的 MPLS，备选为 Internet，并配置业务 SLA，按链路 SLA 选路；链路质量下降时可动态切换。

#### 智能选路：负载分担选路

多链路场景希望充分利用带宽时，可配置负载均衡选路。例如语音业务主选两条 MPLS；在两条链路质量均满足 SLA 前提下负载分担，通过实时带宽利用率监控（如达到 85% 以上）充分利用线路带宽。

#### 智能选路：应用优先级选路

同一链路上有多种业务时，拥塞时优先保证高优先级应用，低优先级避让。例如语音、视频与文件传输都在 MPLS 上，带宽不够时优先保证语音和视频；低优先级流量可切换到其他链路。

#### QoS（多部门）

企业通常有多个部门，既要隔离各部门流量，又要对各部门提供不同带宽：

- 保证不同部门基础带宽配额。
- 部门未占满配额时，“空闲”带宽可被其他部门使用。
- 部门上网或访问传统站点的流量需要被单独限制。

#### 丢包优化（FEC）

FEC（Forward Error Correction，前向纠错）可在发送数据时增加携带校验信息的冗余包，并在接收端校验；若出现丢包或报文损伤，则通过冗余包还原。

两种模式：

- **A-FEC（自动调整冗余率）**：CPE 自动检测网络丢包率并实时调整冗余包数量。丢包少时减少冗余节约带宽；丢包升高时增加冗余。但丢包率突然升高很多时，感知并调整需要一定时间，会出现短暂丢包。
- **D-FEC（固定冗余率）**：根据配置的网络丢包率计算冗余包数量。可在配置的最大丢包率范围内还原丢包；冗余度比 A-FEC 多，但丢包率突然变化时不会丢包。

部署后可从控制器查看优化前后效果，帮助判断 FEC 设计是否合理。

### 4.2 网络业务设计

SD-WAN 站点除与系统内网络互通外，还需与互联网或传统站点互通。网络业务设计一般可分为：访问互联网设计、传统站点互访设计。

#### 访问互联网方案

主要场景：

1. **本地上网**：站点上网流量从本地 EDGE 直接出局。
2. **集中上网**：所有站点上网流量绕行至集中上网站点后出局。
3. **混合上网**：
   - 默认本地上网 + 备选集中上网：默认本地出局，本地接口故障时绕行集中网关。
   - 默认集中上网 + 指定流量本地上网：默认经集中上网站点出局，部分指定业务本地 WAN 侧直接上网。

注意：

- 上网不支持多条链路负载分担组网，只能支持基于优先级主备。
- 基于指定应用流量的本地上网需要和集中上网同时使用，内部通过编排策略路由实现。
- 开启本地上网时，Underlay WAN 侧默认路由需单独配置：可为静态（主要 Internet 类型接口），也可通过 BGP/OSPF 动态学习（主要 MPLS 类型接口）。

**集中上网设计**：适用于站点没有访问 Internet 的链路，或需对上网流量集中安全管控的场景。所有站点通过一个集中上网站点出局；集中网关站点二选一：

- LAN 侧有 Internet 出口，上网流量经 LAN 侧出局（LAN 侧配置默认路由或动态学习默认路由）。
- 通过 WAN 侧接口上网（作为集中网关的站点需同时开启本地上网功能）。

**混合：默认本地 + 备选集中**：适用于规模较小或无需集中安全管控、WAN 侧有 Internet、对上网可靠性要求较高的场景。同时配置本地与集中上网；本地默认路由优先级更高；本地故障时绕行集中网关。

**混合：默认集中 + 指定应用本地**：适用于需对大部分上网流量集中安全管控，部分应用因 SLA 可本地出局的场景。集中上网站点开启本地上网（全部流量本地）；其他站点开启本地上网但配置为指定应用本地出局。

**互联网访问链路可靠性**：以站点为单位设置，每个站点最多可设置三个 WAN Link 作为 Site to Internet 接入链路。每个 WAN Link 有 Link Priority，优先级不可相同，同一时刻只有一个激活链路；高优先级故障时自动切换至次高优先级。备份链路与混合上网方式可同时使能。

#### 传统站点互访

企业部署 SD-WAN 前可能已存在通过传统 WAN 专线（如 MPLS）互联的传统站点。SD-WAN 与非 SD-WAN 站点互访方案一般有：

1. **通过企业站点互访**
   - 基于专用线路互访（Dedicated link）：在传统 CPE 与 SD-WAN CPE 用户侧接口互联，运行 BGP/OSPF 等交换路由，集中互联。
   - 基于本地互访：
     - **分布式本地互访**：所有 SD-WAN 站点可通过 Local Breakout 到 Underlay MPLS 访问传统站点，互访流量本地直接转发。
     - **集中式本地互访**：部分站点无法本地 Breakout 时，选一个能互访的站点作集中互访站点，其他站点先经 Overlay 到该站点再 Breakout。
     - **混合式本地互访**：多链路分布式站点可本地优先、集中备份；本地 MPLS 故障时经 Overlay 到集中互访站点再转发。

2. **通过 IWG 互访**（运营商为多企业提供服务时更经济）
   - 基于 Option B 跨域方案互访
   - 基于 L3 VXLAN 的 Option A 跨域互访
   - 基于 L3 VLAN 的 Option A 跨域互访

一套 IWG（Interworking Gateway）系统能同时为多个企业租户提供 SD-WAN 站点与已有传统 MPLS VPN 站点的连通服务；无论多少用户，只需配置一个 MP-BGP 邻居和对端 ASBR-PE 对接。

**Option B**：IWG 与传统网络 ASBR-PE 之间通过 MP-EBGP 交换各自 AS 的 PE 收到的标签 VPN-IPv4 路由；配置一对公共接口使能 MPLS，运行 MP-EBGP，域间标签由 BGP 携带，无需运行 LDP。

**Option A（L3 VXLAN）**：IWG 与 ASBR-PE 通过 L3 VXLAN 隧道对接，在隧道两端建立 eBGP 或 iBGP，互相学习 SD-WAN 与传统站点路由。

**Option A（L3 VLAN）**：在 IWG 与传统 MPLS PE 之间为每个用户 VPN 配置一对特定接口（VLANIF 或以太子接口）并加入相应 VRF，配置基于 VPN 实例的 EBGP，交换两边路由。

### 业务设计小结

- **应用业务设计**：智能选路设计、QoS 设计、丢包优化设计。
- **网络业务设计**：访问互联网设计、传统站点互访设计。

## 5. 华为 SD-WAN 可靠性与安全设计（概览与站点可靠性开头）

可靠性与安全设计主要包括：站点可靠性设计、控制器可靠性设计与安全设计。

设计思路：

1. **站点可靠性**：Hub 站点、RR 站点、IWG 站点可靠性设计。
2. **控制器可靠性**：控制器部署可靠性、控制器组网可靠性。
3. **安全设计**：系统安全、业务安全。

### 站点可靠性设计全景

SD-WAN 站点一般可分为 Edge、Hub、RR 以及与传统网络互联的 GW 站点。Hub、RR 与 GW 属于关键站点，其可靠性会极大影响整网可靠性。

#### 多活 Hub 组网

- **基于业务网段的多活 Hub**：分支访问数据中心可按不同业务网段区分时，可实现基于业务网段的双 Hub 双活，不同业务关联不同主备 Hub。
- **基于 Spoke 站点的多活 Hub**：企业广域分布广、两个数据中心距离较远时推荐。在异地多个数据中心部署 Hub，Spoke 关联多个 Hub，以距离较近为主、较远为备，获得较好的数据中心业务访问体验。
