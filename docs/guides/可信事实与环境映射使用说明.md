# 可信事实与环境映射使用说明（V7-B）

适用范围：工作台 `设备` 页的“只读观察”、`环境映射` 页（管理员）、配置下发/审批的既有确认流程。本文只讲 B 新增能力，不替代 C 的助手教学和 D 的规则扩展。

## 1. 环境映射（管理员）

1. 进入 `设备与变更 → 环境映射`，点“新建环境”。
2. 填名称、版本、站点；每个设备映射填设备、角色（如 R1/R2/R3）、接口地址（如 `GigabitEthernet3/0/3=10.0.123.1/24`）。
3. 保护项每行一项（如 `mgmt_port=GE0/0/0`、`uplink=GE3/0/3`）。
4. 保存后点“预检”。状态含义：
   - `ready`：当前已知映射/状态一致，**不等于**设备已验证通过；
   - `mismatch`：缺角色/接口/保护项，或环境仍为草稿；
   - `unreachable`：设备离线/不可达；
   - `busy`：存在部署写锁，先处理/恢复任务；
   - `unknown`：信息不足。
5. 预检只读，不会自动补映射，也不会改设备。

R1/R2/R3 的地址/接口是接收方现场映射，不要把仿真默认值当全局默认；不同版本的环境应分别建版本。

## 2. 只读观察（普通用户）

1. 进入 `设备`，在目标行点“只读观察”。
2. 选择固定动作之一：接口状态与地址、OSPF 邻居、OSPF 路由；可选归到某个环境。
3. 点“采集只读事实”。服务端使用固定命令，不接受任意命令/换行注入；结果记录来源 `server_observed`、完整性、解析器版本和受控原文。
4. 结果为空/失败时按“证据不足”处理，不要据此判断通过。OSPF 空返回会显示 `empty`，规则返回不足，不会因出现 Full 就通过。
5. “与本环境预期比对”只在有完整、新鲜证据时给结论；不足/过期会明确显示。

## 3. 设备锁与终端

部署任务确认后会取得设备写锁；存在锁时终端会拒绝连接并提示占用。锁状态可在 `/api/v1/trust/locks` 查询（`recovery_required` 表示需要先确认上一次结果）。不要在未确认恢复前手工删除锁记录。

## 4. 实训连续任务

实训会话内打开“连续任务 · 笔记与步骤”，可保存笔记、勾选步骤。刷新/重开会话会恢复；其他页面同时改会提示冲突。已结束的会话只读，需要重练请新开会话。

## 5. 边界

- 只读观察不写设备；配置变更仍走原有草稿→确认→执行→验证。
- 真实设备上 OSPF 未配置时，空证据是正确结果，不是系统失败。
- 现用库未迁移；B 只在隔离环境验证。
