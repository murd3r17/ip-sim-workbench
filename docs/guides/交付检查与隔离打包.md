# V7.0 交付检查与隔离打包

适用任务：维护审查 R12。交付准备与本机环境初始化是不同操作。以下脚本不调用真实设备、不沿用源工作区 `.env`，不自动运行旧的在线全链路验证脚本。

## 只读检查

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deliver-check.ps1 -Mode minimal
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deliver-check.ps1 -SourceRoot <准备目录> -Mode minimal
```

只枚举实际交付文件、检查编码和依赖锁文件、扫描敏感内容、核对准备证据。不会安装依赖、构建、初始化数据库、启动服务或生成日志。未跟踪的源码也进入清单；检查不依赖 Git 索引。

退出码：`0` 所选模式的全部门禁通过；`1` 存在失败；`2` 未完成（缺少证据、证据对应的文件已变化或检查被跳过）。`-SkipSlow` 兼容旧命令，但不会把缺失证据改成通过。

## 隔离准备

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare-delivery.ps1 -Mode minimal
```

准备脚本复制源码到新的 `.runtime/delivery-stage-<随机标识>`，复用本机 Python 虚拟环境解释器，并复制已安装的前端依赖。需要提前按锁文件安装依赖；准备脚本不联网安装，也不会覆盖源目录的 `dist`。前端类型、Lint、交互契约测试与生产构建、后端隔离单元测试、独立 SQLite 初始化、模拟设备/实训样例播种及最小模式验收均有独立结果。

单元测试禁用 `.env` 读取，由各测试的模拟器或假 SSH 决定分支。集成验收固定使用 `DEVICE_MODE=sim`、本地知识库和准备目录下的独立 SQLite。临时测试目录也在准备目录内。测试和构建失败会阻断交付，运行详情留在准备目录的 `.runtime/logs`。

准备目录的 `.env` 只含新生成的临时认证材料与隔离配置，供本地验收使用，永不进入压缩包。启动该副本时应清除外部同名环境变量，避免它们覆盖副本的隔离设置；可使用独立端口，例如 `18080`。准备脚本本身不启动持久服务。

`minimal` 门禁还要求该副本的严格浏览器验收。准备阶段先通过 Playwright `--list` 登记完整测试 ID 集合，不执行浏览器操作；准备结束后先返回 `INCOMPLETE`。在副本启动独立服务、执行完整 Playwright 套件并导出 JSON 后，通过以下命令登记。报告必须属于该副本的 `sim-frontend/e2e`，测试 ID 集合须完整一致，全部测试结果成功且失败、跳过、不稳定测试和全局错误均为零，副本文件摘要仍须匹配。过滤子集或分片报告不能冒充完整验收。

```powershell
backend/.venv/Scripts/python.exe -B scripts/delivery.py browser --root '<准备目录>'
```

命令从工作区根运行，使用已安装的 Playwright 浏览器和暂存目录的临时账号。在随机回环端口启动此副本，核对模拟模式和源码根身份，运行 V7 浏览器清单，记录报告并停止该次进程。V7 清单覆盖角色、页面、设备观察、拓扑、知识原文、模拟下发、实训恢复和助手取消。仓库仍保留 V6 浏览器脚本，使用 `E2E_PROFILE=legacy` 选择旧清单。

`minimal` 只证明离线模拟闭环。`full` 还要求独立 MySQL、外部知识库/模型服务、浏览器 WebSSH 的现场证据；本脚本不会自动连接这些服务，因此未完成相关独立验收时会明确返回 `INCOMPLETE`，不会把 SQLite 或模拟终端结果当成完整环境验证。

## 扫描与导出

```powershell
backend/.venv/Scripts/python.exe -B scripts/delivery.py scan
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/package-delivery.ps1 -PreparedRoot <准备目录> -Mode minimal
```

扫描和打包共用清单。包含当前业务源码、运行脚本、当前 Markdown 文档、知识语料、前端 `dist` 和两端锁文件；排除 `.env`、Git 历史、虚拟环境、依赖安装目录、运行数据/日志、上传目录、私钥文件、旧计划及测试源码。测试源码仅进入隔离准备目录，避免把不随包交付的虚构测试值误判为交付凭据。

规则覆盖字面量口令/密钥、环境变量值、凭据 URL、常见访问令牌、设备配置口令和私钥块。只输出文件、行号、规则，不输出命中的值。扫描只能识别已定义规则，不能替代对交付内容的人工复核。

经本次维护授权，复制后的教材/文档中固定示例秘密会替换成 `<REDACTED>`，保留正文；原始文档不变。业务源码不会自动脱敏，硬编码命中直接阻断。`DELIVERY-REDACTIONS.json` 记录变更路径和规则；`delivery-evidence.json` 分开保存复制前后的内容摘要。未能完整识别的私钥块仍会阻断，避免仅去掉标记后泄露内容。

仅证据对应的文件完全匹配且所选门禁全部通过，才会在准备目录 `.runtime/delivery` 导出 ZIP。`dist/assets` 内的 JS/CSS 也全部纳入；检查会核对入口页引用的资源存在。包内附 `DELIVERY-MANIFEST.json`，逐文件记录 SHA-256；导出前后再核对内容，成功后才将 `.partial` 定稿成 ZIP，防止检查后文件被修改。准备期间源码仍有修改时，应重新准备最终副本。

E 阶段通过本地工程门禁后，可使用 `-Mode candidate` 导出含 full 配置、初始化和运行脚本的工程候选。包内的 `DELIVERY-SCOPE.json` 会标明 F 完整联调待完成。正式 full 导出仍使用 `-Mode full`，按完整现场证据验收。

## 收件方初始化

`bootstrap-local.ps1` 是有写操作的显式环境准备入口。`minimal` 强制 SQLite/sim，本地旧库升级前默认备份到 `.runtime/backups`；`full` 不播种模拟设备或实训数据。可用 `-BackupDir` / `-BackupFile` 向数据库初始化程序提供备份参数，已有库的升级规则由迁移程序校验。

安装依赖失败、前端构建失败、任一步播种失败或启动超时都会失败退出。初始认证信息只写入接收方本机 `.env`，不回显到交付日志。不要把接收方运行后的目录重新整体压缩作为交付包，应重新走清单导出。

新建 `minimal` 环境时，模型和远程知识库密钥留空，模型地址设为本机不可用占位端口，不会携带模板占位密钥请求外部模型。AI 生成功能由接收方另行配置模型后启用；离线检索仍使用随包知识语料。已有 `.env` 保持不变。直接使用 Python 初始化入口时，必须先设置本机 `ADMIN_PASSWORD`；空值会在迁移或创建账号前失败退出，不再随机生成并打印口令。
