## 1. 版本定位与决策摘要

V7.0 是面向网络维护初学者、也能支持熟练用户的网络工作台。主要价值是把实际维护工具、可信网络事实和可解释的对话助手连在一起，帮助用户在真实任务中理解、排查和复盘。无需先进入课程体系。

现有设备、SSH、配置校验、受控下发、回读、监控、审计与实训底座继续复用。优先修复明确缺陷、改善信息组织与助手质量，不重写所有正常运维能力，不扩建大量课程。

1. 统一工作台首页与导航，不保留独立或可选学习入口；实训、知识库仍可从普通工具菜单访问。
2. 系统改造布局、视觉、按钮与流程；保留技术基础，不保留不合理的页面结构。不能只换颜色与圆角。
3. 右侧助手贯穿全站：理解页面、选中对象、任务及有效环境；按权限读取事实，关联教材并处理多轮追问。可以修改前后端与检索链路。
4. C 批独立聚焦助手；B 先交付其所需的环境、证据、权限与只读接口，D 再扩充规则覆盖和全站整合。
5. 完成操作、现场状态满足与理解原理分别记录。模型评价、历史参考分或检索相似度均不等于正确性证明。
6. 用户可要求简明回答、展开原理或引导排查；不强迫每次先答理解题。写入草稿仍进入原有校验、人工确认和恢复流程。
7. 校对现有实验和语料；只在既有任务无法覆盖入门观察时增加最多两个短只读任务，放在原实训工具内。
8. 完整交付仍要求真实 DeepSeek、知识服务与三台真实设备。接收方填写自己的凭据并首次配置后运行；离线演示不替代 full 验收。

## 2. 原设计实现程度与本版变更依据

### 2.1 不能给出“全部实现”的结论

原仓库完整设计与当前 `项目设计方案V6.0.md` 内容一致；详细开发计划仅有 11 处文档路径调整。后续修改主要沉淀在补充计划、环境上下文和交付报告中。因此当前代码、原设计和维护决策并非一份同步的产品契约。

本轮审查覆盖 16 个登录后的业务/管理页面，在 1102×1004 视口使用管理员账号，实测 R2 只读 SSH、三台拓扑校验、三台监控采集、AI 提示与复盘、知识检索、配置非法输入校验及历史任务查看。没有重演真实写入、普通学员权限或全新安装。逐项要求及证据等级见审查报告 §4。

| 维度 | 当前判断 | V7.0 处理 |
|---|---|---|
| 运维主链路 | 主要能力存在，已有受控真实执行历史证据 | 保留并做有针对性的回归 |
| 原设计所有细项 | 未完全满足：拓扑完整性、资料导入/阅读/引用、差异展示、部分结构化契约仍有缺口或偏离 | 明确保留、修复、收窄和暂缓项，不报笼统完成率 |
| 初学者使用与助手 | 有实验与教练，但全站感知、事实依据、连贯操作和解释不足 | 统一工作台与助手专项共同处理 |
| 使用体验 | 多处真实可复现问题，不是视觉润色即可解决 | 优先修错误语义，再统一布局与交互 |
| 交付 | V6.0 有约定边界内的 Windows 单机验收 | V7.0 新候选必须补首次配置、知识初始化与普通学员路径 |

## 3. 用户、学习目标与范围

### 3.1 用户角色

| 用户 | 需要解决的问题 | 入口与能力 |
|---|---|---|
| 初学者 | 不知道看什么、输出含义、何时算成功 | 统一首页、按权限开放的工具、右侧解释/只读协作、自己的记录 |
| 进阶学习者 | 在受控条件下配置与排障 | 同一导航，被授权实训、变更草稿、确认及核验 |
| 教师/管理员 | 准备环境、保护设备、检查内容与证据 | 管理菜单、环境映射、授权查看/导出；不扩建班级系统 |
| 熟练运维人员 | 快速访问设备、拓扑、告警与任务 | 同一导航，助手可收起或简明回答；保留直接操作路径 |

熟练程度、回答深度、设备操作模式和后端权限是不同维度。用户偏好不改变授权，后端继续执行对象归属、角色和危险操作检查。

### 3.2 可观察的学习目标

- 能从设备接口信息中区分管理口、业务口、未使用口，并解释观察到的状态。
- 能根据拓扑和地址判断应该检查哪台设备、哪个接口、哪条邻居关系。
- 能先收集证据，再提出假设，不把所有 down 端口都当故障。
- 能比较操作前后状态，指出哪些观察支持“已经恢复”，哪些还不能确认。
- 能说清一次变更的目的、影响、恢复办法与限制。

“运行过命令”只能证明操作发生；“当前状态正确”不一定证明是用户配置造成；“AI 说做得好”不能作为技能通过证据。

### 3.3 内容边界

保留并校对当前全部实验。先完成一个 OSPF 维护实验的完整纵向闭环，再将其模板应用到其余实验。BGP/MPLS 等设置先修要求与“进阶”标签，未绑定有效环境的实验标为“需准备环境”，不能仅凭发布状态显示可立即运行。

两种基础观察目标为：①识别真实设备、接口与地址；②从接口/邻居/路由信息收集一次排障证据。优先复用现有任务；确有缺口才新增最多两个各约 10–20 分钟的只读任务，仍放在既有实训工具内。不得编造硬件环境或制造故障作为入门前提。

## 4. 核心用户旅程

### 4.1 第一次使用：从工作台观察网络

接收方完成配置 → 登录统一首页 → 看环境/采集时间/设备概览 → 选择设备 → 从右侧问“这个接口状态是什么意思” → 按权限执行一次只读检查 → 看字段解释与引用 → 保存并重新找到这次证据。

可由现有实训提供明确观察目标，但不得将进入课程或学习页面作为使用设备工具的前置条件。依赖故障与用户操作错误分开；阅读旧资料或示例必须明确标识，不能静默替换真实结果。

### 4.2 连续排查：对话与工具协同

用户从设备、拓扑或告警页提出问题 → 助手说明当前对象和已有事实 → 必要时调用允许的只读工具 → 给出有证据的判断、仍未知的部分和下一项最小检查 → 点击证据定位到实际页面 → 追问或切换对象 → 保存记录。

“R2 为什么访问不了 R3”不能只得到通用教材，也不能在没有证据时得到确定故障结论。“那 R3 呢”“和刚才相比呢”必须使用正确对象和可比较的时间点；页面选择与对话对象冲突时显式澄清，不悄悄改目标。

### 4.3 受控实操与实训

查看基线 → 说明预期变化 → 生成/编辑草稿 → 静态校验 → 确认设备、差异和恢复方案 → 按角色授权执行 → 回读核验 → 必要时恢复 → 持久复盘。

实训仍在普通工具菜单内，任务详情/步骤/笔记与共享助手协作，不另建“学习工作台”。用户自愿选择分级提示或理解题；直接提问可直接回答。复用既有部署、审批、锁、审计、快照及恢复逻辑，不建立绕过确认的 SSH 写通道。

## 5. 信息架构与界面设计

### 5.1 唯一首页与导航

工作台为唯一默认首页。导航建议按任务分组：工作台；网络（设备、拓扑、监控、告警、终端）；变更（配置、审批、版本/任务）；工具（实训、知识库）；管理（系统、审计等，按角色提供）。不是新造所有页面，也不是复制一套运维导航。

首页主区域展示紧凑环境摘要、可操作网络概览、需关注事项和继续上次工作。状态必须有来源与时间，未采集不显示正常。只显示少量必要统计，避免同权重 KPI 卡片墙。首页可以把“了解当前网络”“分析当前问题”作为助手的快捷提问，但不设置“开始学习/学习中心”入口或推荐课程区。

既有实训与资料从工具菜单正常访问；实训专用记录在实训工具中查看，已有对话从助手历史查看。无权限说明与后端授权一致，深链接继续可达或有明确兼容重定向。

### 5.2 视觉和布局标准

采用克制的专业桌面工具风格。先完成浅色主题：浅灰工作区、清晰白色内容面、深灰文字、单一低饱和蓝色强调；状态色只表达状态和风险。现有深色若保留须一并验证，不能只留下失效切换按钮。具体色值在 B 原型中按对比度确定，不再要求用户提供旧首页参考图。

字体建议正文 14px、辅助 12–13px、标题 20–24px；间距以 4/8px 为基础；表格密度一致。代码/终端使用适合中文混排的等宽字体。减少重复卡片与边框，不以装饰插画、渐变大标题和图标墙占据工作区域。这些是实现起点，不能用固定尺寸牺牲可读性。

先做统一首页、设备排查、配置变更三个真实页面原型，覆盖助手展开/收起、长内容、错误/空态。记录真实读图和取舍后实现，不能交三张概念图便称 B 完成；用户已授权设计方向，常规原型迭代在批内连续推进。

- ≥1440px：助手可停靠并调宽，主操作区建议至少 640px；复杂终端/拓扑可专注展开。
- 1024–1439px：按需要折叠次级区域，助手用可切换面板，避免与表格同时挤压；1102px 必测。
- <1024px 与 200% 缩放：优先保证阅读、导航和主要动作可达；必要二维终端/拓扑可专用展开，不豁免整页溢出。
- 引用阅读、助手和当前设备证据应可交替或并排查看；返回保留焦点、滚动与选择，切标签不重连终端。
- 对话可收起、调整宽度或展开专注视图，但不新增第二套聊天数据和路由业务。

普通文字对比度至少 4.5:1，大字至少 3:1；键盘可到达主要动作、独立关闭控件和返回路径。这些是本项目验收目标，工具/视口能力不足必须如实标未测。

2026-10-26 用户新增：全部前端以实际全屏/最大化为主验收标准，同时适配不同窗口宽高比。页面应合理利用可用区域，连续改变宽高/比例再恢复时保持输入、选择、对话与终端状态；助手和主任务不互挡。详见 [前端全屏与窗口拉伸验收规范](../plans/v7/前端全屏与窗口拉伸验收规范.md)，不能用固定预览、CSS/DOM 检查或仅视口模拟替代实机全屏结论。

### 5.3 动作清单与按钮治理

B 先盘点所有实际业务页面的动作：名称、用户目的、路由/API、副作用、适用状态、角色、模型/网络成本、可恢复性、重复入口和去向。逐项保留/合并/移入详情/删除冗余入口；只删除已确认重复的入口，不删除业务能力或历史数据。

普通区域默认一个主要操作、少量次要操作，低频动作放入有名称的菜单；终端/编辑器工具栏按真实任务需要设置，不机械限制数量。重要禁用动作说明条件，不能全靠悬停提示或要求先问 AI。

| 原动作组 | 新组织方式 | 不得混淆 |
|---|---|---|
| 开始/继续/再次练习/模式 | 按状态突出开始或继续，其他放次级入口 | 恢复会话与新建不同；教学偏好不改变设备模式 |
| 查看/生成/重生成/导出复盘 | 一个复盘入口，内部展示报告与显式生成动作 | 查看不能偷偷触发模型；重生成保留旧版本 |
| 刷新/采集/核验 | 分别说明缓存刷新、现场读取与规则判断，可组成检查流程 | 不用模糊“检查”按钮冒充所有动作 |
| 确认/执行/验证/恢复 | 按变更状态显示当前可用步骤 | 人工确认不能被合并绕过；取消不等于撤销设备变化 |
| 删除/导出/原始详情/管理 | 清楚分组的菜单与详情层 | 保留权限、风险说明、必要确认和可发现性 |

### 5.4 页面状态与解释

区分加载、空数据、未采集、依赖不可用、无权限、失败与陈旧数据；未返回不先显示零/正常，未知大小不显示 null B。主错误提供对象、原因和可执行下一步，原始 JSON/动作码留在可发现的高级详情。

术语和重要字段有简短说明；复杂解释交给右侧助手，页面自身仍能独立完成核心操作。助手失败时设备/配置等核心流程可继续。

## 6. 环境绑定、操作模式与设备安全

### 6.1 环境清单

增加版本化的实验环境定义，至少包含：环境 ID、版本、设备角色到实际设备 ID 的映射、厂商/系统信息、接口名称、预期地址/掩码、管理口与禁止修改项、拓扑关系、纳管状态、预期活动端口、所需能力、核验规则及检查时间。

当前现场参考是 R1 业务口 GE3/0/3、R2/R3 业务口 GE3/0/4、LoopBack0 为 10.0.0.1/2/3；这些来自当前实验 seed 与抽样回读，**不能作为所有接收方环境的常量**。导入时由管理员映射，开始任务时再进行只读核对。

S1 或广播网段可作为未纳管对象表达，只记录已知逻辑连接及来源。不得伪造发现结果、LLDP 邻居或设备可达状态。静态预期、手工登记、实时发现用不同样式和时间标识。

环境检查结果为 `ready / mismatch / unreachable / busy / unknown`。未知不自动算通过；缺少写入目标映射、保护端口信息或恢复前提时禁止生成可直接执行的草稿，并说明缺失项。读取观察不需要等到所有进阶实验环境就绪。

### 6.2 模式矩阵

| 运行模式 | 数据与模型 | 设备行为 | 必须显示的提示 |
|---|---|---|---|
| 离线演示 | 明确的示例数据/本地资料，模型能力单列 | 不连接真实设备 | 演示结果不能证明真实设备通过 |
| 联网只读练习 | 真实 DeepSeek、资料与现场状态 | 后端允许的只读动作 | 真实设备，仅执行允许的读取动作 |
| 联网受控实操 | 真实模型与现场状态 | 经权限、校验、人工确认的写入 | 目标设备、影响、差异、恢复条件 |

“引导实验/自由练习”是教学组织方式，和上述设备操作模式是两个维度。没有设备实例隔离时，不使用“安全沙箱”的名称。仅有 `DEPLOY_SIMULATE_ONLY=true` 不能证明交互 WebSSH 不可写。

### 6.3 只读与原始终端

初学者只读模式使用后端结构化命令动作：动作 ID、目标、有限参数、输出与证据。设备类型对应命令由既有允许列表和适配器生成；拒绝分隔符、换行注入、任意原文透传。

原始交互 WebSSH 保留给明确授权的高级用户。不能用前端正则过滤假装提供可靠只读终端。若启用原始终端，必须准确标记真实连接、会话归属、操作审计和写入风险；受控实验的写权限与设备占用必须遵守同一套后端策略。

### 6.4 共享设备与恢复

三台设备是共享资源，多个学员不能同时进行会互相干扰的写实验。复用已有设备锁，扩展会话归属/租约信息，不另做互不知情的第二套锁。只读操作按既有设备连接能力限制并发。

任务结束不等于配置已恢复。已改变设备的任务必须显示恢复状态与证据；恢复失败保留占用/异常标记并交管理员处理，不自动释放后允许下一人继续。会话心跳丢失不触发未经确认的破坏性恢复，也不能误停其他工作区服务。

“故障场景记录”只提供题目与假设。真实故障构造若未来纳入实验，必须使用已有部署流程、限定目标和恢复方案，另行批准具体操作窗口；本设计不授权实施。

## 7. 实验版本、进度与可信核验

### 7.1 内容结构

每个实验包含稳定 ID、内容版本、目标、先修要求、预计时间、支持环境版本、步骤、每步预期观察、只读检查动作、允许的变更范围、失败说明、恢复条件及引用。发布前检查文本、命令、地址和验证规则的一致性。

同一实验的精简版与完整版应共享参数和规则；差别只在说明深度，不能各自写一套接口/地址。教材原文保持原样，页面明确标出“教材示例”和“本实验现场映射”。已开始会话固定使用当时实验版本，内容更新不能悄悄改变历史任务。

### 7.2 会话与步骤状态

会话使用明确的 `created → active → paused/completed/abandoned` 状态；环境错误单独记录，不把错误等同学员失败。只有 active 且归属合法的会话可绑定终端与操作记录。completed/abandoned 默认只读；再次练习新建会话，不能重用旧会话污染证据。

每步分别保存：用户声明完成、观察记录、核验尝试、结果和解释。页面刷新/断线后从后端恢复进度；Pinia 保存交互状态，不成为唯一事实来源。切换实验时提示尚未保存的笔记，取消中的 AI 请求不能把结果写进另一实验。

### 7.3 核验规则与结果

核验器根据只读采集得到结构化结果，不让 LLM 决定设备是否通过。规则必须绑定设备角色、接口、邻居、地址、进程/区域等具体对象；检查输出完整性、时间、解析状态与环境版本。

| 结果 | 条件 | 用户看到的内容 |
|---|---|---|
| 通过 | 规则要求的观察完整且满足预期 | 哪些对象、什么时间、哪些字段支持结论 |
| 未通过 | 观察有效，但与预期不符 | 实际值、预期值及下一项建议检查 |
| 无法判断 | 超时、输出截断、解析不支持、环境漂移、权限不足 | 缺失证据，不给失败分或通过分 |
| 未验证 | 用户仅勾选完成、贴输出或提交笔记 | 明确只是自述/客户端记录 |

OSPF 校验不能只搜索一个 `Full` 字符串；必须核对预期邻居集合、接口/区域和路由结果。广播网络中邻接关系受 DR/BDR 等角色影响，规则按实际任务拓扑制定，不能把任意网络套成全互联 Full。

对“开始时已经配置正确”的情况，标为“现场状态满足要求”；若学习目标是完成变更，另要求前后差异和操作证据。理解题由用户给出解释，参考要点帮助复习，不自动推断全面掌握。

### 7.4 证据可信度

证据至少区分 `server_observed`、`client_reported`、`demonstration`。前者包含采集请求、执行实例、设备 ID、命令动作、采集时间、解析器版本、原始输出摘要及受控存储引用；后二者不能提升为现场核验。摘要用于完整性检查，不宣称具有独立第三方证明力。

已有日志和历史分数保留原始内容并标记来源；不反向生成“通过”记录。保存/导出前过滤凭据与敏感配置，不能为教学报告复制整份含口令的配置。

## 8. 全工作台对话助手

本节由专门的 C 批实现。知识问答、页面帮助、设备输出解读、告警分析、排查、变更草稿和复盘共享助手与会话体系。实训教练是任务上下文中的一种表现，不是另一套产品。

### 8.1 上下文与事实契约

输入使用有版本的结构化上下文：页面与实际能力目录、当前选择对象、会话/任务/步骤、执行模式、用户权限、有效环境映射、事实引用及新鲜度。前端仅提供候选页面和选择，后端核验身份、对象、归属与权限；不得信任任意前端传入的“已验证”状态。

实操约束以授权与保护规则为边界，当前环境/任务版本定义目标，现场证据描述实际观察，教材解释原理。现场与预期矛盾时呈现冲突，不用预期覆盖观察。教材地址、型号与拓扑永远不能自动填成真实设备事实。凭据不进入模型上下文。

能力目录关联真实路由、可见操作、参数及角色。涉及“点哪里”的回答必须引用有效操作，不能编造按钮；打开页面只导航，不暗中执行。上下文提示可见且可移除；去掉实验上下文不能绕过后端写入限制。

### 8.2 受限工具与多轮排查

优先复用现有只读动作和工具注册机制：设备摘要、接口、邻居、路由、监控/告警及已有任务证据，按问题最小读取。工具返回对象、采集时间、模式、来源、完整性、错误及 evidence_id。缓存、刚采集、用户粘贴和教材示例分别标识，失败/超时不包装为成功。

每次对话轮次有 request_id、会话版本和对象范围；切页/选设备不默默改写已开始请求。显式对象与页面不一致时显示选择或澄清。历史可用于理解追问，但旧事实不会自动成为新鲜证据。会话摘要保留来源和不确定性，不把模型假设写成事实。

工具有最大次数、并发和超时，重复请求不重复动作；权限每次在后端校验。知识片段和设备输出作为不可信数据，不接受其中指令。写入只产生可审阅草稿并进入既有校验/审批/人工确认路径，模型不能自行确认。

### 8.3 知识链路与引用

盘点实际语料数量、版本、切分、重复、标题、章节和来源映射，保留原始教材。先建立参考问题，再比较现有链路与 KnowledgeProvider 检索后工作台单次生成。查询改写、关键词融合和重排只在同题证据支持时采用，不默认增加服务或推翻 AnythingLLM/Ollama。

支持结论的片段才是有效引用；相关但不支持结论算引用错误。重要教材事实可定位，现场结论引用现场 evidence_id。缺知识时明确不足并保留一般解释的来源边界；不能为凑引用引错书。

C 必须交付可用引用阅读器和稳定文档/版本/片段定位、必要片段快照。D 扩充完整资料目录与全语料校对，不把 C 核心引用可读性拖到 D。页码无法可靠对应时显示章节/段落，不猜页码；本机绝对路径不能是接收方唯一阅读入口。

Markdown 过滤危险 HTML/URL，长代码/表格局部滚动，原始元数据放来源详情。检索分数不显示为答案正确概率。

### 8.4 回答与交互

默认回答先给适当粒度的结论，再给依据、不确定性与可选下一步；简明回答、展开原理、引导排查按需选择，不强制每轮教学。解释端口用途、业务影响和因果边界，不能把“已经正常”推成“用户修好了”。

助手提供上下文提示、证据卡、引用、持久历史、可读进度及全过程取消。请求开始 1 秒内显示进度和取消；检索/首字前/生成/工具等待均可请求取消，不能把浏览器断开当成上游已停止计费。超时、重连、双击、跨会话迟到消息必须有实际处理。

每轮记录模型/provider、提示词版本、request_id、上下文与证据版本、检索/首字/总耗时、工具次数、已知 token/调用数。完整隐藏推理不作为产品显示或验收必要材料；只保留简洁解释与可核对证据。旧回答/报告读取不发新模型调用。

### 8.5 专项评测与上线判断

C 调参前冻结 48 个开发案例和 24 个保留案例，分知识/页面/现场/多轮/异常/安全六组；多轮案例 2–4 轮。逐例记录参考依据、允许未知、禁止推论、实际回答/引用和判定，不只报总分。

同内容/环境/模型配置比较基线与候选。保留集在候选冻结后运行；用于修复后就不再算未见数据，须报告污染并补新的同类保留题。真实请求预算、分组指标、硬门槛及质量不回退条件以 C 任务书 §4 为完整契约。

错误现场对象、伪称执行、越权、保护口违规和把未知编为已知，固定挑战集任一出现即阻塞。真实 DeepSeek、实际知识 provider、R1/R2/R3 的代表性只读旅程是必需项；合成数据只补异常与危险边界。模型自评不能代替逐例证据与协调者人工抽查。

上线先满足各组最低门槛，再比较质量、延迟、成本；更快不抵消更多错误。没有足够证据不宣传准确率提升或零幻觉，无法实测不得报通过。

### 8.6 Agent能力与效率专项（C-AG1，2026-10-30）

采用单Agent、共享同步/SSE执行内核与按需加载的运维技能。直接问答、技能工作流、自适应排查按任务选择，不让简单问题都先做模型工具规划。至少实现页面引导、教材解释、设备接口排查、路由/OSPF排查、变更草稿审阅、实训复盘六技能；技能只调用既有授权工具，不能扩大权限或新增写设备通道。

可信上下文/证据/会话摘要、中文术语和命令的词法与向量检索、有效引用、工具结果分支、流式输出前草稿校验、缓存失效、取消恢复及请求级成本轨迹一并实现。重排和其他增强以开发集收益决定采用，不盲目叠加框架。允许必要内部模块与小型锁定依赖，保留主栈、真实DeepSeek与知识provider。

完整细则、CA-01…10及CA-T01…18见docs/plans/v7/V7-C-Agent能力与效率设计.md；与原CF-01…08、C-01…13同轮收口。既有质量阈值与原500次C批总预算不提高；原72题standard评测固定每轮2次生成/3次只读。产品复杂排查diagnostic档按C-AG2最多4次生成/6次实际读取，升级累计并单列验证，不能替换原成绩。按实际任务成功、依据、首个有用输出、p50/p95和调用/token用量验收，设计文件或技能数量不能作为完成证明。

## 9. 复盘、学习记录与运维展示

### 9.1 复盘是持久记录

生成报告后保存不可变版本，至少包含：会话与实验版本、环境绑定、采用的证据范围、核验结果、用户笔记、模型与提示词版本、引用、生成时间和报告状态。查看已有报告是读取，不再次调用模型。

“重新生成”是明确的新动作，产生新版本并保留旧版；用户能知道输入证据是否改变。生成失败保留失败原因，完成会话不清掉已生成报告。支持脱敏 HTML/打印导出，先复用浏览器打印，不为 PDF 另引入复杂服务。

复盘结构：任务目标、实际观察、采取动作、核验结果、证据不足、理解要点、下一项练习。统计显示最近完成/验证的任务与待复习知识点，不把历史参考分汇成“100% 已掌握”。

### 9.2 拓扑与监控的学习语义

- 拓扑分别展示“基线是否完整”“设备是否可达”“发现覆盖了什么”“与预期有哪些差异”。零基线/零发现只能表示无可比较链路。
- 告警基于端口用途、预期启用状态、管理状态及新鲜度；未使用口 down 默认是状态信息，未知用途提示待标注。业务口异常再进入告警规则。
- 每条告警解释“观察值是什么、为什么触发、可能影响、先读哪条信息”。告警确认仅记录处理状态，不能冒充故障已经恢复。
- 保留监控刷新/采集区别，展示样本年龄、采集任务结果和缺失设备。没有样本与正常零值分开。

### 9.3 配置、审批与系统页面

配置差异先显示设备名、前后版本、增删改行和范围；JSON 作为高级查看。任务模式取自那一次执行记录，不能由当前环境变量决定历史标签。按钮按真实行为命名为“确认方案”“执行”“查看核验”“申请恢复”。

审计保留机器可读动作码，同时给中文动作、对象、结果和请求关联；后台任务入口聚合或明确跳转到监控/部署各自任务，不把空列表解释成系统无任务。

系统配置显示有效值、来源、是否覆盖默认值、是否需重启和健康检查。模型区分别说明文本、视觉、知识检索/嵌入的实际调用关系；凭据只显示已配置状态，不回显明文。不能让学员通过通用配置表修改运行安全开关。

测试记录增加来源标签；正常列表默认可过滤测试数据，管理员可查看全部。不得通过删除历史任务、证据或用户会话实现“清爽”。

### 9.4 时间契约

API 新时间统一为带时区的 ISO 8601 UTC（`Z` 或明确 offset），界面按用户时区显示并标识；排序和时长使用时间点而非格式化字符串。迁移前先核实各表历史 naive datetime 的真实含义，建立转换台账和备份，避免统一加八小时导致重复偏移。

## 10. 技术栈取舍

选型目标是可靠、易维护、接收方能启动；“更新”或“更流行”本身不构成更换理由。下表基于当前代码和官方文档，不是全栈性能评测结果。

| 层 | 当前方案 | V7.0 决策与理由 | 再考虑替换的条件 |
|---|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite + Pinia + Router | 保留；问题主要在布局、状态和产品流程 | 现有技术无法满足已验证需求，而非审美偏好 |
| 组件/图表 | Element Plus、ECharts、SVG 拓扑 | 保留，统一主题变量与可访问性；按需加载大图表 | 真实大拓扑性能或编辑需求超出 SVG 能力 |
| 终端 | xterm 5.3 与旧 addon 包名 | 先保持行为，单独评估迁往官方 `@xterm/*` 包 | 兼容回归完成后升级，不夹带在 UX 修复中 |
| 配置编辑 | 现有文本输入和校验 | 先补行号、定位、差异；小原型比较 CodeMirror/Monaco 的成本 | 需要复杂语言服务时才引入 Monaco；不强制装两套 |
| 后端 | FastAPI + Pydantic + SQLAlchemy | 保留；模块内增加明确契约，避免微服务拆分 | 独立伸缩/部署有实测需求 |
| 设备接入 | Netmiko/Paramiko、现有 VRP 规则 | 保留，完善结构化只读与证据 | 新厂商/协议的实物验证确有需要 |
| 数据库 | full 为 MySQL，minimal 为 SQLite | 首版 V7 full 继续 MySQL，保护已有事务/锁/迁移证据 | 单机 SQLite full 只做限时可行性试验，未验收不替换 |
| 调度 | APScheduler 3 | 单实例调度；采集任务有执行归属与防重入 | 多进程/多节点再拆专用调度进程，不直接共享 job store |
| 知识服务 | AnythingLLM Desktop + Ollama + provider 抽象 | 保留现有本机 profile；检索与生成职责分开 | 多用户教室场景评估 Docker profile；不直接重写 RAG |
| 文件存储 | MinIO 等现有路径 | 先列真实使用方；不为减组件直接删 | 文件系统 provider 完成备份/访问权限/迁移验证后才可选 |
| 发布 | Windows 脚本、bootstrap、preflight、冻结包 | 复用现有入口，加配置向导与状态解释 | 没有必要为启动按钮增加 Electron/Tauri 外壳 |

Pinia 是 Vue 官方推荐的新应用状态管理方案，当前路线合理。[Vue 官方说明](https://vuejs.org/guide/scaling-up/state-management.html)。xterm 当前官方导入使用 `@xterm/xterm` 与 `@xterm/addon-fit`；这里建议维护性迁移，不宣称当前版本有未经核实的安全漏洞。[xterm 官方导入指南](https://xtermjs.org/docs/guides/import/)。

SQLite 可用于单机应用，但写入同时性有边界；共享设备锁和并发采集必须按当前负载验证，不能只因安装简单就替换 full 数据库。[SQLite 适用场景](https://www.sqlite.org/whentouse.html)。FastAPI 多个 worker 的内存通常不共享，增加 worker 前必须检查会话、锁与任务状态所在位置。[FastAPI 部署概念](https://fastapi.tiangolo.com/deployment/concepts/)。APScheduler 3 官方明确说明多进程共享同一 job store 存在重复或漏执行风险，不能把它当成现成分布式调度。[APScheduler FAQ](https://apscheduler.readthedocs.io/en/3.x/faq.html)。

AnythingLLM Desktop 适合本机单用户；需要多用户访问控制时才评估其 Docker 方案。当前一次 30 并发读取的历史结果不能证明 Desktop 已适合 30 人同时问答。[AnythingLLM 部署方式说明](https://docs.anythingllm.com/installation-docker/overview)。

V7.0 不新增 Kubernetes、Redis/Celery、独立向量数据库或微服务集群。若性能数据证明需要，提交单独的瓶颈与收益分析。依赖升级使用锁文件、小批兼容验证，功能修复和大版本升级分开。

## 11. 数据、接口与迁移设计

本节是新增/扩展契约的提案；实施前须核对现有表和接口，优先扩展已有对象，不能据这些名称宣称功能已存在。

### 11.1 建议实体

| 逻辑实体 | 核心字段 | 与现有对象的关系 |
|---|---|---|
| LabVersion | lab_id、version、目标/先修、步骤定义、内容摘要、发布状态 | 扩展实验，旧会话固定版本 |
| EnvironmentBinding | profile_id、version、角色映射、拓扑引用、保护项、预期状态、检查结果 | 引用已有设备/拓扑，不复制设备凭据 |
| SessionStepAttempt | session_id、step_id、attempt、用户声明、笔记、开始/完成时间 | 扩展实训会话，允许重试不覆盖旧证据 |
| VerificationEvidence | rule_version、环境版本、request_id、device_id、采集时间、原始引用、解析结果、可信度 | 复用只读采集/操作日志，补证据关联 |
| TrainingReport | session_id、report_version、input_hash、model/prompt_version、正文、引用、状态、创建时间 | 持久报告，AI 调用日志仍独立保留 |
| ResourceLease | session_id、owner、设备集合、状态、更新时间、恢复要求 | 扩展或关联已有设备锁，不新建另一套互斥体系 |
| AssistantContext / Capability | page_id、选择对象、权限投影、模式、环境/任务版本、有效动作 | 扩展现有 copilotContext/pageDataContext，后端验证，不要求新增独立表 |
| ConversationTurn / ToolEvidence | request_id、会话版本、输入快照、工具/evidence引用、回答、引用、终止状态 | 扩展已有助手会话与日志，避免与实训会话混为一体 |

涉及证据的更正采用新版本并记录原因，不直接覆盖历史结论。用户笔记可编辑，但明确修改时间，不改变原始采集记录。所有对象继续执行租户/用户归属或既有角色边界。

### 11.2 建议接口行为

具体 URL 可复用现有命名；以下列行为契约，避免机械照抄产生重复接口。

| 行为 | 方法语义 | 关键约束 |
|---|---|---|
| 读取实验与版本 | GET | 返回先修、环境要求、步骤和适用模式 |
| 检查环境 | POST | 只读设备；返回逐项状态、证据与有效时间 |
| 创建/恢复会话 | POST | 绑定固定版本；completed 不允许恢复成 active |
| 保存步骤/笔记 | PATCH | 乐观版本号防覆盖，检查所属会话 |
| 执行只读动作 | POST | 接收动作 ID 与受限参数，不收任意 SSH 字符串 |
| 核验步骤 | POST | 幂等键、任务 ID、确定性结果；超时标无法判断 |
| 获取已有报告 | GET | 不触发 LLM、不额外收费 |
| 生成报告新版本 | POST | 固定输入快照、幂等键、状态查询、显式重生成 |
| 取消 AI 请求 | 取消动作 | 从检索到生成均可请求取消，返回上游取消状态 |
| 读取引用 | GET | 按文档/版本/片段定位，校验访问权限 |
| 获取助手有效上下文/能力 | 读取 | 验证页面/对象/角色，返回版本及事实新鲜度，不信任客户端授权 |
| 生成助手回答/调用只读工具 | 有副作用请求 | request_id/会话版本/对象范围固定；限次数/超时；后端工具授权 |
| 读取助手历史 | GET | 按所属用户/授权范围，旧内容不重新生成；事实保留原时间 |

跨步骤操作必须带 session_id、step_id、environment_version；后端验证它们的关系。环境版本改变时返回可识别冲突，要求重新核对，不自动接受旧草稿。错误码至少区分环境不匹配、设备占用、证据不足、权限不足、依赖不可用和请求已结束，前端映射为可理解文案。

### 11.3 迁移策略

1. 在独立数据库副本验证增量迁移、旧记录读取、备份恢复和回退；不在当前数据库上试错。
2. 旧实验可导入为 legacy 版本；内容不完整的会话保留“不具备版本化证据”标签，禁止自动补成已验证。
3. 时间字段逐表核实后迁移；用已知日志时间点验证同一事件，防重复转换。
4. 先支持旧前端/接口兼容或明确版本升级顺序，再逐步迁走有副作用的 GET 报告生成；删除旧接口前记录调用方。
5. 内容、环境映射和凭据分离。教材目录不存运行密钥，实验 JSON 不复制账号口令，测试只用合成数据或受控脱敏证据。

## 12. 首次配置与交付形态

### 12.1 交付承诺

V7.0 的正式目标是 Windows 单机完整模式：接收方按向导准备/检测依赖、填写自己的模型和设备凭据、完成环境映射后可以运行。**不是无需网络、无需模型账号、无需设备、无需任何外部服务的单文件程序。**

发布目录包含可运行工作台、构建好的前端、依赖锁定与 bootstrap、配置模板、受控语料/索引元数据、启动/停止/诊断入口及用户指南。安装器、第三方运行时和模型是否随包分发，要另行核对体积、许可与平台条件；不把本机 venv、node_modules、数据库或密钥直接复制作为交付方案。

### 12.2 配置向导流程

| 步骤 | 用户输入/操作 | 自动检查与恢复路径 |
|---|---|---|
| 选择模式 | 完整联网或离线演示 | 说明各自能力与依赖，不静默降级 |
| 检测本机 | 确认安装/连接现有依赖 | 显示版本、路径、端口占用、网络下载需求；不杀未知进程 |
| 管理员与模型 | 接收方设置自己的凭据与模型端点 | 本地安全保存；遮蔽显示；模型测试有明确调用提示 |
| 数据与知识 | 选择数据库/知识服务、同步受控教材 | 迁移、文档数量/版本、索引状态、实际检索；失败可续跑 |
| 设备与拓扑 | 三台设备凭据、角色/接口映射 | 只读连接、设备指纹和环境核对；不自动配置路由 |
| 启动检查 | 查看结果，进入统一工作台并选择设备 | 逐项通过/失败/未验证；给出相关诊断，不只显示总绿灯 |

复用现有脚本和 full_preflight 的权威判断，前端向导只做输入、编排与可读反馈，不复制出第二套放宽的门禁。凭据只经受控本地配置流程保存，诊断包默认脱敏；错误页面不打印完整连接字符串。

AnythingLLM/Ollama 的首次安装与模型准备可能需要下载，向导需提前说明并检测，不能将本机已安装状态当成接收方现状。[AnythingLLM Windows 安装说明](https://docs.anythingllm.com/installation-desktop/windows)。

### 12.3 新接收方验收必须补齐

在含空格的新路径、全新空库、接收方自己的配置中运行，验证交互向导、真实知识空间初始化与首次向量化、三台设备映射、重启与恢复。先明确交付包携带哪些语料及其授权，再执行首次入库；不能把旧知识空间已存在 135 篇当成首次同步成功。

启动/停止继续使用 root、PID、launch_id 和实例收据核验；不按端口或进程名批量终止。保留旧冻结交付包，V7.0 产出新候选、指纹和验收记录，不覆盖旧证据。

### 13.2 体验目标

- 全屏/最大化为前端主标准；按全屏与窗口拉伸规范覆盖 16:9、16:10、较窄较高、4:3、超宽等代表比例，以及同一页面连续拉伸和恢复。记录实际尺寸、缩放及真实最大化/模拟的区别。另查 200% 阅读和主要动作；二维终端局部滚动不豁免普通页溢出。
- 引用详情、错误、表单及图表关键文字达到对比度目标；键盘能开始/停止请求、切换步骤、打开/关闭资料。
- 本地稳定依赖下，首页可操作 p95 ≤2 秒、普通列表读取 p95 ≤1 秒，明确冷/热缓存、样本数与硬件。第三方模型耗时单独记录，不能混进页面加载指标。
- AI 请求 1 秒内呈现进度/取消入口；记录检索、首字和总耗时 p50/p95。超时预算按实测确定，不能为获得好看数字截断复杂回答或隐藏失败。
- 对固定操作挑战集，保护口违规草稿、编造现场接口和伪称已执行均为 0；这是有限用例门槛，不是全场景零幻觉承诺。

### 13.3 真实初学者测试

邀请 8 名具备基础计算机/IPv4 知识、尚不熟悉工作台的参与者；说明可随时停止，不收集不必要个人信息。管理员事先准备环境，不把设备安装时间算入学习任务。

从统一首页/设备工具开始，允许使用右侧助手但记录其帮助；不要求参与者经过学习入口。目标：至少 6/8 人无需旁人代操作，在 15 分钟内完成第一项只读任务，并能解释一项接口观察；至少 6/8 人能在结束后重新找到自己的证据和复盘。记录每人的完成/未完成、时间、求助次数、卡点与误解，保留分母，不用平均分掩盖失败者。

另选一个完整 OSPF 维护任务，记录是否能按顺序观察、判断、核验；真实写入部分由权限与操作窗口决定。若暂时无法招募参与者，发布状态标为“专家走查完成，初学者可用性待验证”，不能声称学习体验已充分验收。

### 13.4 回归方式

按用户 2026-10-26 补充要求，界面验收必须包含 computer use 的真实用户操作与读图：从正常入口完成流程，实际检查关键状态截图的排版、遮挡、对比度、反馈与可操作性，交回逐步UI旅程记录。API/DOM/自动化断言通过不能代替；先用接口完成核心动作再拍结果图不算该流程验收。每批任务书列必做UI旅程，协调者逐批抽查；无相应能力或证据时标未验，不自行豁免。具体规则见根目录计划链接的公共回传模板 §4。

优先给状态、授权、环境绑定、核验、迁移和取消竞争编写有实际行为断言的测试；不为文案和低风险样式堆砌镜像测试。前端使用既有 lint/typecheck/build 与浏览器回归，后台使用既有隔离测试数据库和依赖锁文件。

每批只重跑受影响检查。产品改动冻结后再执行一次覆盖完整主链路的候选验收；若新失败或影响安全路径的改动出现，重跑对应范围并重新计算指纹。不要反复重演已通过的旧版本真实设备批次。

## 14. 实施顺序与阶段出口

执行者按用户逐批派发连续完成批内任务，批末交 Codex 验收，不自行跨批或写 ACCEPTED。用户已确认 R3 产品方向，普通视觉/实现取舍不重复询问；真实写入窗口、范围改变和破坏性迁移仍按现有边界处理。

| 批次 | 主要内容 | 必须交给下一批 |
