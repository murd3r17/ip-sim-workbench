# 助手请求计量说明

> 2026-11-06 C6.13 增量：用户已取消金额/调用次数上限。产品 direct 维持0轮/0工具/1逻辑生成；standard 改为最多2轮/6工具尝试/4逻辑生成，diagnostic 最多3轮/9工具尝试/6逻辑生成。逻辑生成包括规划、初稿、定稿和草稿，HTTP失败/故障转移另行逐次记账且无金额或次数上限。同轮只复用既有结果时提前停止；授权检查、同一读取最多一次瞬时重试、总时限和取消不变。这些是防循环工作流边界，不是每次必须花完的配额；原2/3、4/6的历史分数不可与新策略冒称同条件。新策略需经定向真实模型和回归验证，C仍NEEDS_FIX。

适用于现有 V7 Copilot 的同步与 SSE 请求；计量本身不改变选路、知识结果或设备权限。

带服务端独立审校说明的知识问答使用选择性定稿：`knowledge_draft` 产生待核对正文，`knowledge_finalization` 依据同一批实际片段与审校说明生成展示正文。两次实际派发分别计量并汇总；首份正文只在请求内存中使用，不显示或保存成用户答案，模型思考不保存。`trace.knowledge_review` 记录是否采用该流程、原来源编号与阶段，不是自动准确率评分或验收结论。用户感知首字只在定稿正文真正发出时记录；额外等待与token成本必须如实报告。无审校说明的知识、页面帮助、现场读取和草稿沿用原路径；客户端伪造同名文字不会启用服务端审校。

## 时间口径

`trace.timings` 使用进程内高精度 `perf_counter`，版本为1。`request_elapsed_ms` 从请求取得运行登记后开始，包含持久预留、准备、检索和生成，到最终结果写入之前结束；不包含最终持久写入、网络交付和浏览器绘制。它不能冒充用户看到首字或完成的时间。旧 `trace.elapsed_ms` 只覆盖助手生成服务，保留兼容，勿与新指标混为同一口径。

`first_progress_ms` 记录实际非空进度事件；`first_safe_content_ms` 记录首个通过现有输出边界的非空正文事件。同步请求只有完整答案，故该值是答案可用时间，不是流式首字。reasoning、空 token、工具运行提示均不计正文。`first_evidence_event_ms` 仅记录带服务端观察来源和 evidence_id 的 ok/empty/partial 工具事件；部分结果仍是部分证据，不代表故障已定位。同步入口不输出中间证据事件时该项为 null。浏览器首字/布局绘制仍由原生 Playwright 旅程另测。

`stages.retrieval/tool` 汇总本请求实际进入的检索/工具执行边界，记录次数、耗时与完成/失败/取消。工具阶段含短数据库会话及执行器授权检查；复用也经过现有执行器，真实读取次数以原 `tool_dispatch_attempts` 和工具结果为准。没有观察到的阶段为 `not_observed`、耗时 null，不推断已执行零毫秒。观测列表最多128项，超出不会追加。现有每请求预算远小于该上限。

`provider_operations` 按 generate/chat_completion/stream_parts 等操作记录等待时间、操作总时间、首正文和终态。一个操作可发生主提供商失败后备用派发，因此不是单个 HTTP 耗时；`dispatch_count` 与原 `model_calls` 分开。流式 `provider_await_ms` 只累计等待上游的时间，`operation_wall_ms` 和首正文时间还可能包含消费者背压。部分读取后关闭为 interrupted，超时/取消/失败分别保留，异常仅记类型名。

## 用量与缓存

`contexts[].usage` 只保留提供商实际返回且为非负整数的 input/output/total 和缓存 token。支持 DeepSeek `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens`、明确的缓存读取/创建字段，以及从 `prompt_tokens_details.cached_tokens` 规范化的 `cached_prompt_tokens`。后两种命中数可能是同一事实的不同字段，不能相加。未返回不能补零或推算账单。

`trace.usage` 只有全部实际派发都返回 total 时才提供汇总，且仅汇总所有派发均已返回的字段。一次失败派发没有用量时，完整总量仍为 null，各派发已知部分保留在 contexts。不能只加成功请求宣称完整成本。

`timings.knowledge_cache` 是本请求检索片段缓存实际命中/未命中的计数，不是模型前缀缓存。未访问为 null。指标在具体缓存分支记入请求上下文，绝不用全局统计前后差值计算，避免并发串账。未命中后提供商失败仍是一次未命中。

## 恢复、隐私与验证

计量上下文只绑定在等待生产者工作期间，不能跨消费者 yield；共享提供商、并发请求、浏览器切换不会共享计量对象。最终 trace 随原结果持久化，同请求重放返回原指标，不再计一次生成，也不改写成新的更短耗时。历史旧请求没有新字段时保持缺失，不能事后补测。

计量对象不存提示词、查询、CLI参数、密钥、设备配置、异常正文或隐藏推理。引用/工具原有权限与脱敏约束继续有效；新增指标不新增外传。评测候选、问题与源码版本仍由冻结 manifest 关联，模型上下文原有 context_id 和 source_bundle_id 用于核对实际输入，不以之后的源码替代执行时版本。
