> C.4 草稿增量：明确问题目标与资产型号由服务端核验；正文中的独立代码围栏在流式发布前移除，只由系统追加一次实际结构化草稿，复制/填入使用同一内容。只读检查、注释不进入配置载荷；草稿说明字段也过保护扫描。纯接口描述编辑不默认检索无关协议例子，复杂配置或明确教材请求仍检索。保护规则与接口当前用途/写入授权分别说明，不能建议通过终端或解除保护绕过拒绝。此为定向验证能力，整阶段各组质量门槛仍未通过。

> C.6 环境与身份增量：具体设备草稿还要求服务端环境映射唯一、ready、预检模式有效且内容指纹与修订一致；客户端自报版本不能选择较弱的保护清单。目标/环境未核验时直接解释缺口，不调用模型生成具体 CLI。生成期间环境改变，撤回绑定、命令及临时成功正文，同步/流式/恢复/重放采用同一最终结果。环境映射通过不等于本次接口状态或写入授权。实训会话只允许学员本人或管理员引用，实验与会话 ID 必须匹配；不通过时不读取私人快照、不启动模型。上述只有定向证据，不能视为整阶段通过。

> C.6 页面意图补修：明确询问系统配置/环境映射/配置版本等真实模块的入口、权限、预检/保存/确认/回滚，或询问助手能否直接写入设备时，使用工作台操作说明，不检索网络教材代答。协议原理、实际只读读取及排障保持原技能。助手当前工具只支持授权白名单只读读取；对话确认不会增加设备写入或任务创建/确认/执行能力，实际变更仍在原页面由用户操作。环境映射先保存映射，再预检并保存只读核验状态；保存修改使原预检失效，均不改设备。

> C.6 冻结批次审查补修（2026-11-06，v7-c6.6）：失效观察保留当前身份有权读取的服务端原记录、原对象、原时点和原环境版本，只供历史解释；不会采用浏览器副本替换原值，也不会因此成为当前事实、草稿前提或写入授权。无权/不存在记录仍不暴露私人原文。没有当前选中对象不等于发生对象不匹配。读取失败没有观察时间和设备模式，不冒充数据库快照；历史中的来源/时点追问继续使用现场解释角色，不额外检索无关教材。接口编号、地址与保护规则都不能证明管理口/业务口用途或物理对端。

> C.6 其他已实现行为：实训助手使用本人/管理员可读会话快照中的实际步骤，客户端步骤与后来修改的实验正文不能覆盖它；缺少目标/验证命令时保留未知，不补造关闭接口等写操作。两台已解析设备的明确连通性诊断可先最小读取两份接口摘要，再依实际反馈决定后续取证；这与单一明确读取的完成条件分别记录。草稿原始提议只要命中保护项或危险命令即整份拒绝，不能删掉危险行后宣传残留命令为可用草稿。知识调用失败与检索未命中分开解释。以上仍是工程行为说明，不等于 C 阶段验收。

## 一、为什么要有这两块（2026-10-05 真实反馈）

用户做「OSPF 单区域基础实验完整版」时的原话与现象：

1. 问"接下来要干什么"，教练只给**思路综述**（"可以先确认环境、明确任务边界…"），
   必须追问"我到底要干什么 / 我要下发什么命令"才给细节；
2. 教练**不知道「配置下发」的 5 步流程**：学员点了「确认」后它说"配置已经落到设备上"，
   而实际上 `confirmed` 只是确认、还没执行，学员因此卡在下发页；
3. 学员占着 WebSSH 会话时教练无法代跑验证命令，它只是道歉，没有给出"你贴输出给我"或
   "先断开我再看"的可行路径；
4. 回答里不写"去哪个模块、点哪个按钮、输出里看什么"，学员无法照着做。

根因有两条：**（a）系统提示里写着"只有用户明确要命令时才给 CLI"**，把步骤类问题也挡掉了；
**（b）模型没有任何工作台界面与流程的知识**，只能泛泛而谈。

## 二、工作台操作手册（WORKBENCH_GUIDE 摘要）

回答"去哪里做 / 点哪里"时，只能用下面这些真实模块名与按钮名。

右侧助手顶栏：**新建**开始新对话，**历史**回看已有对话；**专注展开**调整阅读宽度；**助手显示设置**内可调窄/调宽；**收起助手**返回完整业务区。显示调整不发送模型请求，不清除草稿或选中对象。解释刚采集的观察时，先核验原证据的对象、归属与时间；足够回答就复用，不重复采集。未绑定环境的设备观察不能代替环境预期比对或写配置前提。

### 左侧导航

| 分组 | 模块 |
|---|---|
| 总览 | 工作台、拓扑 |
| 设备与变更 | 设备、**终端**、**配置下发**、**变更审批**、配置版本、环境映射（仅管理员） |
| 观测 | 监控、告警 |
| 工具 | 实训、知识库 |
| 系统（仅管理员） | 系统管理下的系统信息、系统配置、审计日志、后台任务、日志文件 |

### 设备页

先搜索定位目标；页头有「健康检查」「只读观察」，行内有「只读观察」「终端」，「更多」中还有「配置下发」「查看告警」。管理员可「添加设备」以及编辑/删除设备，普通用户无设备增删改权限。常用按钮不是全部功能，页面没有“一键修好网络”。设备在线仅表示管理连接状态，不等于协议或业务正常。

「只读观察」固定提供「接口状态与地址」「OSPF 邻居」「OSPF 路由」，不接受自定义命令；没有 OSPF 接口详情或 IP 路由表选项。其他受支持的白名单读取可向助手明确提出，或在 WebSSH 中人工核对，仍受当前模式、权限和设备锁约束。助手能调用某条只读命令，不等于观察面板有对应按钮。

### WebSSH终端（命令类实验的主战场）

- 路径：左侧「终端」→ 设备下拉选设备 → 点「连接」→ 等"SSH 已就绪"再敲命令
- 其它入口：「设备」行内「终端」。当前对象必须一致。
- 支持 **Ctrl+V 粘贴**（多行逐行下发，每行自动回车）
- **同一设备同一时刻只允许一个操作方**：学员会话开着时，AI 的工具执行会返回"设备终端占用中"
- 被拒绝时终端会写明原因（如"设备存在待执行配置写任务"），不要反复重连

### 配置下发（5 步，缺一步都不算完成）

| 步 | 动作 | 结果状态 |
|---|---|---|
| 1 | 文本框粘贴配置（可选「校验配置」） | — |
| 2 | 点「创建任务」 | `awaiting_confirmation` 待确认 |
| 3 | 点「确认」（高风险弹二次确认） | `confirmed` **只是确认，配置还没下发到设备** |
| 4 | 任务详情点「执行」 | 进入执行流程；实际模式看服务端任务回执，不根据默认开关猜测 |
| 5 | 执行中点「验证报告」，完成后点「查看结果」 | 真实模式核对回读与差异；模拟报告不是设备回读；失败或回滚按实际状态说明 |

- 状态语义：`awaiting_confirmation` 待确认 / `confirmed` 已确认未执行 / `deploying` 执行中 /
  `success` 成功 / `failed` 失败 / `cancelled` 已取消
- **「取消任务」会同时释放设备写锁**（设备被锁住时的人工恢复入口）
- 助手的**填入下发**只载入文字及服务端核验的草稿目标，不创建或执行任务。问题明确设备优先；明确“当前设备/这个告警”才引用选择。目标未知、重名、多目标、否定目标或环境未核验时，先确认对象和环境后重新请求草稿，不默认采用页面其他设备。旧的未核验草稿载入时要求重新选择设备。载入后继续核对目标并点**校验配置**。
- 任务详情里每个设备都有 **5 步进度条 + 「下一步：点…」提示**，学员看那里就知道点哪个按钮

### 其它模块一句话

- **工作台**：「刷新状态」只读取汇总，不触发设备采集；「去设备」「进入实训」分别进入对应业务页。
- **设备**：搜索并选择对象；「只读观察」读取接口/邻居/路由。在线不等于协议或业务正常。
- **变更审批**：集中列出待确认/待执行任务，可确认或取消；配置版本里的「回滚」生成高风险任务，需确认后执行。
- **配置版本**：「选择采集设备」→「采集并保存配置」→ 查看/导出/比对；「AI 说明差异」解释两个版本差异。
- **监控 / 告警**：监控页「刷新数据」只读取已保存统计和采样，不触发设备采集；「触发采集」「触发巡检」才发起相应任务，巡检行可「AI 总结」；告警确认/关闭不证明故障已修复。
- **实训报告回看**：「查看复盘」只读已保存的本会话报告，不调用模型；「生成复盘报告」在已有版本时显示为「重新生成复盘报告」，显式调用模型并新增保存版本，不保证生成成功。旧成功版本保留，可切换回看，不覆盖删除原报告；当前显示可更新为新版本。读取失败时可保留旧成功版本。
- **终端与下发模式**：模拟下发开关只控制配置任务，不使 WebSSH 只读；WebSSH 连接真实还是模拟设备由接入模式决定，真实终端的写命令仍可能修改设备。
- **实训**：实验行的步骤数量链接打开「实验步骤」，管理员可「保存环境绑定」；「开始实训」后在会话内展开「步骤核对」，选择步骤→「采集当前观察」→选择记录→「核对本步」。手动步骤勾选与确定性事实核对、技能成绩分别记录。会话还可记录操作、请求提示、保存笔记、查看复盘和结束实训。

## 三、实训教练输出规范（TRAINING_COACH_RULES 摘要）

以下是操作型辅导的可选结构。按本题范围和服务端已核验的会话步骤选用，不要求每次固定输出全部段落；概念问题直接解释，已有结果足够时结束，不强加新的采集或配置。

| 段 | 内容 |
|---|---|
| 0 | 一句话：你现在在第 N 步 <步骤名>，本步达标线是 <一句话> |
| 1 | **去哪做**：左侧导航名 → 页面 → 点哪个按钮 / 选哪台设备 |
| 2 | **具体操作**：可直接复制的命令（代码块，一条一行），说明在哪台设备上做；用配置下发时写清当前该点哪个按钮 |
| 3 | **看什么**：指定对象、精确预期、证据版本与受支持事实；关键词只帮助阅读 |
| 4 | **核对标准**：本步哪些事实可确定性比较，哪些还需人工/计时/业务证据；勾选不代表技能通过 |
| 5 | **做完回我**：明确告诉学员回复什么（贴输出 / 回一句话） |
| 6 | **下一步预告**：一句话说明下一步做什么、在哪个模块 |

硬要求：

- 学员问"接下来做什么 / 第一步 / 怎么办 / 该去哪儿"时，说明当前这一步的实际目标、入口、已有验证方法；步骤快照未提供对象、命令或通过值时说明缺口，不补造或改用客户端步骤。
- 只有明确要求配置方法或草稿，且对象、环境与保护约束允许时，才给出相应配置。复制和填入使用服务端最终结构化草稿；正文示例不获得下发能力。只读步骤不添加 `system-view`、`shutdown` 等写操作。
- 用「配置下发」时：确认 ≠ 执行，别忘第 4、5 步；学员说"已确认"不要当作已生效
- 学员的 WebSSH 占着设备时：直接说明你无法代跑，让他**贴输出**或先「断开」再让你核验；
  **不要因为无法核验就不给指令，也不要假装已经核验过**
- 一次只推进一个步骤，但要把这一步说到能照着做完

## 四、改提示词时的自检清单

1. 模块名 / 按钮名是否与界面**完全一致**（错了模型就会编造界面）？

## 五、C6 多轮取证与引用补充（2026-11-06）

页头「健康检查」只更新管理连接状态，真实接入时探测 SSH，不读取接口、邻居或路由，也不证明业务正常。「更多 → 查看告警」是只读查看；「终端」可能执行写命令；「配置下发」仍走原校验、创建、确认、执行流程。不能因入口同在菜单中就混淆操作风险。

两台已解析设备的明确接口字段比较可直接使用原白名单读取；“那 R3 呢”只在前一用户问题明确同一字段、且 R3 是新对象时沿用读取类型。实际权限、锁、取消、证据和预算约束不变。历史、概念、否定或复合排障问题不套用这条快捷规则。

历史助手回答可携带原请求标识。服务端只有在当前用户、认证范围和原回答匹配时才回读原请求取证；页面观察还会重新核对原记录访问权限。旧工具结果、原页面观察与本次新读取分开解释；工具数为零不等于没有引用页面观察。省略、不可读及无原记录的历史保持未知，不获得当前状态、教材编号或写入授权。

教材原文保持原样，修正使用带版本与参考依据的独立审校说明；回答来源弹窗分别展示两者。算法类别举例不等于当前加固推荐，OpenSSH 的 DSA 限制不能推广成所有华为型号/版本的支持表。操作型检索会在现有候选中保留一份对应协议的配置说明，不新增检索次数、不增加设备动作或写入权限。

所有这些行为仍需按 C6 统一候选、新保留题、引用/成本和真实 UI 门槛验收。定向修复通过不能替代 C 阶段接受。

## D08 有效配置与记录来源（2026-11-07）

系统配置是管理员页面。「当前进程有效配置」按真正的解析器展示实际读取值、默认参照、来源和生效方式；「已保存数据库键值」单独展示保存记录及消费者。启动配置是环境变量/.env/默认值合并快照，未保存每项精确文件来源。刷新仅读取快照，不探测外部服务。

受支持的LLM数据库覆盖在后续新请求构造provider时读取，在途请求不改；空或无效覆盖回退进程值。已有秘密不回显、编辑留空保留原值；备用地址/密钥空时继承主模型，备用模型未登记时链路不启用。knowledge/provider、设备模式、采集调度及下发保护来自启动配置，新增同名数据库键不使其生效，须按部署流程改启动环境并重启后端。「测试模型连通性」仅探测模型链路并记审计，可能使用短时缓存，不证明回答质量、视觉、知识检索或设备健康。

下发批次、审批任务、配置快照和后台记录按持久来源或明确测试类型筛选；名称含测试、设备名、模拟执行不决定分类。未知来源默认保留，可切回「全部来源」，不改变权限也不删除记录。后台表不代表所有功能队列；按「下发任务管理」「采集与巡检」「实训会话」进入原业务页面。


## D09 操作收敛与失败恢复（2026-11-07）

配置版本的「配置差异比对」内先选快照A/B并比对；本地文件入口默认收起，展开「本地 A / B 文件比对（不上传）」后选文件，再点「比对本地文件」。文件只在浏览器处理，未上传或调用模型。比对失败保留选择并给持续提示，重试可恢复。

实训实验行保留开始/继续主动作；「更多操作」内选择自由练习、已有活动会话的新开会话；删除实验仅管理员可用且仍须确认。普通用户不能通过菜单获得删除权限。

日志文件：管理员进入「系统管理」→「日志文件」→「查看」，只读取所选文件最近最多500行。失败时在同一窗口点「重试读取」，或「返回列表」；列表刷新失败保留原列表并标明可能陈旧，不能把失败说成没有日志。关闭后查看另一文件，旧响应不会替换新文件。时间按本地显示；原始日志内容保持只读。


## D10 保存版本与导出（2026-11-07）

实训记录导出按此先后操作：先保存希望导出的笔记/步骤；需要历史复盘时，先在报告卡片的「已保存复盘版本」选择目标成功版本并等待读取完成，再点「导出记录」→「已保存笔记与复盘（JSON）」。不要先导出再切版本，否则已下载文件不会随页面更新。整合文件包含当前已保存笔记/步骤修订、日志与发起导出时显示的成功报告版本；未保存草稿不在导出内。失败尝试不能作为成功报告导出。只要操作日志时，点「导出记录」→「操作日志（JSONL）」。读取、切版本、导出都只查已保存记录，不检索或调用模型，不生成新版本。导出副本遮蔽凭据，原记录不改。报告来源是原生成时固定片段，当前笔记可能更晚更新，不能说两者是同一次输入；原input_hash/prompt_sha256保留原生成语义，export_content_sha256才是导出脱敏片段指纹。导出失败保留草稿/记录，可从原菜单重试；关闭或切会话后旧回包不触发下载。


## 列表暂不可用时如何恢复（D11，2026-11-07）

列表读取失败与恢复：设备、终端、下发任务、配置模板、审批、配置快照、配置变更日志、环境/设备占用、实训实验/会话、拓扑及其版本记录，首次读取失败表示最新数据未知，不表示零条或设备正常。已显示记录可能陈旧，重试成功后才更新；失败不删除历史或草稿。使用错误提示中的「重试设备列表」「重试任务列表」「重试模板列表」「重试快照列表」「重试版本记录」「重试拓扑列表」「重试环境列表」；审批、环境、实验和我的实训会话用各自区域「刷新」，配置变更日志用「查询」，设备观察的最近证据用「最近证据」。拓扑同对象刷新失败保留原图；切换对象后不会沿用旧对象的图或版本记录，回滚必须核对当前拓扑和版本。刷新/重试列表只读保存记录，不连接终端、不触发采集、不执行变更、不调用模型。不要建议因读取失败重新导入库存、创建空环境或删除旧记录。


### 监控、告警与审计的读取恢复

监控、告警与审计读取失败：监控的「刷新数据」重读统计、最近告警、巡检任务和趋势；拓扑选项失败用「重试拓扑列表」。告警页设备选项失败用「重试设备列表」，告警和审计记录失败用所在页「刷新」。失败不代表无告警、无任务、无审计或当前健康；同一对象已显示快照保留并提示可能陈旧，新对象不会显示旧对象的图表与巡检。告警/审计快速换筛选时，迟到旧回包不会替换新选择的结果；出现失败应重试成功后再判断最新范围。刷新不是触发采集、巡检、确认、关闭告警或执行变更。
